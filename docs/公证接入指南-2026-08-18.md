# 苹果签名与公证接入指南（给 SGD 本人操作）

日期：2026-08-18 · 对应版本：v0.5.1 已修复「已损坏」，本文是通往「零提示安装」的最后一步

---

## 一、先把钱的问题说清楚

你问的两件事，答案分开：

| 问题 | 答案 |
| --- | --- |
| 怎么付款？ | 加入 **Apple Developer Program**，年费 **99 美元**（中国区 **¥688/年**），按年订阅 |
| 每次发版要再付一次吗？ | **不用。公证本身完全免费、不限次数。** 一年里发 100 个版本就公证 100 次，不额外收一分钱 |
| 那年费是买什么？ | 买的是「有资格签名和公证」这件事本身，以及 Developer ID 证书 |
| 不续费会怎样？ | **已经公证并 staple 过的旧安装包，用户照样能正常安装**（凭证已经嵌在包里）。但你**不能再签发新版本**——所以「持续更新」确实要求「持续续费」 |

一句话：**不是按版本付费，是按年付费；一年之内随便发版。**

> 注：会员费不可退（Apple 官方规则），注册前想清楚。参考 [Apple Developer Program 会员权益](https://developer.apple.com/programs/whats-included/)。

## 二、注册流程（你本人做，我不能代做）

鲸坞的硬约束里写死了「代理不得使用证书、付费服务」（`AGENTS.md` S3），所以这一段必须你自己走。

1. **准备**：一个开了双重认证的 Apple ID；身份证（个人账号要做实名验证）；一张能付美元的信用卡，或用微信支付走 App Store 通道。
2. **注册**：手机装 **Apple Developer** App（App Store 搜得到）→ 「Membership」→ 加入 Apple Developer Program。
   - 走 App Store 支付通道时，**微信支付可用**，比信用卡省事。
   - 也可以在网页端 <https://developer.apple.com/programs/enroll/> 走信用卡。
3. **等审核**：个人账号通常 1–2 个工作日；偶尔会要求补充身份材料。
4. **拿证书**：审核通过后，在 <https://developer.apple.com/account/resources/certificates> 创建一张
   **Developer ID Application** 证书（注意：不是 "Mac App Distribution"，那是上架 App Store 用的）。
   把证书装进钥匙串，再从「钥匙串访问」导出为 **.p12** 文件（导出时会让你设一个密码，记住它）。
5. **拿公证密钥**：在 <https://appstoreconnect.apple.com/access/integrations/api> 生成一个
   **App Store Connect API Key**，角色选 **Developer**。下载得到一个 `.p8` 文件（**只能下载一次**），
   同时记下 **Key ID** 和 **Issuer ID**。

## 三、把六个值填进 GitHub（你做，或让 AI 陪着你点）

打开 <https://github.com/sgd-shine/whaledock/settings/secrets/actions>，点 New repository secret，逐个添加：

| Secret 名 | 填什么 | 怎么得到 |
| --- | --- | --- |
| `MACOS_SIGN_CERTIFICATE` | .p12 文件的 base64 文本 | 终端跑 `base64 -i 证书.p12 \| pbcopy`，然后粘贴 |
| `MACOS_SIGN_CERTIFICATE_PASSWORD` | 导出 .p12 时设的密码 | 你自己设的 |
| `MACOS_SIGN_IDENTITY` | 证书全名 | 终端跑 `security find-identity -v -p codesigning`，复制形如 `Developer ID Application: 你的名字 (TEAMID)` 的那一行引号内内容 |
| `MACOS_NOTARY_KEY` | .p8 文件的 base64 文本 | `base64 -i AuthKey_XXXX.p8 \| pbcopy` |
| `MACOS_NOTARY_KEY_ID` | API Key 的 Key ID | App Store Connect 页面上显示 |
| `MACOS_NOTARY_ISSUER_ID` | Issuer ID | 同上，页面顶部的一长串 UUID |

**六个都配齐之后，什么代码都不用改。** 下一次打 tag 发版时，Release workflow 会自动检测到这些
secret，把签名从 ad-hoc 切换成 Developer ID + Hardened Runtime，并自动提交公证、staple 到 dmg 上。
六个里缺任何一个（或一个都没配），就自动退回 ad-hoc，构建照样成功，不会卡住发版。

> 安全提醒：.p12 和 .p8 是你的身份凭证，**只放进 GitHub Secrets，绝不要提交进仓库、也不要发到聊天里**。
> 万一泄露，去 Apple 后台吊销重发即可。

## 四、配完之后用户看到什么

| 阶段 | 用户下载后双击的结果 |
| --- | --- |
| v0.5.0 及更早（无签名） | ❌「文件已损坏，应移到废纸篓」——右键打开也没用，普通用户基本直接删了 |
| **v0.5.1（ad-hoc 签名，已完成）** | ⚠️「无法验证开发者」→ 系统设置 → 隐私与安全性 → 点「仍要打开」→ 正常使用 |
| **配好六个 secret 之后** | ✅ 双击直接打开，**零提示**，和从 App Store 装的一样顺 |

## 五、Windows 那边顺带一提

Windows 的 SmartScreen 是另一套体系，要 **代码签名证书**（OV 约 200–400 美元/年，EV 更贵且要硬件 token），
和苹果这 99 美元互不相干。Windows 目前仍是「实验性支持、未真机验证」，建议**先不投钱**，
等 Windows 真机验证做完、有实际用户量了再说。
