# 鲸坞 WhaleDock 第二阶段遗留清单

日期：2026-08-16 · 截至 v0.5.0

这份清单只记**确实没做**的事，以及**没有人工验证过**的事。目的是让下一个接手的人不必猜哪些结论是真证据、哪些是推断。

分级：

- **A：需要 SGD 决策**（花钱、买证书、买设备、改产品方向）
- **B：需要真机或人工，代理做不了**
- **C：纯工程，代理可以继续做**

## B · 需要真机或人工验证

### Windows 全线未真机

CI 只证明构建与纯 Node 合约在 Windows runner 上通过。以下**全部未在真实 Windows 上跑过**：

- NSIS Setup 与便携版的安装、启动、退出
- 内置 dsh runtime 的冷启动
- 托盘、全局快捷键、进程树清理（`taskkill /T`）
- 开机自启（便携版依赖 exe 路径的自愈逻辑）
- 半自动更新的下载与校验
- `Win+Shift+S` 引导 + 剪贴板读取的截图入口
- `Windows.Media.Ocr` 的实际识别
- 工作区切换在 Windows 上的完整事务
- 宠物窗的透明与鼠标穿透在 Windows 上的表现

发布口径必须始终是「**实验性支持（未真机验证）**」。

## 明确不属于遗留、不要再翻出来的

- **工作区不是文件读取沙箱**：dsh 用绝对路径或 `..` 仍可越出 cwd（侦察 T3 实证）。这是上游行为，界面与文档已如实说明，不是待修 bug。
- **看板数字低于真实账单**：标题生成等旁路消耗 dsh 观测不到（侦察 T1.3）。文案已写明「dsh 已观测用量，非账单」。
- **约 200–400ms 硬崩溃窗口**：事件层不宣称 exactly-once，这是已声明的产品边界。
- **不注入 dsh 的 Web UI**：主题不作用于 Harness 网页、主窗口无 preload 无 DOM 注入，是硬约束不是缺功能。
- **`~/.dsh` 永不写入/迁移/清理**：S5 级底线。
- 用户侧待办（例如「只读审计员桌面 test.txt」那类）：不属于本仓库。

## 证据分级提醒

本项目一直把五类证据分开记，交接时请继续保持，不要合并：

1. 本地 `npm run smoke`（纯 Node，当前 233 PASS / ALL PASS）
2. 源码态 GUI 启动（`npm start`，有日志回读）
3. 三平台 CI（GitHub Actions，只证明构建与纯 Node 合约）
4. 打包与成品回读（artifact 下载 + `shasum -c`）
5. 公开 Release（tag、资产、`releases/latest`）

**任何一类都不能替另一类作数。人工没看过的，就写「未验证」。**
