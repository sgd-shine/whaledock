# 鲸坞 WhaleDock v0.4 开发方案

日期：2026-08-15

状态：批次 12 方案先行；代码尚未开始

目标版本：`0.4.0`

基线：批次 11 的 v0.3 实现与发布闭环完成后开工；dsh 根包继续锁定 `0.1.0-rc.6`，host 合约版本继续锁定 `0.0.1`

依据：批次 12 原始要求、`docs/路线图定稿-2026-08-14.md` 第五节、`docs/侦察批次一报告-2026-08-14.md` T3、当前 `lib/config.js` / `lib/backend.js` / `main.js` 边界

## 1. 问题陈述

### 1.1 多工作区

当前鲸坞在 `workdir` 为空时让 dsh 直接从用户主目录启动。普通用户很难判断 AI 正在哪个文件夹工作，切换项目还要进入设置或手改配置；主目录作为默认 cwd 也扩大了误操作范围。

v0.4 要把“工作区”变成用户看得见、可一键切换的“AI 工位”：新安装只从鲸坞专属默认文件夹开始，老用户已有行为保持不变，最近工作区可以安全切换且失败不留下半切换状态。

需要明确：**工作区只是默认 cwd，不是读取沙箱。** T3 已证实锁定版 dsh 的文件读取可使用绝对路径或 `..` 越出 cwd；界面和文档不得宣称切换工作区后 AI 绝对看不到其他目录。

### 1.2 截图入口

用户遇到报错、设计稿或屏幕现场时，目前要自行截图、保存、找路径、复制文字，再回到会话解释。上游 Web 已有图片 paste/drop 和附件展示，但锁定版默认 DeepSeek adapter 是 text-only，图片块会被拒绝；直接把图片塞进 Web UI 不能形成可靠的视觉理解。

v0.4 只补一条薄而可控的入口：三种采集方式进入同一预览，用户确认后把图片保存到当前工作区，按“官方视觉能力槽位 → 可探测 vision 插件 → 本地系统 OCR”选择理解路径，再把**用户确认过的 OCR 文本和图片路径**提交到所选会话；私有 RPC 不可用时复制到剪贴板并明确提示手动粘贴。

## 2. 目标与成功定义

### 2.1 用户目标

1. 新用户首次打开鲸坞时，默认工作目录是 `Documents/鲸坞工作台/默认工作区`，而不是整个主目录。
2. 用户可从应用菜单或托盘看到当前工作区、最近工作区并一键切换；无需编辑 JSON。
3. 工作区切换只有“完整成功”或“恢复到原状态”两种可见结果，不出现配置已改但后端仍在旧目录的假成功。
4. 用户可通过全局截图、拖图或显式读取剪贴板进入同一预览流程；任何发送前都能看到图片、OCR 文本、文件路径、目标会话和实际采用的处理路径。
5. 即使系统 OCR、vision 插件或 dsh 私有提交接口不可用，图片仍可安全落盘，用户至少能复制确认过的文本/路径后手动粘贴。

### 2.2 工程目标

1. 主 Harness 窗口继续没有 preload、没有 Node、没有 DOM 注入或模拟点击。
2. 所有 dsh 私有路径、method、帧名、payload 形状和版本假设只存在于 `lib/backend.js` / `lib/config.js`。
3. 工作区规划、recent 归一化、切换状态机、图片路由和交付 payload 都能用纯 Node fixture 直接测试。
4. 不新增 runtime dependency，不新增遥测或外网请求，不直接读写、扫描、迁移或清理 `~/.dsh`。
5. Ubuntu、Windows、macOS 的统一 smoke 全绿；GUI、系统权限、真机平台与线上 Release 证据另行记录。

### 2.3 无遥测条件下的成功指标

本项目禁止产品遥测，因此不收集采用率、截图内容或路径。发布成功以本地证据衡量：

- 新装/旧配置/切换成功/各失败回滚 fixture 通过率 100%。
- 三入口全部进入同一个图片状态机，取消后 staging 残留为 0。
- 所有 RPC 错版本、坏 envelope、超时和不确定结果 fixture 均零自动重试、零 DOM fallback。
- 三平台 CI smoke 全绿，依赖清单证明 runtime dependency 增量为 0。
- macOS arm64 安装版完成第 17 节人工清单；其他平台按证据边界如实标注。

## 3. 非目标

v0.4 明确不做以下事项：

1. **并行多开不做，定为 P2。** 不分配 3081+ 端口、不创建多实例窗口、不改当前单实例锁；先把单工作区切换事务做稳。
2. 不做截图标注、裁剪编辑器、翻译/解释快捷动作、持续共享屏幕、划词、动作模板或 WPS 专项接入。
3. 不自研视觉模型，不直接接 DeepSeek 在线视觉 API，不新增 API Key 设置或运行时价格/能力联网探测。
4. 不创建、删除、归档或清理 dsh 会话；v0.4 只向用户已选择的普通会话提交一条文本 prompt。
5. 不向锁定版 text-only DeepSeek route 发送 image block，不把 upstream Web 的 paste/drop 当成视觉能力已经可用。
6. 不做通用文件上传；v0.4 输入仅限单张静态图片。
7. 不把工作区包装成安全沙箱，不替换 dsh 的文件 provider，不承诺模型不能读取工作区外路径。
8. 不在后台持续监听或轮询剪贴板；Windows 截图完成后必须由用户显式点击“读取剪贴板”。
9. 不自动清理用户已确认保存到工作区的图片；只清理 WhaleDock 自己的 staging 临时文件。
10. 不升级 dsh，不引入 SDK JSON-RPC/ACP 自定义 runtime；短期只 pin 已审计的 rc.6 Web custom RPC。

## 4. 用户故事

按优先级排列：

1. 作为首次安装鲸坞的普通用户，我希望 App 自动给 AI 创建一个专属默认工位，以免一开始就把整个主目录作为工作范围。
2. 作为已有自定义工作目录的老用户，我希望升级后目录完全不变，以免正在进行的项目被静默迁移。
3. 作为同时维护多个项目的用户，我希望从菜单或托盘一键切换最近工作区，以便不用反复打开设置。
4. 作为担心误切目录的用户，我希望切换失败时鲸坞恢复原配置和原后端，而不是让我猜 AI 最终在哪个目录。
5. 作为 macOS 用户，我希望按一个快捷键调用系统框选截图，以便不安装额外截图库。
6. 作为 Windows 用户，我希望鲸坞明确引导我使用 `Win+Shift+S`，再由我主动读取剪贴板，而不是假装存在跨平台框选能力。
7. 作为已有图片文件的用户，我希望把单张图片拖进鲸坞自有的图片入口窗，进入与截图相同的预览流程。
8. 作为关心隐私的用户，我希望在保存或发送前看到图片和实际文字，能够取消，并知道剪贴板/RPC/系统 OCR 哪条路径会被使用。
9. 作为 dsh 私有接口暂时不可用的用户，我希望鲸坞把确认内容复制好并告诉我粘贴，而不是偷偷操作网页或直接丢失图片。
10. 作为外部终端 dsh 的用户，我希望鲸坞绝不为了切工作区杀掉我的外部进程；不能可靠切换时应明确拒绝。

## 5. P0 / P1 / P2 范围

### 5.1 P0：`0.4.0` 发布门槛

| 能力 | 明确行为 | 验收摘要 |
|---|---|---|
| 首次默认工作区 | 仅配置文件不存在的新用户创建专属目录 | 老配置含 `null` 也不迁移；创建失败绝不回落主目录启动 |
| 最近工作区 | 当前项 + 最近最多 10 项，config 原子持久化 | 去重、有界、缺失目录不自动切换 |
| 单实例切换事务 | 停事件层/自有后端 → 写 config → 启新后端 | 失败恢复原 config；部分失败保留 journal 待启动恢复 |
| 菜单/托盘/标题 | 两处“工作区”子菜单，标题显示当前名称 | 不显示原始 Web title；同名目录可区分 |
| 截图设置 | 默认 `CommandOrControl+Shift+S`，可改可关 | 注册冲突时原快捷键与配置一起回滚 |
| 三入口 | mac 系统框选、拖图、显式剪贴板读取 | Windows 框选入口只提示 `Win+Shift+S`；不轮询剪贴板 |
| 统一预览 | 独立本地窗口、最小 preload、可取消 | 主 Harness 窗不加 preload，不接收鲸坞 IPC |
| 安全落盘 | 当前工作区 `鲸坞截图/`，随机不覆盖文件名 | 拒绝目录 symlink/reparse 越界；失败不改源图 |
| 理解路由 | 官方槽位 → vision 插件槽位 → 本地 OCR → path-only | 前两项探测不到即跳过，不扫描真实 dsh home |
| 本地 OCR | macOS Vision/JXA；Windows Windows.Media.Ocr/PowerShell | 超时/缺语言包/权限失败均降级，不阻塞图片保存 |
| 会话交付 | 用户选普通会话，`queue` 文本 prompt | 仅 loopback + rc.6 证明 + feature detect + contract 通过时启用 |
| 复制降级 | 复制同一份用户确认 payload，提示手动粘贴 | RPC 结果不确定时不自动重试，提示先检查会话防重复 |
| 安全/测试/文档 | 路径、大小、IPC、临时清理、平台边界 | 统一 smoke 与发布材料闭环 |

### 5.2 P1：P0 全绿后才做，不阻塞发布

- 最近工作区同名时用父目录短标签消歧，菜单仍不默认展示完整个人路径。
- 在图片窗提供“在文件夹中显示”与“复制图片路径”两个显式按钮。
- macOS 在可读取屏幕录制权限状态时给出更精确的系统设置指引；权限 API 不可靠时仍以实际截图结果为准。
- 会话列表优先选中最新、非空、顶层且仍运行的普通会话；用户仍必须最终确认。
- 为 OCR 文本提供只读展开/折叠和“已截断”提示，不加入编辑器或模板系统。

### 5.3 P2：本版不实现

- **并行多开（独立端口、多 backend、多主窗口、多托盘状态）明确不做。** 保留当前 `requestSingleInstanceLock()`。
- 图片标注、裁剪、翻译、解释、持续屏幕共享、批量图片与普通文件。
- 在线官方视觉 API 客户端、插件商店扫描/安装、SDK JSON-RPC/ACP runtime。
- 临时会话、新会话自动创建、会话删除/retention。

## 6. 不可放宽的硬约束

1. `lib/` 下所有模块保持纯 Node，严禁 `require('electron')`；Electron 窗口、`nativeImage`、`clipboard`、`dialog`、`globalShortcut` 只在 `main.js` / preload。
2. 不新增 runtime dependency；devDependencies 仍只有 `electron` 与 `electron-builder`。
3. dsh 端口、版本、命令、原始 URL/method、RPC envelope、session payload、model/plugin 探测假设只放 `lib/backend.js` / `lib/config.js`。
4. 主 Harness `BrowserWindow` 保持 `preload` 为空、`nodeIntegration:false`、`contextIsolation:true`；禁止 DOM 注入、模拟点击、键盘自动化或页面文字抓取。
5. 永远不直接读写、扫描、迁移或清理 `~/.dsh`。用户确认提交 prompt 后，dsh 自己按其正常语义持久会话，不等于鲸坞直接操作其数据目录。
6. 不新增遥测、统计、截图/路径/文本上报或视觉 API 外网请求；现有唯一批准的外网请求仍是受总开关控制的 GitHub `releases/latest`。
7. 不记录图片内容、OCR 全文、剪贴板内容、会话正文、裸 session ID 或完整个人路径。必要诊断只记来源类型、阶段、错误码、大小等级和匿名标识。
8. attach 到外部 dsh 时绝不 stop。无法证明 backend 归属或 rc.6 根包版本时，工作区切换/RPC 写入按各自规则 fail-closed。
9. 所有写入只落 WhaleDock userData、用户明确选择的 config，或当前工作区的 `鲸坞截图/`；不修改拖入源文件。
10. 每次代码改动后运行完整 `npm run smoke`；自动化、GUI、安装、平台真机、签名和 Release 是不同证据。

## 7. 总体架构与文件边界

```text
系统入口 / 用户图片
  mac screencapture   Windows 剪贴板   drop/paste
          \              |              /
           +------ main.js Electron 薄执行层 ------+
           |  hotkey / nativeImage / clipboard     |
           |  自有图片窗 / 最小 IPC / child spawn   |
           +------------------+---------------------+
                              |
                              v
                     lib/image-input.js
                     - 中性输入描述与状态机
                     - 路由选择、限额、payload
                     - staging / 目标路径计划
                     - OCR runner 编排（纯 Node）
                              |
           +------------------+---------------------+
           |                                        |
           v                                        v
  assets/ocr/* 系统脚本                    lib/backend.js
  Vision / Windows.Media.Ocr               rc.6 prompt adapter
                                            - loopback + version proof
                                            - raw sessionId 仅内部持有
                                            - list / prompt 合约校验

菜单 / 托盘 / 设置
          |
          v
      main.js 单一切换队列
          |
          v
   lib/workspaces.js -------- lib/config.js
   - recent/path 纯逻辑        - schema/默认值/原子 config
   - journal/切换状态机        - dsh version/port/workdir
          |
          v
   backend.start/stop（现有）

主 Harness BrowserWindow
  - 无 preload
  - 无截图 IPC
  - 无 DOM 注入
```

边界原则：

- `lib/workspaces.js` 不知道 dsh method、端口或 Electron，只接受中性 backend 生命周期结果。
- `lib/image-input.js` 不知道 `session.prompt`、raw session ID 或 Electron clipboard，只产出中性 route/delivery intent。
- `lib/backend.js` 知道 rc.6 私有 wire，但不接触窗口、剪贴板、图片预览或工作区菜单。
- `main.js` 只串联上述中性 API，不复制 dsh 字段常量。

## 8. 配置与持久数据模型

### 8.1 `config.json` 新字段

```json
{
  "workdir": null,
  "recentWorkdirs": [],
  "screenshotHotkeyEnabled": true,
  "screenshotHotkey": "CommandOrControl+Shift+S"
}
```

规则：

- `workdir` 继续是唯一当前工作区字段；不另建互相可能漂移的 currentWorkspace。
- `recentWorkdirs` 为内部维护的绝对路径数组，最近项在前，最多 10 项；不进入通用 renderer 可写白名单。
- 老配置缺 `recentWorkdirs` 时内存补空数组，**不据此修改 `workdir`**。
- `screenshotHotkeyEnabled` / `screenshotHotkey` 进入设置白名单；快捷键非空、最长 128 字，运行时还要通过 Electron 实际注册。
- `screenshotHotkey` 不得与主窗口 `hotkey` 相同；两组快捷键切换必须作为一个运行时事务回滚。
- 路径通过 `path.resolve`、存在性、目录类型和 `realpath` 校验。Windows 去重使用大小写不敏感比较键；POSIX 不擅自 lower-case。

### 8.2 新用户与旧用户判定

判定依据是**迁移旧名配置之后，WhaleDock `config.json` 是否已存在**：

1. 先执行现有 `migrateLegacyConfig()`；成功复制的旧配置视为旧用户。
2. 若配置文件存在，无论其中 `workdir` 是绝对路径还是 `null`，都按旧用户处理，原值不迁移。
3. 只有配置文件确实不存在，才计算 `app.getPath('documents')/鲸坞工作台/默认工作区` 并创建目录。
4. 默认目录创建、校验成功后，把它作为 `config.init(..., { freshDefaults })` 的首次默认值一次写入。
5. 目标路径已有目录时安全复用；若同名是文件、权限拒绝或无法验证，显示“选择其他文件夹 / 退出”，**不得静默回落到主目录启动 backend**。

新建的鲸坞专属目录在 POSIX 尽量使用 `0700`，截图使用 `0600`；Windows 依赖当前用户的 userData/Documents ACL，不用 POSIX mode 位做假保证。不得修改用户已存在工作区的权限。

### 8.3 最近工作区

纯函数 `updateRecentWorkdirs({ previous, current, target, platform, limit: 10 })`：

- 成功切换后把 target 放首位，把原有效工作区放在其后，去重并截断。
- 同一路径切换是 no-op，不 stop、不写 config、不重启。
- 菜单读取时可以显示 current + recent 的合并视图，但不因打开菜单写 config。
- recent 项不存在或不再是目录：点击时提示失败，可由用户明确移除；不能先改 workdir 再发现路径坏了。
- 两个目录 basename 相同：显示 `项目名 — 父目录名`；仍冲突才显示经过长度限制的路径尾部。

### 8.4 工作区切换 journal

config 单文件原子写不能覆盖“停止进程 + 写配置 + 启动进程”的跨资源事务。新增 WhaleDock userData 内的 `workspace-switch.json`：

```json
{
  "schemaVersion": 1,
  "phase": "prepared",
  "startedAt": "2026-08-15T00:00:00.000Z",
  "previous": {
    "workdir": null,
    "recentWorkdirs": []
  },
  "target": {
    "workdir": "/absolute/validated/path",
    "recentWorkdirs": ["/absolute/validated/path"]
  },
  "previousRuntime": {
    "wasReady": true,
    "wasManaged": true
  }
}
```

- 只允许 `prepared` / `config-applied` 两个 phase；不写 pid、命令、会话、截图或用户内容。
- 原子临时文件 + rename；POSIX `0600`，Windows 依赖 userData ACL。
- 一次只允许一个 journal；坏 schema 不猜测恢复，保留有界诊断备份并阻止 backend 自动启动，提示用户选择工作区。
- journal 含本地路径，日志不得把内容展开。
- App 正常完成切换或完整回滚后删除；删除失败只报告，不把切换冒充未完成。

### 8.5 图片处理数据

图片处理 session 只存在内存，不写 config/state：

```text
captureId             随机不透明 ID
source                mac-capture | windows-clipboard | paste | drop
stage                  acquiring | preview | saving | recognizing |
                       delivery-ready | submitting | copied | done | failed | cancelled
stagingPath            仅 main/lib 内存可见
thumbnail              限尺寸 data URL，只给自有预览窗
workspaceGeneration    捕获时的工作区代号
savedPath              用户确认落盘后才出现
route                  official | plugin | local-ocr | path-only
ocrText                仅内存，限长
targetToken            预览窗级临时 token，不是 raw session ID
deliveryState          not-attempted | accepted | failed | unknown
```

`userData/capture-staging/` 只保存随机名临时 PNG：目录 POSIX `0700`、文件 `0600`。正常取消/关闭/finally 删除；App 启动时只清理该受控目录中符合固定前缀的 staging 文件，不扫描或删除工作区图片。

## 9. 工作区切换事务

### 9.1 前置条件

切换入口包括应用菜单、托盘和设置窗，全部调用 main 中同一个串行 `switchWorkspace(target)`：

1. 解析并 realpath 目标，确认是现存目录；不要求修改其权限。
2. 与当前有效 workdir 比较；相同则刷新窗口并返回 no-op。
3. 若今日预算仍处于暂停态，阻止需要重启的切换并引导用户先明确恢复预算。
4. 若当前连接是无法确认归属的 external attach，拒绝切换并说明“鲸坞不会停止外部 dsh；请先退出外部服务或改由鲸坞托管”。绝不只改 config 后继续 attach 旧 cwd。
5. 切换开始后暂停新截图处理；已有未落盘预览失效并清理 staging，避免图片落进另一个工作区。

### 9.2 正常提交顺序

```text
idle
  -> validate target
  -> write journal(prepared)
  -> cancel startup/recovery generations
  -> stop event layer
  -> stop old managed backend and confirm state exited
  -> config.set(target workdir + new recents)
  -> write journal(config-applied)
  -> start backend with target cwd
  -> confirm owned child alive + expected port ready
  -> relaunch event layer
  -> rebuild menu/tray/title/settings snapshot
  -> delete journal
  -> committed
```

成功不能只依据 TCP 端口打开：必须同时确认本次 `backend.start()` 返回的同一 child state 仍存活、归属仍是 `spawnedByUs`、startup generation 未失效。若 backend adapter 能安全回读 `host.describe.cwd`，再做 canonical cwd 一致性确认；回读不匹配必须 fail-closed。该 raw 字段只能由 backend adapter 归一化为 `effectiveWorkdir` 后返回。

### 9.3 失败回滚

| 失败点 | 必须行为 |
|---|---|
| 目标预检失败 | 不写 journal、不停 backend、不改 config |
| journal 首写失败 | 不停 backend、不改 config |
| 旧 backend 停止失败 | 不改 config；保留/清理 prepared journal 后报告 |
| target config 写失败 | config 仍是 previous；重启原 managed backend（如原来在运行） |
| target backend 启动失败 | 停止本次可能残留的自有 child；原子恢复 previous config/recents；再恢复原 backend |
| 原 config 恢复失败 | 保留 journal，阻止继续自动启动，显示需要用户选择目录的错误；不猜测写新值 |
| 原 backend 恢复失败 | config 必须已恢复；显示原工作区 + backend 未启动，不把 target 标为当前 |
| App 在事务中崩溃 | 下次启动先读 journal；恢复 previous config 后才进行任何 backend attach/start |

回滚也在同一队列内完成。菜单、标题和 config 快照只在 commit 后切换；处理中显示“正在切换工作区…”，防止重复点击。

硬崩溃后可能存在鲸坞已失去进程身份的 dsh 占用端口。不得凭 journal pid 或端口猜测性强杀；先恢复配置，端口仍占用时按 external attach/mismatch 现有安全路径提示用户。

### 9.4 窗口标题和菜单

- 正常标题：`鲸坞 WhaleDock — <工作区显示名>`。
- 老配置 `workdir:null` 的显示名为“主目录（旧配置）”，不在后台把它改成默认工作区。
- `page-title-updated` 继续 `preventDefault()`，每次从 committed workspace snapshot 重算标题。
- 菜单和托盘都有“工作区”子菜单：当前项（勾选/禁用）、最近项、分隔线、“打开新文件夹…”。
- 日志默认只记显示名和事务阶段；完整路径只在用户主动打开的设置/预览中显示。

## 10. 截图与图片入口

### 10.1 为什么使用自有图片窗

主 Harness 窗口禁止 preload 和 DOM 注入，Electron main 也不能可靠取得其网页 drop 的本地文件。因此“拖图进窗”和“粘贴”在 v0.4 的正式含义是：拖入/粘贴到鲸坞自有的“截图与图片”窗。

入口位置：

- 全局截图快捷键；
- 应用菜单 / 托盘“截图与图片…”；
- 图片窗内部的拖放区和“读取剪贴板”按钮。

上游 Harness 自己原有的图片 paste/drop 继续存在，但不属于鲸坞 v0.4 的保证，也不能绕过本预览确认流程。

### 10.2 三入口

#### macOS 全局框选

1. 注册用户配置的快捷键，触发后暂时隐藏鲸坞自有窗口。
2. 用 `execFile`/`spawn` 直接执行系统 `/usr/sbin/screencapture`，参数为 `-i -x <random-staging.png>`；禁止 shell 拼接。
3. 进程退出且文件存在、可解码才进入 preview；用户按 Esc 或无文件视为正常取消。
4. 权限拒绝、命令缺失、超时或坏图显示可操作错误；恢复原窗口，不产生工作区文件。
5. 多显示器、Retina/缩放和框选坐标交给系统工具，仍需真机人工验收。

本功能只需要系统屏幕录制权限，不申请 Accessibility，不绕过 TCC，不调用任何持续录屏 API。

#### Windows 全局快捷键

Windows 没有与 `screencapture -i` 等价且稳定的内置 CLI。触发后：

1. 打开本地图片窗，明确显示“请按 `Win+Shift+S` 完成框选”。
2. 用户完成系统截图后，主动点击“读取剪贴板”。
3. 鲸坞只在该明确动作发生时调用 `clipboard.readImage()`；不轮询、不监听历史剪贴板。

不得模拟 `Win+Shift+S`、注入键盘、调用不稳定 URI 或冒充已完成系统框选。

#### 拖图 / 粘贴

- 图片窗 preload 在自己的 isolated world 监听 drop/paste；drop 用 Electron `webUtils.getPathForFile()` 得到路径后交 main 校验，不向普通 renderer 暴露 fs。
- 一次只接受一张图片；多张、目录、快捷方式、网络 URL 或非图片明确拒绝。
- 粘贴等价于用户显式读取当前 clipboard image；不读取 clipboard 文本。
- 源文件只读，永不改名、移动、删除或覆盖。

### 10.3 输入校验与规范化

main 使用 Electron `nativeImage` 解码，所有入口规范化为 staging PNG：

- 支持能被 Electron 安全解码的 PNG/JPEG；WebP/GIF 可列 P1，启用前必须有跨平台 fixture，GIF 只取静态首帧并明确提示。
- 输入文件最大建议 20 MiB；解码后最大 40,000,000 像素，宽高均为正且有合理上限。
- 不能只信扩展名/MIME；必须实际解码并检查 `nativeImage.isEmpty()` 与尺寸。
- renderer 只得到限边长的 thumbnail data URL，不得到 staging 路径或任意 `file:` 读取权。
- 所有字符串、数组、图片字节和 IPC payload 设上限；坏输入不让图片窗或 main 崩溃。

### 10.4 统一状态机与双确认

```text
idle -> acquiring -> preview
preview --取消--> cancelled -> cleanup
preview --确认保存并处理--> saving -> recognizing -> delivery-ready
delivery-ready --发送--> submitting -> accepted | copied-fallback | unknown
delivery-ready --仅保存--> done
任意阶段失败 -> failed（按归属清理 staging，不删除已确认保存文件）
```

第一次确认回答“这张图是否保存并处理”：

- 显示图片缩略图、来源、当前工作区显示名和将写入的 `鲸坞截图/`。
- 点击取消时不创建工作区文件并清掉 staging。

保存后在同一窗口显示交付预览：

- 实际保存路径；
- 实际 route（官方视觉 / vision 插件 / 本地 OCR / 仅路径）；
- OCR 文本或明确的不可用原因；
- 目标会话匿名标签；
- 将提交/复制的完整文本。

第二次明确点击“发送到所选会话”或“复制后手动粘贴”，才执行外部可见副作用。用户已确认保存后再关闭窗口，图片保留；界面可提供显式删除本次图片，但不得后台删除。

## 11. 安全落盘与路径模型

### 11.1 目标路径

默认目标：

```text
<current effective workdir>/鲸坞截图/鲸坞截图-YYYYMMDD-HHMMSS-<random>.png
```

- `effective workdir` 为 committed config 的绝对目录；老配置 `null` 时是现有 backend 实际使用的 home，但预览必须如实显示。
- 文件名由鲸坞生成，不使用拖入源文件名、OCR 文本或会话标题。
- 以 `wx` / `O_EXCL` 创建，绝不覆盖；碰撞重新生成随机后缀。
- 工作区在 preview 后发生切换时，`workspaceGeneration` 不匹配，当前 capture 必须失效并要求重新确认，不能悄悄写进新目录。

### 11.2 symlink / traversal 防护

1. 对 workspace 做绝对化、存在性和 realpath 校验。
2. `鲸坞截图` 不存在时由鲸坞创建；已存在时必须是普通目录，拒绝 symlink、junction/reparse 等可识别跳转。
3. 对目录 realpath 做 `path.relative(workspaceReal, screenshotsReal)` containment；结果不能绝对、不能是 `..` 或以 `../` 开头。
4. 随机最终文件不存在，再用 exclusive open；写完 `fsync`、close，必要时原子 rename。
5. 任一检查失败，只保留 staging 并提示用户另选工作区/手动保存；不尝试修复或删除可疑目录。

工作区是用户选择的目录，不禁止其本身位于 symlink 后；一旦选择就以 canonical realpath 作为本次事务路径。安全承诺只覆盖鲸坞自己的目标计算，不宣称 dsh 文件工具受同一 containment 限制。

## 12. 理解层路由与系统 OCR

### 12.1 纯函数路由

`selectImageRoute(capabilities)` 的固定优先级：

```text
official-vision available + exact contract
  -> compatible-vision-plugin available + exact contract
  -> local-ocr available for current platform
  -> path-only
```

每个 capability 为 `available | unavailable | unknown`，带有限枚举 reason。`unknown` 等同不可用，不允许乐观调用。route 选择结果显示给用户并进入 fixture。

### 12.2 官方视觉槽位

当前 v0.4 不新增在线 API client，也不联网探测 DeepSeek 官方价格或能力。锁定版默认 DeepSeek adapter 已实证 `inputModalities:["text"]` 并拒绝 image block，因此生产默认 `official-vision=unavailable`。

只预留一个中性 capability 输入位。未来若 dsh 的本地、已锁合约能明确声明当前会话可接收 image，必须先新增 backend contract fixture、隐私说明和用户确认，再启用；不能仅凭模型名含 “vision” 猜测。

### 12.3 vision 插件槽位

- 不扫描 `~/.dsh`，不运行 `dsh plugin --help`，不为了探测插件初始化 profile、下载 pnpm 或改用户状态。
- 只有已运行 host 通过一个已审计、只读、loopback 的明确 capability/RPC 暴露兼容 vision 能力时，backend adapter 才返回 `available`。
- rc.6 当前若没有稳定发现合约，则该槽位是 `unknown -> skip`，直接走本地 OCR。这是预期降级，不是发布阻塞。
- 不把“用户可能安装了某插件”写成鲸坞已验证视觉能力。

### 12.4 macOS OCR

- 内置自有脚本 `assets/ocr/macos-vision.jxa`，用 JXA ObjC bridge 调 `Vision` 的 `VNRecognizeTextRequest`。
- main/lib 用 `/usr/bin/osascript -l JavaScript <script> <image>` 的参数数组执行，不经 shell。
- 脚本只读单个明确图片，stdout 只输出有限 JSON；stderr、exit code、超时均归一化，不记录识别文本。
- 建议 30 秒超时、stdout 1 MiB 上限、识别文本 50 KiB 上限；超限截断并加入用户可见标记。
- Vision framework 不可用、语言识别失败或脚本异常时降级 path-only，不改图片。

### 12.5 Windows OCR

- 内置自有脚本 `assets/ocr/windows-media-ocr.ps1`，调用系统 `Windows.Media.Ocr`。
- 通过 `powershell.exe -NoProfile -NonInteractive` 执行受控脚本；不拼接用户路径，不加载 profile，不联网，不更改系统执行策略。若系统策略阻止脚本，按 OCR unavailable 降级，不用 `ExecutionPolicy Bypass` 绕过。
- 图片路径通过受控参数或进程环境传入，stdout 只返回有限 JSON。
- 缺 OCR 语言包、WinRT API 不可用、超时或非零退出都降级 path-only，并给出“图片已保存，系统 OCR 不可用”。

### 12.6 Linux / 未支持平台

Linux 只运行纯 Node smoke，不作为 v0.4 安装目标。系统框选和本地 OCR 返回明确 unavailable；拖图/粘贴的纯逻辑仍可测，不得把 CI 通过写成 Linux GUI 支持。

## 13. 会话选择、custom RPC 与复制降级

### 13.1 backend adapter 边界

在 `lib/backend.js` 内新增独立写能力 adapter，建议 API：

```js
createDshPromptAdapter({
  port,
  expectedHostVersion,
  packageVersionProof,
  fetch,
  timeoutMs
})

adapter.detect()
adapter.listTargets()
adapter.submitText({ targetToken, text, clientTimeZone })
adapter.close()
```

不得向 main 暴露通用 `call(method,payload)`。事件只读 adapter 继续保持自己的 method allowlist，不能因为截图功能而获得写权限。两个 adapter 可以在 `backend.js` 内复用私有 carrier、loopback 校验、响应限长、AbortController 和 envelope validator。

### 13.2 rc.6 精确写合约

仅 backend 内出现以下原始事实：

- HTTP 只允许固定 loopback origin；endpoint 由配置端口生成，renderer 不能传 URL。
- feature detect 使用已审计的 `host.describe` 和 `session.list`，校验 host `0.0.1`、请求/响应 type、rpcId 回显、`result.ok/value` 和数组/字符串/数字上限。
- `session.prompt` 仅在用户点击发送时调用，不用伪造空请求做后台探测。
- payload 固定为已审计的 rc.6 形状：`sessionId`、`mode:'queue'`、`content:[{type:'text',text}]`，可选经过验证的 `clientTimeZone`。
- 只接受 `{accepted:true}` 成功形状；不使用 `steer`、image content、session.create/cancel/delete、approval respond 或其他写方法。
- 根包证明必须精确等于 `DSH_CONTRACT.packageVersion`。托管 backend 可由已解析命令/state 提供证明；无法证明根包版本的 external attach 自动提交关闭，仅保留复制降级。

### 13.3 会话列表

- `listTargets()` 只返回普通、顶层、非空会话的临时 `targetToken`、匿名标签、running 和有限更新时间。
- raw session ID 永不离开 adapter；targetToken 仅当前 adapter/预览生命周期有效，adapter close 后全部失效。
- subagent 会话排除；无法确认 origin 的行按 rc.6 list 规则处理，但 UI 不展示敏感标题/正文。
- 默认可选最新 running 会话，用户必须在第二次确认前看到并可更换。
- 没有目标会话时不自动创建；保存图片并复制 payload，提示先在主窗口建立会话。

### 13.4 交付文本

纯函数生成并限长：

```text
请根据下面这张截图协助我。

图片路径：<用户已确认的绝对路径>

OCR 文本：
<识别文本；若截断则含明确标记>
```

若 OCR 不可用，默认只显示和复制图片路径，不冒充模型已理解图片。路径可能含用户名或项目名，因此完整 payload 必须在发送前展示。

### 13.5 降级与不确定结果

| 条件 | 行为 |
|---|---|
| 非 loopback / host 版本错 / 根包无法证明 | 不调用 prompt；复制并提示粘贴 |
| list/feature detect 失败 | 不展示虚假会话；复制并提示粘贴 |
| 用户未选会话 | 禁止自动提交；允许仅保存/复制 |
| prompt 明确拒绝且服务端未接纳 | 复制同一 payload，提示手动粘贴 |
| timeout/断线/响应坏 shape | 标记 `deliveryState:unknown`，不自动重试；复制并警告先检查会话避免重复 |
| prompt `{accepted:true}` | 显示“已提交，回答请回主窗口查看”；不宣称模型已回答 |

RPC transport rpcId 不是业务幂等键。一次点击只发一次；按钮进入 submitting 后禁用。任何重试都必须由用户检查会话后再次明确点击。

## 14. 图片窗、设置、preload 与 IPC

### 14.1 图片窗口

- 新建单例 `BrowserWindow`，本地 `capture.html`，建议 760×680。
- `contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`、独立最小 preload；若 drop 所需 API 在 sandbox 中不可用，先用最小 contract probe 找系统级替代，不能直接关闭 sandbox 过关。
- CSP 至少 `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'none'`；生产 JS 外置，不允许远程资源。
- 拒绝导航和新窗口；renderer 只用 `textContent` / 安全属性，绝不把 OCR/路径写入 `innerHTML`。
- renderer crash 后销毁当前内存 capture、清 staging；已确认保存文件不删。

### 14.2 最小 IPC

建议固定通道：

```text
capture:get
capture:read-clipboard
capture:accept-drop
capture:confirm-save
capture:deliver
capture:cancel
capture:show-in-folder
capture:state（main -> renderer）
```

约束：

- 每个 handler 同时校验 sender、mainFrame、精确 `capture.html` file URL。
- `capture:accept-drop` 只接受 preload 从一个本地 File 提取的单一路径；main 重新做全部校验。
- `capture:deliver` 参数只允许 captureId、枚举 action 和 targetToken；renderer 不能提交自报 OCR、路径或任意 endpoint。
- main 每次从内存规范状态重建 delivery payload，不信 renderer 显示值。
- preload 只暴露冻结的窄 API，不暴露 `ipcRenderer`、`clipboard`、`shell`、`fs` 或通用 invoke。

### 14.3 设置窗与快捷键事务

新增设置项：

- “启用截图快捷键”（默认开）；
- “截图快捷键”（默认 `CommandOrControl+Shift+S`）；
- 当前工作区只读显示 + “选择并切换工作区”。

`preload-settings.js` 只新增固定的 `switchWorkspace()`（若现有 choose/apply 无法安全承载事务），不把图片 IPC 塞进设置 preload。`settings:apply` 若收到 `workdir` 必须拒绝通用直写或转入同一 `switchWorkspace`，不能沿用“先保存、以后手动重启”的旧语义。

快捷键保存流程：先验证配置 → 尝试注册新截图键并检查与主 hotkey 冲突 → 成功后写 config → 失败恢复旧注册；config 写失败也恢复旧注册。关闭开关时真实 unregister，不只保存布尔值。

### 14.4 主窗口保持不变

- `openMainWindow()` 的 `webPreferences` 继续不设置 preload。
- 不向主页面注册 drop/paste DOM handler，不执行 JavaScript，不找输入框，不自动点击发送。
- 切换工作区成功后销毁/重建或安全 reload 主窗口，使其只加载新 backend；标题由 committed workspace 状态设置。

## 15. 权限、隐私与失败降级

### 15.1 权限与用户可见性

- macOS 第一次截图可能触发屏幕录制权限；拒绝后保留拖图/粘贴入口，并给出系统设置路径，不重复骚扰。
- Windows 剪贴板只在按钮/粘贴动作发生时读取；鲸坞不读取剪贴板历史。
- OCR 全程本机系统框架；若未来官方/插件 route 会联网，必须在启用前另补可见说明，v0.4 当前不主动联网。
- custom RPC 是 loopback，但同机进程可访问并不等于认证；只在用户手势、固定目标和版本合约下调用。

### 15.2 隐私边界

- 预览前只保存 WhaleDock staging；取消立即清理。
- OCR 文本不写 config、events state、日志或战报；只存在当前内存和用户明确选择的剪贴板/dsh prompt。
- 完整路径只在设置/预览按功能需要显示；日志用阶段 + 错误码。
- 复制降级会把内容放进系统剪贴板，UI 必须明确提示剪贴板可能被其他应用读取。
- 用户已确认保存的 `鲸坞截图/*.png` 属于用户文件，App 退出或升级不清理。

### 15.3 失败总表

| 子系统失败 | fail-open / fail-closed |
|---|---|
| 默认工作区创建失败 | backend 启动 fail-closed；让用户选目录，不回落 home |
| recent 项失效 | 该次切换 fail-closed；当前 backend 继续 |
| 工作区切换事务失败 | target fail-closed；恢复 previous，主 Harness 继续或显示恢复失败 |
| 图片 capture/解码失败 | 图片功能失败；backend/主窗口继续 |
| OCR 失败 | 图片保存成功，route 降级 path-only |
| official/plugin 探测未知 | 跳过，走本地 OCR |
| prompt adapter 失败 | 写能力 fail-closed；复制降级，主 Harness 继续 |
| 图片 renderer 崩溃 | 清 staging，已保存文件保留，backend 继续 |
| config/journal 持久失败 | 相关切换副作用 fail-closed，不交付假成功 |
