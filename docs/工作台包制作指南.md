# 鲸坞工作台包制作指南

一句话：**一个工作台包就是一个文件夹，里面只有几个文本文件。把它拖进鲸坞窗口，装好了。**

不用写代码，不用打包，不用上架。鲸坞**永远不会运行你包里的任何东西**——它只读里面的文字。

---

## 一、5 分钟做一个能用的工作台

新建一个文件夹，名字就是工作台的名字，比如 `合同初审台`。里面放两个文件：

**`manifest.json`** —— 告诉鲸坞这是个什么台

```json
{
  "schemaVersion": 1,
  "name": "合同初审台",
  "summary": "一份合同拆成风险点、修改建议和一页纸",
  "version": "1.0.0",
  "author": "你的名字",
  "license": "MIT"
}
```

**`actions.json`** —— 左边那一列按钮

```json
{
  "actions": [
    {
      "id": "review",
      "label": "出初审意见",
      "hint": "通读一遍，列出重点关注条款",
      "prompt": "你是我的合同初审助手。第一步，读 01_待审合同/ 下的文件……"
    }
  ]
}
```

把这个文件夹**拖进鲸坞窗口**，松手就装好了。左上角的工作台按钮里点一下就能切过去。

> 鲸坞做的事只有一件：把这个文件夹原样复制到自己的目录下。
> **不解压、不执行、不联网、不改你原来的文件夹。** 拖错了就在设置里点「移除」，它只删掉那份副本。

---

## 二、包里可以放什么

文件名全部由鲸坞写死，你不能指定路径——这让「路径穿越」在结构上就不可能发生。

```
你的工作台/
├── manifest.json        必填。没有它 = 不是工作台包，整个目录跳过
├── icon.png             可选。切换器里的小图标
├── theme.json           可选。换一套配色（v0.5 主题格式）
├── pet/                 可选。换一个桌面宠物（v0.5 宠物包格式）
│   ├── manifest.json
│   └── *.png
├── workspace.json       可选。要建的文件夹结构
├── actions.json         可选。左侧按钮 + 每个按钮发给 agent 的提示词
├── agent.cordis.yml     可选。dsh 的 agent 预设，我们只查存在性，绝不解析
├── skills.json          可选。推荐 skill 清单，只展示不安装
└── onboarding.md        可选。首次启用时显示的引导文字
```

**轻工作台 vs 重工作台**——这个区别决定了用户的体感：

- **没写 `workspace.json`** = 轻工作台。切换 = 换皮肤 + 换按钮，**瞬间完成，后端不重启，什么都不弹**。
- **写了 `workspace.json`** = 重工作台。它要在硬盘上建文件夹、要重启后端，所以**第一次启用会弹一次确认卡**，之后再切就不弹了。真机上大约几秒。

> **建议默认做成轻工作台。** 只有确实需要一套独立文件夹的（比如短视频创作台）才做成重的。

## 三、字段速查

### `manifest.json`

| 字段 | 必填 | 上限 | 不写会怎样 |
| --- | --- | --- | --- |
| `schemaVersion` | 否 | 必须是数字 `1` | 当作 1。**写了别的数字整包会被拒**，这是唯一一个这样的字段 |
| `name` | 否 | ≤ 40 字 | 用文件夹名 |
| `summary` | 否 | ≤ 120 字 | 切换器里不显示副标题 |
| `version` | 否 | `^[0-9A-Za-z.+-]{1,32}$` | 不显示版本 |
| `author` | 否 | ≤ 80 字 | 不显示作者 |
| `license` | 否 | ≤ 80 字 | **UI 里明写「未声明许可证」**——所以请写上 |
| `homepage` | 否 | 必须 `https://` 开头，≤ 300 字 | 不显示主页。其他 scheme 一律丢弃 |
| `dshRange` | 否 | ≤ 64 字 | 不限。**它只用于提示，永远不会阻止用户启用** |
| `accent` | 否 | `#RGB` 或 `#RRGGBB` | 跟随当前主题 |

### `workspace.json`

```json
{
  "root": "合同初审台",
  "folders": [
    {
      "path": "01_待审合同",
      "readme": "把要审的合同原件放这里，一份合同一个文件。",
      "files": [
        { "name": "示例-一份合同.md", "content": "这是示例，可以直接删掉。" }
      ]
    }
  ]
}
```

| 字段 | 必填 | 上限 | 说明 |
| --- | --- | --- | --- |
| `root` | 否 | 单段目录名，≤ 40 字 | 不写就用 `name`，再不行用文件夹名 |
| `folders` | 是 | ≤ 32 项 | **不是数组或为空，整个包就退化成轻工作台**，不报错 |
| `folders[].path` | 是 | 1–3 段，`/` 分隔，每段 ≤ 40 字 | 含 `..`、绝对路径、`\` `:` 的那一条会被丢掉，其余照建 |
| `folders[].readme` | 否 | ≤ 4000 字 | 会写成该文件夹里的 `说明.md` |
| `folders[].files` | 否 | ≤ 8 项 | 预置示例文件，见下 |
| `files[].name` | 是 | 单段文件名，≤ 60 字，**必须 `.md` 或 `.txt` 结尾** | 不能叫 `说明.md`，那个名字归 `readme` |
| `files[].content` | 是 | ≤ 8000 字 | 文件正文 |

**建文件夹的三条铁律**（鲸坞对你和用户的承诺）：

1. **只新建，不覆盖。** 文件夹存在就跳过；同名文件已存在就**一个字都不动**——用户改过的内容是他的财产。
2. **不删任何东西。** v0.6 的鲸坞里没有任何删除用户文件的代码路径。切走一个工作台只是不再显示它的按钮。
3. **落点必须过工作区校验**，字面路径与 realpath 两轮都查，任何一层落进 `~/.dsh` 一律拒绝，而且**拒绝时连文件夹都不建**。

建在哪：`<文档目录>/鲸坞工作台/<root>/`。

### `actions.json`

| 字段 | 必填 | 上限 | 不合法会怎样 |
| --- | --- | --- | --- |
| `actions` | 是 | ≤ 12 项 | 超出的截断 |
| `id` | 是 | `^[a-z0-9][a-z0-9_-]{0,31}$` | 非法或重复 → 丢这一条，保留先出现的 |
| `label` | 是 | ≤ 16 字（按钮放得下） | 洗完为空 → 丢这一条；超长会截断 |
| `hint` | 否 | ≤ 80 字 | 不显示悬浮说明 |
| `confirm` | 否 | 布尔 | 默认 `false`。设成 `true` 会先弹一次确认 |
| `prompt` | 是 | ≤ 8 KiB，非空，不含控制字符，trim 后不以 `/` 开头 | 违反任一条 → **丢这一条**，用户会在设置里看到具体原因 |

**提示词是死文本。** 包里写什么就原样发什么：不做变量替换、不做拼接、不和输入框内容合并。写 `{{变量}}` 就会原样发出去一个 `{{变量}}`。

### `skills.json`

```json
{ "skills": [{ "name": "示例", "why": "一句话理由", "install": "dsh skills add 示例", "url": "https://..." }] }
```

`install` 必须是**单行**（含换行直接丢弃）。UI 只会把它显示成可见文本，旁边给一个「复制」按钮。
**鲸坞没有一键安装，也没有任何执行路径。** 写 `{"skills": []}` 表示「本包不推荐任何 skill」，那一栏会整个隐藏。

### `onboarding.md`

纯文本显示，≤ 64 KiB。只做两件事：`#` 开头的行加大加粗，`-` 开头的行显示成条目。
**不解析 Markdown、不渲染 HTML、不生成可点链接。** 别指望排版，指望它把话说清楚。

### `agent.cordis.yml`

鲸坞对它做且只做四件事：在不在、是不是普通文件（**符号链接一律拒**）、有没有超过 256 KiB、realpath 之后还在不在包里。

**内容一个字节都不会被读进解析器。** UI 里只会写「已检测到，尚未接通」，而且只在「关于这个工作台」详情里写。
真正把它交给 dsh 要等上游侦察做完，在那之前任何地方都不会说「支持 agent 预设」。

## 四、写提示词的四条经验

这四条是短视频创作台那五个提示词打磨出来的，直接抄就行。

1. **明确说清读哪个文件夹、写哪个文件。** 不要写「读取相关资料」，要写「读 `01_选题库/` 下的所有 .md 和 .txt」。
2. **找不到就问，不许编。** 每个提示词都要有一句「如果这个文件夹不存在或者是空的，就直接告诉我，然后停下」。
   这一条是防止 agent 乱找、乱建、产出一堆错位文件的**唯一**手段。
3. **同名不覆盖。** 写「如果同名文件已存在，就在文件名后加 `-2`、`-3`，绝对不要覆盖」。
4. **结果里最要紧的一段直接贴回对话。** 这样用户不用打开文件就知道成没成。

### 四条容易踩的坑

**坑一：长清单不要塞进提示词，要放进工作区。**
比如「我方标准条款清单」，塞进 `prompt` 会顶到 8 KiB 上限，而且**用户改不了它**。
正确做法是建一个 `03_我方立场/` 文件夹，提示词里只写「去读那个文件夹」。清单就成了用户的财产，改完立刻生效。

**坑二：文件夹名写在两个地方，改一处会漏。**
`workspace.json` 的 `path` 定义了文件夹叫什么，`prompt` 里也写死了同样的名字。
**改文件夹名时必须同时改所有提到它的提示词。** v0.6 不做变量替换（那是模板引擎，是执行面），这个重复消不掉。
好消息是：因为有经验第 2 条，用户改名之后 agent 会老实说找不到，而不是乱建。

**坑三：不是每个按钮都要产出文件。**
「换个语气」「要不要升级」这种按钮，直接把答案贴回对话就行，不用存文件。
甚至可以做成反过来问用户的结构化访谈（「课后复盘」就是一段一段问）。`actions` 不是「生成文件的按钮」，是「一句想好的话」。

**坑四：涉及用户真实数据的包，请在 `onboarding.md` 里写一句。**
合同、简历、客户原话、学生信息都会被交给 AI 处理。推荐模板：

> 你的<某某文件>会被交给 AI 处理。涉密内容能不能放进来，请你自己判断。

这不是强制字段——我们不替你做合规承诺，但这句话该有。

## 五、分发：zip 双击解压 + 拖入

**v0.6 只认文件夹，不做一键装 zip，这是刻意的。**

- Node 没有内置解压，写一个 = 新依赖或者自己写解压器（新的攻击面：zip-slip）。
- 折中方案已经够简单：包发在 GitHub 上是一个 zip，**macOS 和 Windows 双击 zip 就自动解压**，
  然后把解出来的文件夹拖进鲸坞窗口。**两步，其中一步是系统自带的。**

给用户的说明可以直接抄这段：

```text
1. 下载 xxx.zip，双击解压（macOS/Windows 都是双击就行）
2. 把解出来的文件夹拖进鲸坞窗口，松手即装好
3. 左上角的工作台按钮里点一下就能用
```

一键装 `.whaledock` 单文件包排到 v0.7，届时会专门处理 zip-slip。

**装包上限**：单个包 ≤ 512 个文件、≤ 5 层目录、总体积 ≤ 32 MiB、单文件 ≤ 8 MiB；包里有符号链接会被直接拒绝。
已装的工作台总数上限 64 个。

## 六、包作者契约

### 我们对你的四条承诺

1. **你今天写的包，将来的鲸坞还能装。** `schemaVersion: 1` 定下的字段含义永不改变。
2. **我们不改你的包**，不重写、不迁移、不自动升级你的文件。
3. **我们不上传你的包内容**到任何地方，也不联网校验它。
4. **你的包解析失败时，我们如实告诉用户是哪一项、什么原因**，不含糊其辞。设置里的「关于这个工作台」会逐条列出来。

还有一条比承诺更硬的规矩：**新版本鲸坞遇到不认识的字段，一律忽略、照常加载**，只在设置里记一条灰色的
「这个包用了 N 个本版本不认识的字段」。绝不会因为多了个字段就说「包坏了」——那是所有插件体系最常见的死法。
所以你可以放心用将来才有的新字段，老鲸坞不会因此拒绝你的包。

### 我们对你的三条要求

1. **包里只能有数据**（JSON / Markdown / PNG / 你自己的 yml）。放了可执行文件我们也不会执行它，但请别放。
2. **声明 `license`。** 不声明的，装的时候会明确标出「未声明许可证」。
3. **别在 `skills.json` 里写你自己没实测过的安装命令。** 用户会照着粘贴。

## 七、给画图 AI 的素材提示词

工作台的 `icon.png` 与 `pet/` 都是可选的，缺了就跟随全局，不影响功能。想做的话把下面这段发给画图 AI：

```text
帮我画一个工作台图标：
- 主体：一个能一眼看出「<换成你的行业，比如合同审查 / 招聘筛选 / 短视频剪辑>」的物件
- 正方形画布 128×128 像素，背景必须完全透明（PNG，带 alpha 通道）
- 主体居中，四周留 10 像素空白，不要裁到边缘
- 干净的粗描边、色块平涂，不要渐变、不要投影、不要文字和水印
- 整体色调偏 <换成你 manifest 里 accent 的颜色>
输出 PNG。
```

`pet/` 的画法与命名规则跟宠物包完全一样，见 [`宠物包制作指南.md`](宠物包制作指南.md)。

## 八、装不上的时候，去哪看原因

设置 → **工作台** → 找到那个包 → 点「关于这个工作台」。里面会逐条列出：

- 哪个文件出了问题、什么原因（比如 `workspace.json：folder-path-invalid（../etc）`）
- 用了几个本版本不认识的字段
- 有没有声明许可证
- 有没有带 agent 预设

包**整个**被拒绝只有四种情况，其余一律「某个字段回落，包还能用」：

| 原因 | 意思 |
| --- | --- |
| `manifest-unreadable` | 没有 `manifest.json`，或它不是普通文件 / 是符号链接 / 超过 64 KiB |
| `invalid-json` / `not-an-object` | `manifest.json` 不是合法 JSON，或顶层不是对象 |
| `schema-unsupported` | `schemaVersion` 存在但不等于 1 |
| `invalid-id` | 文件夹名不合法（是 `.`/`..`、含路径分隔符或控制字符、超过 64 字） |

被拒的包不会拖垮其他包，它会在设置里显示成一条灰色的「未加载：<原因>」。

## 九、完整示例二：电商客服

仓库里的第二个内置包是 [`assets/workbenches/电商客服/`](../assets/workbenches/电商客服/)。它演示的是一类典型重工作台：用户有一份自己维护的资料，agent 只能依据这份资料生成草稿，答不了就明确转人工。

这个示例只含纯虚构语料，共五个声明式数据文件：

```text
电商客服/
├── manifest.json
├── workspace.json
├── actions.json
├── skills.json
└── onboarding.md
```

它故意不放 `theme.json`、`icon.png`、`pet/` 与 `agent.cordis.yml`：缺少视觉素材就跟随全局；agent 预设在没有接通证据前也不冒充可用能力。

### 1. manifest：先把身份与兼容口径说清楚

```json
{
  "schemaVersion": 1,
  "name": "电商客服",
  "summary": "粘进买家问题，秒出带依据的回复草稿；话术库越喂越聪明",
  "version": "0.1.0",
  "author": "SGD",
  "license": "MIT",
  "homepage": "https://github.com/sgd-shine/whaledock",
  "dshRange": "0.1.1-rc.2",
  "accent": "#0ea5e9"
}
```

### 2. workspace：正式资料与候选资料分开

`workspace.json` 的 `root` 是 `电商客服`，只建两个文件夹：

- `话术库/`：只放人已经核准的正式问答。预置 `示例-话术表.txt`，首行是 `问题,答案`，下面 22 条全是虚构演示数据，例如：

  ```text
  什么时候发货？,亲，您拍下后我们48小时内安排发货哦，节假日顺延；发出后单号会第一时间同步给您~
  尺寸怎么选？,亲，详情页有尺寸对照表哦，您按平时用的尺寸对照选；拿不准把具体数据发我，我帮您参考~
  ```

- `待入库/`：只放「收录这条」「批量喂」产生的候选问答。候选永远不会自动进入正式话术表，必须由人审核后手动搬过去。

预置文件为什么是 `.txt` 而不是 `.csv` 或 `.xlsx`：v0.6 的 `folders[].files` 只收 `.md/.txt`。用户自己放进工作区的 `.csv` 不受这个预置白名单限制，所以引导写的是「Excel 建两列 → 另存为 CSV（UTF-8）→ 放进 `话术库/`」。不要为了交付母版去扩大解析面。

工作区根目录的 `缺料清单.md` 也不预置。当前 schema 只能给 `folders[]` 放种子文件，它由「把这题登记为缺料」按钮第一次使用时创建。

### 3. actions：一个总规则，七个窄动作

八个按钮按固定顺序排列，全部是死文本，`confirm` 都是 `false`：

| id | 按钮 | 只负责什么 |
| --- | --- | --- |
| `start` | 开工上岗 | 建立整场值班的依据、待核、转人工与脱敏规则 |
| `draft` | 生成草稿 | 对最近一条买家消息重出三段式草稿 |
| `polish` | 改写得更礼貌 | 只换语气，不改事实与风险判断 |
| `human` | 给我转人工话术 | 只给过渡安抚话术 |
| `gap` | 把这题登记为缺料 | 把脱敏后的问题追加到根目录缺料清单 |
| `collect` | 收录这条 | 把人工定稿追加到待入库候选 |
| `feed` | 批量喂 | 先列候选，等人回复「确认」才写入 |
| `report` | 值班小结 | 只统计本次会话真实发生的数量 |

`start` 的输出合同固定为：

```text
【草稿】可复制的回复；待核或转人工时只写安抚，不猜事实。
【依据】话术表《文件名》第 X 条：「答案原文开头约20字…」
【风险】无 / 待核：原因 / 转人工：类型
```

表头不算条目，第一条问答就是第 1 条。价格、库存、材质、尺寸、物流时效与活动等事实没有命中时一律待核；已发生的退款退货、纠纷、投诉、差评、赔偿、改价承诺与发票细节一律转人工；话术冲突或疑似过期也待核，不允许 agent 自己选边。

### 4. onboarding：先讲人工边界，再讲怎么用

引导里明确写了四件事：鲸坞只出草稿、发送由人决定；示例语料正式使用前要替换；粘贴内容会交给 AI 处理；真实消息先脱敏——昵称改成 `买家A/B`、订单号只留尾号 4 位、手机号和地址整段删除。

这类涉及客户数据的包，不能只写「三步上手」。数据去了哪里、哪些内容不该原样粘贴、候选资料会不会自动升格，都必须在首次引导里说清楚。

### 5. 最小回归证据

这个包的自动检查直接放在 `test/workbenches-smoke.js`：零解析 issue、五文件白名单、两个工作区目录、表头外恰好 22 条虚构话术、每行恰好一个英文逗号、八个 action 顺序与红线、空 skills、无 agent/theme/pet/icon，以及 `缺料清单.md` 不被预置。新增行业包时，照这个粒度为自己的数据合同补一条真实包回归即可。

## 十、视频驾驶舱文件契约（v0.7）

视频驾驶舱是鲸坞本体的第一方界面，不是包内脚本。工作台包仍然只有数据；包作者只需在 `manifest.json` 里选择性声明：

```json
{
  "schemaVersion": 1,
  "name": "短视频创作台",
  "cockpit": "video"
}
```

`cockpit` 目前只接受精确值 `video`。不写、写成其他值，或用旧版鲸坞打开，都继续走普通工作台；旧版会把它当成未知字段忽略，不影响装包和切换。该字段不会给包增加执行、联网或读取平台数据的能力。

### 驾驶舱会看哪些文件

驾驶舱只扫描工作区内下列位置的普通 UTF-8 `.md` / `.txt` 文件，软链接拒绝，单文件上限 512 KiB：

| 目录 | 不写 `stage` 时推断为 |
| --- | --- |
| `01_选题库/` | `topic` |
| `02_脚本/` | `script` |
| `03_口播稿/` | `shoot` |
| `04_素材清单/` | `shoot` |
| `06_灵感收件箱/待分拣/` | `inspiration` |
| `07_打法库/` | `asset` |
| `08_发布检查/` | `publish` |

其他目录不进入驾驶舱扫描，但原文件仍留在工作区。旧稿完全可以没有 front matter：标题依次取 `title`、正文第一条 Markdown 标题、文件名；阶段按上表推断。驾驶舱不会为了“升级格式”重写旧稿。

### 可选 front matter

front matter 必须位于文件开头的一对 `---` 之间，格式是简单的单行 `key: value`；它不是完整 YAML，不支持嵌套。列表字段使用 ` | ` 分隔：

```markdown
---
title: 小团队怎样用一张表完成选题
stage: topic
platforms: 抖音 | 视频号
audience: 一人公司
angles: 先看失败样本 | 先看完成结果
angle: 先看完成结果
hooks: 这张表替我省了三小时 | 别再从空白页写起
hook: 这张表替我省了三小时
decision: 请选择主角度
status: needs-decision
updated: 2026-08-21T12:00:00.000Z
source: manual
topicId: topic-001
aiDisclosure: unknown
---

# 正文从这里开始
```

| 字段 | 含义与受支持值 |
| --- | --- |
| `title` | 驾驶舱卡片标题 |
| `stage` | `inspiration`、`topic`、`script`、`shoot`、`edit`、`publish`、`data`、`review`、`asset` |
| `platforms` | 平台文字列表，只展示，不会访问平台 |
| `audience` | 受众说明 |
| `angles` / `hooks` | 待选择的角度 / 钩子列表 |
| `angle` / `hook` | 已由人选定的角度 / 钩子 |
| `decision` | 待拍板提示；非空时进入“今天” |
| `status` | `needs-decision` 会进入“今天”；`ignored` 不计入航道数量，且不会删除文件 |
| `updated` / `source` / `topicId` | 更新时间、来源与业务标识，均为本地文字元数据 |
| `aiDisclosure` | 发布检查只接受 `unknown`、`ai`、`not-ai`；它是人的显式选择，不是平台回读 |

每个字段最多出现一次。无法识别的字段和无法解析的原始行会原样保留；驾驶舱只忽略它们并记录问题，不会擅自删除。鲸坞只会改动用户刚刚操作的已知字段；若文件在操作期间被别的编辑器改过，CAS 校验会拒绝覆盖。

### 正文块、发布灯与恢复副本

脚本现场把 Markdown 标题、表格行、围栏代码块和以空行分隔的段落作为可交互块。Agent 先改 `00_鲸坞建议/` 下的完整建议副本；采用时只替换被选中的一个块，其他正文和 front matter 必须逐字保持。撤销同样要求当前文件仍与采用结果一致。

发布检查灯只写回带 `<!-- whaledock:... -->` 标记的清单行。“本人已发布”只是本地人工记录，不等于平台回读；鲸坞不会代发，也不会凭空生成播放量、漏斗或合规结论。

每次成功的受控替换都会在原文件同目录保留一份 `WhaleDock-recovery-*.bak`；只新建文件的动作不会产生这份副本。它保存被替换的旧文件实体，也能接住仍握着旧文件的编辑器晚到的保存，不是第二个正式项目。确认目标文件与恢复文件都没有遗漏后，再由人决定归档或删除；鲸坞不会自动删除，也不会把校验失败的恢复副本装成正式文件。特殊的只支持复制回退文件卷或中断冲突可能留下额外恢复证据，遇到“需要人工恢复”时应先保留整个目录再核对。
