## 0. 先说结论

视频作者在 01:34 将该项目描述为一款围绕 **DeepSeek 官方网页版**做桌面增强的本地端；本报告把这项作者声明作为工作假设，但未获得源码或网络证据独立验证。画面所示产品把网页聊天扩展成了一个接近“系统级 AI 快捷助手”的形态：可截图、在浏览器页面划词、共享 WPS 文档或当前屏幕快照，再由紧凑副窗调用 DeepSeek 回答；同时提供主副窗口切换、快捷键、托盘、通知、详细设置、提示词模板和“问 AI 看说明书”等能力。

它最值得鲸坞借鉴的不是“直接接 DeepSeek 官网”的技术路线，而是以下四种交互思想：

1. **上下文就地获取**：用户不必先保存、上传、再解释，截图或选中文本后即可发问。
2. **低打扰副窗**：完整主窗负责历史和长对话，副窗负责随叫随用的短任务。
3. **系统级反馈**：截图和操作反馈提供可配置开关；回答完成则实际演示了原生通知与点击返回。
4. **设置可见、帮助可问**：复杂能力不埋在 JSON 和说明书里；用户可搜索说明，甚至直接把说明书交给 AI 解答。

但鲸坞当前是 **dsh 后端的启动、托管和 Web UI 容器**，不是通用聊天客户端。v0.4 已经拍板做“图片入口 v1（全局截图快捷键、拖图、剪贴板粘贴）”，但若把视频中的完整截图动作体系、划词、WPS、屏幕共享和官网自动交互整套照搬，会把产品从“Agent 桌面底座”改造成“系统级 AI 助手”，同时引入权限、隐私、上游接口和跨平台维护问题。因此新增部分仍必须先做产品边界判断和接口侦察，不能只凭演示效果立项。

初步建议是：

- **已经拍板、应按总纲推进**：v0.2 原生设置界面；v0.3 Token 看板 / 预算熔断 / 战报分享卡片；v0.4 多工作区与图片入口 v1（全局截图快捷键、拖图、剪贴板粘贴）。图片理解层按既定顺序路由“官方视觉接口 → 已安装视觉插件 → 本地系统 OCR”。
- **需项目所有者消除冲突**：完成通知在路线表中被列入 v0.3，但同一总纲的“已定决策”和末尾候选池又把它列为待提案项。Claude 只能标为 `NEEDS-OWNER`，不能擅自排期。
- **先设计侦察、获批后再执行**：紧凑副窗、通用文件附加、说明书问 AI、稳定会话提交与任务完成事件。
- **暂不进入近期开发**：WPS 专项接入、持续屏幕共享、跨应用划词工具、多大模型官网聚合、液态玻璃。
- **不要重做**：dsh 已经提供或应由 dsh 提供的模型模式、搜索、思考过程、会话和 Agent 能力。

以上只是给 Claude 的预分流，不是最终立项结论。

## 4. 功能清单、作用与证据强度

### F01. DeepSeek 网页桌面壳

**可见行为**：完整主窗口承载 DeepSeek 风格网页会话，保留历史列表、输入框和网页对话能力；片尾声明直接与 DeepSeek 官网交互。  
**用户作用**：把网页标签页变成可托盘驻留、可快捷呼出的桌面应用。  
**证据**：E1–E2。窗口与片尾声明可见，但底层交互机制未展示。  
**对鲸坞意义**：只能借鉴桌面交互；鲸坞不应因这份视频自动改成 DeepSeek 官网包装器，它的上游是本地 dsh。

### F02. 快速 / 专家 / 识图三种会话模式

**可见行为**：新对话入口可以选择快速模式、专家模式和识图模式；输入区另有深度思考与智能搜索入口。  
**用户作用**：用户先选择任务类型，再进入适合的模型行为，减少反复开关。  
**证据**：E2。模式控件可见，但视频没有比较三种模式的输出差异。  
**对鲸坞意义**：优先复用 dsh 已有模型 / Agent / 工具选择，不应由 WhaleDock 重新实现一套模型语义。

### F03. 全局快捷键截图与区域选择

**可见行为**：从桌面触发截图，全屏变暗，拖出矩形区域并可调整边界；设置页显示默认快捷键 `Alt+C`。  
**用户作用**：不离开当前应用即可把视觉上下文交给 AI。  
**证据**：区域选择与截图操作链为 E3；`Alt+C` 只在设置页可见，快捷键映射本身为 E2。  
**开发含义**：涉及跨平台截屏、macOS Screen Recording 权限、Windows 多屏与缩放、窗口排除策略和快捷键冲突。

### F04. 截图标注

**可见行为**：顶部“标注”栏包含自由画笔、矩形、圆形、红 / 绿 / 蓝 / 黄 / 白颜色、撤销和删除；演示实际画了红圈。  
**用户作用**：用视觉圈选告诉 AI “关注这里”，降低文字描述成本。  
**证据**：E3。  
**开发含义**：它不是简单调用系统截图，至少需要一个全屏选择层、Canvas / SVG 标注层和导出管线。

### F05. 截图后的七类动作

**可见行为**：底部动作栏清晰显示 `复制 / 提取文字 / 翻译 / 解释 / 当前对话 / 新对话 / 取消`。截图可附带自动生成的解释、OCR 或翻译提示词进入紧凑聊天窗。  
**用户作用**：同一个截图入口同时承担复制、OCR、翻译、解释和问 AI。  
**证据**：解释、提取文字、翻译均有结果展示，E3；当前对话 / 新对话的长期行为只到控件层，E2。  
**开发含义**：应拆成三层：原生采集 / 复制与预览；官方视觉接口、已安装视觉插件或本地系统 OCR 的理解路由；稳定接口或人类确认降级的会话交付。复制和 OCR 不依赖 dsh 图像直传；翻译 / 解释可使用 OCR 文本；没有自动提交接口时可让用户确认后复制粘贴或落地文件。DOM 自动化不是唯一替代方案，也不得作为正式交付方案。

### F06. 共享 WPS Word / Excel / PDF 与通用上传

**可见行为**：分享菜单列出 `共享WPS Word / 共享WPS Excel / 共享WPS PDF / 上传文件`。Word 通过 `测试文档.docx` 完成一次端到端问答；Excel 和 PDF 只在菜单与设置中出现。  
**用户作用**：把当前办公文档直接作为上下文，省去找文件和上传步骤。  
**证据**：Word 为 E3；Excel / PDF 为 E2。  
**开发含义**：WPS 专项桥接平台局限强、易受版本变化影响；对于拥有工作区文件访问能力的 Harness，价值可能低于普通聊天产品。

### F07. 共享当前屏幕给识图模式

**可见行为**：开启共享后自动进入识图模式；聊天中出现当前屏幕缩略图，AI据此回答 GitHub Release 应下载哪个文件。  
**用户作用**：适合“我现在这个页面该点哪里 / 下载哪个 / 报错是什么”的现场求助。  
**证据**：屏幕快照输入与回答链是 E3；是否连续实时流是 E0。  
**开发含义**：报告中只能称“屏幕上下文 / 屏幕快照”，不能称“实时视频共享”。持续共享会显著增加隐私与资源风险。

### F08. 浏览器页面内划词浮动动作栏

**可见行为**：在浏览器页面选择文本后，选区附近自动出现 `问问DeepSeek / 复制 / 翻译 / 解释`。点击后副窗带入选中文字和模板。视频没有证明 WPS、原生应用或任意第三方应用都兼容。  
**用户作用**：阅读时不用复制、切应用、写提示词。  
**证据**：浏览器页面内链路为 E3；跨应用 / 全系统兼容为 E0。  
**开发含义**：若要扩展到跨应用，Windows 与 macOS 的选区监听、辅助功能权限、应用兼容性差异都很大；这是一条独立产品线，不是一个小按钮。

### F09. 可编辑、排序和扩展的划词动作 / 提示词

**可见行为**：划词按钮列表支持拖拽排序、重命名、删除和添加；翻译模板使用 `{targetLang}`、`{content}`，解释模板使用 `{content}`。  
**用户作用**：把常用提示词变成就地动作，用户可以扩展自己的处理方式。  
**证据**：E2。配置页清晰可见，但视频没有演示新增自定义动作后的完整运行。  
**开发含义**：可抽象为通用“动作模板”系统，但只有在已有稳定上下文输入与提交接口时才值得做。

### F10. 快捷问答会话自动清理

**可见行为**：设置项 `提问小窗对话自动清理` 处于开启；画面字幕称回答完成后自动清除对话记录。  
**用户作用**：把一次性问答与长期会话分离，减少历史噪声。  
**证据**：开关为 E2，清理时机和保留策略未做端到端展示。  
**开发含义**：若鲸坞未来做副窗，需要先定义“临时会话”契约，不能直接删除 dsh 历史数据。

### F11. 通知与反馈矩阵

**可见行为**：通知页有总开关、截图反馈、操作反馈、划词反馈、快捷键提示、回答完成提醒；回答完成后出现 Windows 原生通知并可点击回到主窗。  
**用户作用**：把异步等待从“盯着窗口”变成“完成后提醒”。  
**证据**：通知设置项可见为 E2；回答完成通知实际出现并被点击返回主窗为 E3。  
**开发含义**：鲸坞已有后端恢复失败的通知请求与点击处理代码，但未签名 macOS 的通知中心投递已证实失败，当前由错误对话框兜底，Windows 原生投递尚未验证；同时没有可靠的“任务 / 回答完成”事件。实现前必须找到 dsh 稳定事件源并跨平台验证通知身份、投递和点击回跳。

### F12. 主窗 / 副窗双形态与共享会话

**可见行为**：标题栏按钮在完整主窗口与窄小副窗间切换；副窗继续显示同一会话，画面还能看到置顶、最小化和关闭控件。视频没有逐一验证这些控件的实际行为。  
**用户作用**：完整主窗适合历史和深度对话，副窗适合覆盖在当前工作上方快速处理。  
**证据**：主副窗切换与同一内容延续为 E3；置顶、最小化、关闭等只看到控件或设置，相关行为为 E2。  
**开发含义**：值得作为鲸坞差异化候选，但稳定提交消息和同步同一 dsh 会话是前置条件。

### F13. 窗口生命周期、托盘和全局快捷键

**可见行为**：副窗默认置顶、关闭进托盘、开机自启、启动最小化到托盘；截图快捷键 `Alt+C`、副窗呼出键 `Alt+Space`、可配置划词开关快捷键。  
**用户作用**：让工具始终在后台可用，同时不长期占据桌面。  
**证据**：设置页为 E2；副窗快捷呼出在帮助文档中也有说明。  
**对鲸坞意义**：托盘和全局呼出已经存在；设置 UI、自启、启动最小化和多快捷键仍可借鉴。

### F14. 详细设置中心与配置可见性

**可见行为**：左侧分为应用、对话、工具、个人中心和帮助；底部有“重置默认”和“已应用”。  
**用户作用**：把复杂行为从隐藏配置文件搬到可理解的界面。  
**证据**：E2。  
**对鲸坞意义**：与当前 v0.2 已定“设置界面”高度一致，是最强的可直接吸收项。

### F15. 可搜索、可跳转的内置说明书

**可见行为**：说明书以卡片分组展示主副窗、快捷键、截图、划词、对话和共享屏幕；有搜索框，卡片标注对应设置路径。  
**用户作用**：用户能按问题搜索，并直接知道应该去哪个设置页面。  
**证据**：E2。页面、搜索入口和设置路径标注清晰可见，但搜索匹配和设置深链都未端到端演示。  
**开发含义**：可在不依赖 dsh 内部接口的情况下先做静态帮助中心；设置深链应作为待实现行为单独验收。

### F16. “看不懂，问问 AI”说明书问答

**可见行为**：点击后副窗附加 `DeepSeek桌面版详细说明…` Markdown 文件（6.66 KB），AI读后生成三个用户可能想问的问题。  
**用户作用**：把静态说明转成自然语言答疑，降低第一次使用门槛。  
**证据**：E3。  
**开发含义**：需确认 dsh 是否已有本地文档上下文、文件附加或帮助问答能力；若没有，不应通过 DOM 自动上传实现正式功能。

### F17. GitHub Release 更新入口

**可见行为**：更新页显示 `v1.0.0` 和跳转 GitHub Release 的按钮。  
**用户作用**：让用户知道版本并找到下载入口。  
**证据**：E2；未演示检测、下载、校验、安装或回滚。  
**对鲸坞意义**：可借鉴“新版提醒”，但不能把一个 Release 跳转按钮等同于自动更新。

## 6. 六条完整用户旅程

### 旅程 A：看到问题，截图就问

`Alt+C → 框选 → 可选标注 → 解释 / OCR / 翻译 → 当前或新会话 → 副窗看结果`

核心价值：将视觉上下文采集、提示词生成和会话路由合为一次动作。

### 旅程 B：读到一段话，就地处理

`选择文本 → 浮动动作栏 → 复制 / 翻译 / 解释 / 自由提问 → 副窗回答`

核心价值：避免复制、切应用、粘贴和重复写模板。

### 旅程 C：正在写文档，直接问文档

`分享 → 当前 WPS Word → 文件芯片 → 提问 → AI 读取并总结`

核心价值：减少找文件和手动上传，强调“当前工作对象”而不是“某个文件路径”。

### 旅程 D：不知道页面该怎么操作

`共享屏幕 → 自动切识图 → 发问 → 当前屏幕快照进入对话 → AI 给操作建议`

核心价值：把“描述我眼前的页面”替换为直接提供视觉上下文。

### 旅程 E：长任务结束后提醒我

`发起问题 → 切去别的应用 → 回答完成 → 原生通知 → 点击返回主窗`

核心价值：解除盯窗口等待。

### 旅程 F：说明书看不懂，直接问说明书

`打开帮助 → 搜索或点击“看不懂，问问 AI” → 自动附加说明书 MD → AI 生成 / 回答问题`

核心价值：让复杂产品具备自解释能力。

## 8. 鲸坞当前真实基线

### 8.1 产品本质

鲸坞当前的三层结构是：

1. Electron 原生壳：生命周期、窗口、托盘、菜单、快捷键、通知。
2. dsh 外部子进程：查找、启动、等待、恢复和清理。
3. dsh 官方本地 Web UI：主窗口直接加载 `http://127.0.0.1:<port>`。

鲸坞没有自研聊天数据层，也没有把 dsh 的会话、任务、模型、工具调用和文件系统重新实现一遍。当前主窗口没有 preload，`contextIsolation: true`、`nodeIntegration: false`，只负责安全地承载上游页面。

### 8.2 已有能力与视频功能的关系

| 能力 | 鲸坞当前情况 | 与视频的关系 |
| --- | --- | --- |
| 托盘常驻、关窗隐藏 | 已有 | 已吸收同类思想 |
| 全局快捷键呼出 / 隐藏 | 已有，默认 `⌘⇧H` | 视频的副窗快捷键是增强形态 |
| 窗口记忆、刷新、缩放、全屏 | 已有 | 主窗基础能力已覆盖 |
| 后端自动启动 / attach / 清理 / 恢复 | 已有 | 视频产品没有展示这一类 Agent 后端托管能力 |
| 启动页与实时后端日志 | 已有 | 鲸坞独有价值，不应因仿视频而弱化 |
| 设置窗口 | 未有；当前手改 JSON；已定入 v0.2 | 视频提供了强交互参考 |
| 开机自启、启动最小化 | 未有 | 可纳入设置设计，但要跨平台实现 |
| 紧凑副窗 | 未有 | 候选，需要 dsh 稳定会话接口 |
| 回答 / 任务完成通知 | 无可靠任务事件；已有后端恢复失败的通知请求与回退代码，但未签名 macOS 通知投递已证实失败，实际由错误对话框兜底；Windows 未验证 | 同一总纲对“完成通知”是否已进 v0.3 存在冲突，需项目所有者确认；技术上仍需侦察 dsh 事件源 |
| 图片入口 / 本地 OCR | 尚未实现；已拍板入 v0.4 | WhaleDock 负责全局截图快捷键、拖图、剪贴板粘贴三类入口；理解层按官方视觉接口 → 已安装视觉插件 → 本地系统 OCR 路由 |
| 截图翻译 / 解释 / 自动送入会话 | 尚未实现，未全部拍板 | 需分别查 dsh / 插件能力和稳定消息提交接口，不能与截图采集本身捆成一个前置 |
| WPS / 屏幕共享 / 划词 | 未有 | 不属于当前核心，复杂度和权限都高 |
| 内置帮助中心 | 未有 | 可独立开发，风险较低 |
| Token 看板 / 预算熔断 / 战报分享卡片 | 已定 v0.3，尚需 Token 数据侦察 | 视频没有覆盖，不能被新想法挤掉；战报与看板共用真实数据源 |
| 多工作区 | 已定后续路线 | 视频没有覆盖，仍是鲸坞自身高价值方向 |

### 8.3 当前路线图优先级

以 `docs/路线图定稿-2026-08-14.md` 为当前总纲：

- v0.2：Windows 安装器与便携版、免 Node、Intel Mac、设置界面、更新能力，并行 Token 数据侦察。
- v0.3：Token 看板、预算熔断、战报分享卡片；路线表还写了完成通知，但同一总纲第 12 行与末尾候选池又把完成通知列为待提案，状态为 `NEEDS-OWNER`。
- v0.4：多工作区管理 + 图片入口 v1（全局截图快捷键、拖图、剪贴板粘贴）；图片理解按“官方视觉接口 → 已安装视觉插件 → 本地系统 OCR”路由，不在鲸坞自研视觉模型。
- v0.5：桌面宠物与皮肤。

视频功能若要进入，应说明是替换、插入还是依附这些已定版本，不能无声覆盖现有总纲。

## 9. 初步“已拍板 / 复用 / 待确认 / 侦察 / 延后 / 不做”矩阵

这是给 Claude 的挑战对象，不是新的立项批准。状态枚举固定如下：

- `COMMITTED`：当前总纲已经拍板，按既定版本推进。
- `REUSE`：已有或应复用 dsh / WhaleDock 能力，不另写一套。
- `NEEDS-OWNER`：文档冲突或产品边界需要项目所有者确认。
- `RECON-PLAN`：本轮只写侦察方案；未经单独批准不得执行 POC、发送内容或触发权限。
- `LATER`：有潜在价值，但不能挤占已定范围；写明重新开放条件。
- `NO`：当前产品内不做；若未来重开应另立项或满足明确条件。

## 10. 推荐的技术边界

### 10.1 A 路线：独立原生伴生窗口——优先

适用：设置、帮助、副窗外壳、截图选择层、预览确认、通知。

原则：

- 继续保持 dsh 主页面 `nodeIntegration: false`。
- 新能力放在独立 BrowserWindow；需要系统能力时使用专属 preload 和最小 IPC 白名单。
- 主页面仍是上游 dsh UI，不把 Node 权限注入其中。
- 原生功能失败时不影响 dsh 主界面可用。

### 10.2 B 路线：通过 dsh 稳定接口集成——涉及会话时首选

适用：提交提示词、附加图片 / 文件、选定会话、读取任务状态、通知、临时会话。

可接受的数据源：

- 正式 JSON-RPC / headless API。
- dsh 插件事件或明确版本化接口。
- 有结构、可回归验证的本地会话 / 任务记录。

不得把页面文字、日志沉默或 CSS selector 当作关键任务完成判断。

### 10.3 C 路线：DOM 注入 / 自动点击——仅限短期侦察

用途：验证交互价值或发现上游能力，不进入正式产品承诺。

风险：

- dsh 仍处于 rc，DOM 和选择器会变化。
- 破坏当前主窗口隔离边界。
- 登录、文件、会话和发送按钮的自动化可能造成误发或数据泄露。
- 很难写出稳定、跨平台、可回退的自动化测试。

### 10.4 D 路线：fork dsh Web UI 或自研聊天 UI——当前不建议

它会把鲸坞从薄壳变成上游前端维护者，工作量、同步成本和安全责任都显著上升。除非上游稳定到 1.0、产品价值被 POC 证实且用户明确批准，否则不进入开发方案。

## 12. 安全、隐私与人类门槛

任何截图、划词、屏幕或文件功能必须满足：

1. **用户主动触发**：不能后台静默抓屏、抓选区或上传文件。
2. **发送前可见**：截图 / 文件必须先预览，并明确目标会话和将要发送的内容。
3. **持续状态可见**：若未来做屏幕共享，必须有永久可见指示和一键停止；首版不做持续共享。
4. **默认不改源文件**：尤其禁止复制视频中“共享 PDF 自动保存编辑后 PDF”的副作用。
5. **窗口排除可控**：截图开始前隐藏鲸坞；发送前强制预览，并允许取消、裁剪或遮挡。不要承诺跨平台自动识别并排除所有敏感窗口。
6. **权限可解释**：macOS TCC、Windows 权限、辅助功能权限被拒绝时要给出可恢复路径，不反复弹窗。
7. **日志不泄密**：不记录完整截图、文件内容、提示词、Cookie、API Key 或个人路径中的敏感片段。
8. **不新增遥测**：继续遵守鲸坞零遥测约束。
9. **不扩大 dsh 页权限**：不得为方便实现而给上游 Web UI 开 `nodeIntegration`。
10. **对外动作保留人类确认**：官网登录、发送、发布、更新安装、权限授权都必须保持明确人类门槛。

## 13. 候选功能的最小验收标准

### 设置界面

- 能读取现有 `port / autoStartBackend / command / dshVersion / workdir / hotkey`。
- 输入校验明确，保存失败不能伪装成功。
- 修改快捷键后旧快捷键注销、新快捷键注册，失败时回滚。
- 配置迁移可回退，手工 JSON 仍可兼容。
- 不新增运行时依赖；`npm run smoke` 14 项继续 ALL PASS，并补设置数据层测试。

### 紧凑副窗

- 全局快捷键可显示 / 隐藏；可置顶；不抢焦点的场景有明确定义。
- 主窗与副窗指向同一个明确会话，不出现消息丢失或重复发送。
- 后端不可用时显示真实状态，不展示空白网页。
- 关闭、切换、退出不产生多份 dsh 或孤儿窗口。

### 图片入口 v1（获批实施后的验收）

- 全局截图快捷键、拖入图片、剪贴板粘贴三类入口都进入同一套预览、确认、取消和临时文件清理流程。
- 截图入口在单屏、多屏和不同缩放下选区坐标准确；权限拒绝、取消和重新授权均可恢复。
- 发送前显示图片预览、提示词、目标会话及实际采用的理解路径（官方视觉接口 / 已安装视觉插件 / 本地系统 OCR）。
- 默认只处理用户明确选择的静态图片，不后台持续抓屏；拖图和粘贴不读取用户未选择的其他文件或剪贴板历史。
- 只有在 dsh 提供稳定会话提交接口时才允许自动送入会话；否则降级为用户确认后的复制、粘贴或文件附加，不使用 DOM 自动化。
- 用户取消或处理结束后无残留临时图片；日志中不记录图片内容、OCR 全文或剪贴板内容。

### 任务完成通知

- 只在正式完成事件触发；失败、取消、等待人工输入不可误报成功。
- 同一任务只通知一次；重启后不会重复通知旧任务。
- 点击通知能回到正确任务 / 会话。
- macOS 未签名状态只能报告 `NEEDS-HUMAN / NEEDS-SIGNING`，不能冒充通知中心已通过。

### 帮助中心

- 内容与当前版本一致，卡片深链能打开对应设置。
- 搜索支持功能名和用户痛点词，不要求用户先知道术语。
- “问 AI”前明确展示将附加的本地说明文档；失败时仍能阅读静态说明。
