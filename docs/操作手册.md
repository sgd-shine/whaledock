# 鲸坞 WhaleDock 操作手册：从跑通到发布 GitHub（原名 Harness Desktop）

这份手册是写给你（SGD）的，假设你完全不写代码。照着做就行，每一步的命令都可以直接复制粘贴。本地项目文件夹仍叫 `harness-desktop`（需要时可自行改为 `whaledock`）；代码已通过 14 项自动化测试，以及 macOS 源码态和 Finder 安装版的真实 dsh 回归。

## 〇、这个 App 是怎么回事（30 秒版）

你现在用 Harness，要先开终端敲命令，再去浏览器开 `127.0.0.1:3080`。这个 App 把这两步合成一次点击：双击图标 → 它自动在后台把 `dsh` 服务拉起来（默认锁定已验证的版本，防上游变动）→ 用一个真正的 Mac 窗口显示 Harness 界面。附赠：菜单栏托盘常驻、`⌘⇧H` 全局呼出、启动日志面板、退出时自动关干净后台进程。

技术选型说一句：用的是 Electron 而不是 Tauri，因为当前版本只需要装一个 Node.js（跑 Harness 本来就要装），不用碰 Rust 编译环境，出问题也最好排查。代价是安装包一百多 MB，对桌面工具来说无所谓；免装 Node 是 v0.2 的明确目标。

## 一、准备环境（只做一次）

你既然已经用过 Harness 网页版，大概率已经装了 Node.js。打开「终端」（聚焦搜索输入 Terminal），输入：

```bash
node -v
```

如果显示 `v22.12.0` 或更高版本，跳到第二步。源码安装使用的 Electron 43 要求 Node 22.12+；如果版本更低或提示找不到命令，去 [nodejs.org](https://nodejs.org) 下载 macOS 的 LTS 安装包（.pkg 文件），像装普通软件一样装好，重开终端再验证一次。

## 二、第一次把 App 跑起来

1. 把仓库文件夹放到你喜欢的位置（本地目录名仍可叫 `harness-desktop`，GitHub 仓库名改为 `whaledock`）。
2. 打开终端，进入这个文件夹并安装依赖（第一次要几分钟）：

```bash
cd /你的路径/harness-desktop
npm install
```

3. 启动：

```bash
npm start
```

正常情况下你会看到深蓝色的启动页 → 后端日志滚动 → 几秒到几分钟后（第一次要下载组件）主窗口打开，里面就是你熟悉的 Harness 界面。

**如果启动页报错**：最稳的兜底是自己在另一个终端窗口先跑 `npx -y @deepseek-ai/dsh@0.1.0-rc.6 web`，等它起来后回到 App 点「重试」——App 检测到服务已在运行就会直接接入。报错时也可以点「复制日志」，把日志直接丢给 Claude 帮你看。

跑通后玩一下这几个点（拍视频都用得上）：关掉窗口 App 不退出，点菜单栏的鲸鱼模板图能再唤出；在任何应用里按 `⌘⇧H` 一键呼出/隐藏；菜单「视图」里能缩放、进全屏；「后端」菜单里能重启服务、看日志。

## 三、打包成 .dmg 安装包

```bash
npm run dist
```

跑完后产物在 `release/` 文件夹：一个 `.dmg`（发给别人装的）和一个 `.zip`。双击 dmg 把 App 拖进「应用程序」就完成安装。

注意：安装包没有 Apple 签名（签名+公证需要每年 99 美元的开发者账号，以后再说），所以**第一次打开要右键点击 App → 打开**，不然系统会拦。这一点 README 里已经写给你的用户了，拍视频时也值得口播一句，很多人会卡在这。

## 四、发布到 GitHub

`v0.1.0` 已通过 GitHub Actions 自动构建并发布。当前仓库地址为 `https://github.com/sgd-shine/whaledock`，历史 `v0.1.0` 安装包在 `https://github.com/sgd-shine/whaledock/releases/tag/v0.1.0`；GitHub 会把旧地址自动重定向到新地址。

**以后发布新版本（自动路线，推荐）**

1. 更新 `package.json` 里的版本号，提交并 push 到 `main`。
2. 在终端为同一版本打一个新标签并推送，例如 `git tag v0.1.1 && git push origin v0.1.1`。
3. `.github/workflows/release.yml` 会在云端 Mac 上依次运行 `npm ci`、14 项 smoke、dmg/zip 构建并发布 Release；去仓库的 Actions 与 Releases 页面确认全部成功。

**备用手动路线：** 如果自动流程临时故障，先本地运行 `npm run dist`，再去仓库网页 → Releases → Draft a new release，选择对应的新标签，把 `release/` 里的 dmg 与 zip 上传后 Publish。不要重复使用已经发布的 `v0.1.0` 标签。

发布后建议给 README 补一张窗口截图或演示 GIF，把你拍视频时的素材复用进去会好看很多。

## 五、拍演示视频的建议

系统设置成深色模式（App 和图标都是按深色调设计的），开勿扰模式关通知，录屏用 QuickTime（免费）或 Screen Studio（带缩放动效，更出片）。分镜可以这么排：

1. **钩子**（10 秒）：先展示"原来的样子"——开终端敲命令、浏览器一堆标签页里找 Harness，一句话点出痛点。
2. **转折**：双击 Dock 里的 鲸坞 WhaleDock 图标，启动页出现、日志滚动、窗口弹开——这个自动拉起后端的过程就是本片最大的"哇点"，值得给特写。
3. **功能秀**（每个 5-10 秒）：菜单栏托盘点开；切到别的应用按 `⌘⇧H` 瞬间呼出；关窗口后台还在、再唤出秒开；「后端」菜单重启服务。
4. **收尾**：亮出 GitHub 仓库页面和 Releases 下载页，口播开源免费、MIT 协议、欢迎 star，提醒首次打开要右键。

一个加分细节：启动页上有实时滚动的后端日志，观众能直观看到"它在帮我干活"，比纯 loading 动画有说服力。
