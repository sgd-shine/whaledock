# 鲸坞 WhaleDock 操作手册

这份手册写给不写代码的 SGD 和普通用户。鲸坞是 **DeepSeek Harness（dsh）的非官方桌面客户端**：它负责启动或接入本机 Harness 后端，再把 Web UI 放进桌面窗口。项目本身采用 MIT 协议，与 DeepSeek 官方无关。

v0.2 新增 Windows x64、Intel Mac、免装 Node 的内置引擎、设置窗口、开机自启/启动最小化和更新提醒。Windows x64 目前按**实验性支持（未真机验证）**发布；GitHub Actions 只证明构建与纯 Node 合约，不能写成 dsh 或半自动更新已经 Windows 真机通过。

> 版本提示：[`v0.3.0`](https://github.com/sgd-shine/whaledock/releases/tag/v0.3.0) 是当前已公开发布的稳定版，为非 draft、非 prerelease；`releases/latest` 已命中 v0.3 正式版。本手册的任务、用量、通知、预算与战报功能已包含在 v0.3.0 正式资产中。

## 一、按电脑选择下载文件

打开 [WhaleDock Releases](https://github.com/sgd-shine/whaledock/releases)，选择同一版本下与你电脑匹配的文件：

| 电脑 | 下载文件 |
| --- | --- |
| M1/M2/M3/M4 等 Apple Silicon Mac | `WhaleDock-<版本>-arm64.dmg` |
| Intel Mac | `WhaleDock-<版本>-x64.dmg`（目前仅 Apple Silicon + Rosetta 抽查，未做 Intel 真机） |
| Windows 10/11 x64，日常使用 | `WhaleDock-Setup-<版本>.exe` |
| Windows 10/11 x64，不想安装 | `WhaleDock-<版本>-portable.exe` |

普通用户不需要先安装 Node.js。每个安装包都带有锁定版 dsh 运行环境；如果电脑已经装了可用的 Node/dsh，鲸坞默认会先尊重现有环境，找不到时才启用内置引擎。

源码开发者才需要 Node.js 22.12 或更高版本，详见「八、源码运行与打包」。

## 二、安装与首次打开

### macOS

1. 双击 dmg，把 WhaleDock 拖入「应用程序」。
2. 当前安装包没有 Apple 签名与公证。第一次请在「应用程序」中**右键 WhaleDock → 打开 → 打开**。
3. 后续可以直接双击启动。

### Windows 安装版

1. 双击 `WhaleDock-Setup-<版本>.exe`。
2. 当前安装器没有代码签名。SmartScreen 若显示「Windows 已保护你的电脑」，点击**更多信息 → 仍要运行**。
3. 安装器按当前用户安装，不应要求管理员权限。

只从本项目 Releases 页面下载。下载页同时提供 `SHA256SUMS-mac.txt` / `SHA256SUMS-win.txt`；对分发来源有疑问时，先核对 SHA-256 再运行。

### Windows 便携版

便携版不需要安装，放到固定目录后双击即可。不要长期从浏览器「下载」临时目录直接运行；如果启用开机自启，登录项会指向这个 exe。移动后，鲸坞下次启动会尝试修正到新路径，但固定位置最省心。

### 首次启动会发生什么

鲸坞会先检查设置端口（默认 `3080`）：

- 已有 Harness：直接接入，不重复启动，也不会在退出时关掉外部服务；
- 有其他网页服务：启动页显示黄色警告，可改端口或在确认后仍然接入；
- 端口空闲：按探测链启动 dsh，并在就绪后打开主窗口。

默认探测顺序是：自定义命令 → 系统 PATH 中的 dsh → 系统 PATH 中的 npx（锁定 `0.1.0-rc.6`）→ 内置引擎。首次进入 Harness 后，仍需要按 dsh 界面和[官方文档](https://github.com/deepseek-ai/deepseek-harness)配置模型/API Key。

## 三、日常使用

- 关闭主窗口不会退出鲸坞；它留在托盘/菜单栏中继续运行。
- 默认全局快捷键：macOS 是 `⌘⇧H`，Windows 是 `Ctrl+Shift+H`，用于呼出/隐藏窗口。
- 托盘菜单可显示主窗口、打开设置、重启后端、查看日志、检查更新或彻底退出。
- 要结束鲸坞与它托管的后端，请从托盘选择「退出」，或使用 macOS 的 `⌘Q`。

鲸坞只会清理自己启动的后端进程树：macOS 使用进程组信号，Windows 使用 `taskkill /T`。它不会写入、整理或删除 `~/.dsh` 中的数据。

### v0.3：任务、用量、通知与战报

从托盘或应用菜单打开「任务与用量看板…」。这是鲸坞自己的本地窗口，不会给 Harness 页面注入 preload、DOM 或脚本。

- 看板显示今日/本周 token、顶层/子代理聚合、估算费用、最近匿名任务、预算和事件覆盖状态。它不保存或显示会话标题、正文、cwd、工具数据或原始 frame。
- 用量固定标注“**dsh 已观测用量，非账单**”。若 history 不完整，看板会显示 `history-gap`/覆盖缺口，费用也不伪装成精确总额。
- 完成、失败或等待人工的任务在本地持久成功后才通知；系统 Notification 不可用时依次使用 Dock/托盘/鲸坞 banner。通知文案不包含问题正文或会话 ID。
- 选中匿名任务后，可选深色或浅色主题，把 1080×1440 PNG 复制到剪贴板或保存到本地。主进程会依 taskKey 重读规范快照，不接受 renderer 自报的 token/费用。

终态采用“等待约 350ms → 回读 history 尾部 → 持久本地 ledger → 通知”。这是尽力保证，不是 exactly-once：进程强杀、断电或上游尚未落盘时，仍有约 200–400ms 的 hard-crash 窗口。

## 四、设置窗口

从托盘选择「设置…」。macOS 可按 `⌘,`，Windows 也可从「文件 → 设置…」打开。窗口分为「通用」「后端」「帮助」三个标签。

### 通用

**开机自动启动鲸坞**：保存后立即向系统注册或移除登录项。关闭就是当场移除，不会故意留残余。

- Windows 便携版使用当前 exe 路径，并会在下次启动时对账路径；
- macOS 未签名构建可能被系统拒绝。设置页会显示真实结果，并提示到「系统设置 → 通用 → 登录项」手动添加，不会假装成功。

**启动时最小化到托盘**：下次启动开始生效，而且对每次启动都生效，不只开机自启。正常启动时不显示启动页和主窗口，后端仍会启动，可从托盘唤出；若后端启动失败，错误页仍会弹出。

**全局快捷键**：保存时先试注册新组合键。若组合键被其他程序占用，鲸坞会恢复旧快捷键并明确报错。

**自动检查新版本**：默认开启。关闭后，自动与手动检查都不会发出网络请求；重新勾选后可点击「立即检查更新」。

### v0.3 的任务与预算设置

- **任务完成通知**：可整体关闭，关闭不影响本地事件去重和已观测用量。
- **每日 token 预算**：开启后填写 `1`–`1,000,000,000` 的整数；`0` 不是“立即暂停”，而是无效值。
- **输入/缓存命中/输出单价**：都是“每百万 token”的本地估算价，默认为 deepseek-v4-flash 在 2026-08-15 核验的 `¥1 / ¥0.02 / ¥2`；运行时不联网拉取价格。

超限时先持久当日 latch，再仅停止鲸坞本次自己拉起且 generation/进程归属仍匹配的 managed backend。如果是你在终端启动的外部 dsh，鲸坞只显示“外部服务仍在运行/未自动停止”，绝不 stop。「今日继续运行」会先持久恢复选择，再显式重启 managed backend；自动启动、恢复和重连不能绕过当日 latch。

### 后端

这些字段保存后会提示「重启后端生效」，可直接点一键重启：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 端口 | `3080` | 可填 `1024`–`65535` |
| 工作目录 | 用户主目录 | 可用系统目录选择器 |
| 后端版本 | `0.1.0-rc.6` | 控制 npx 回退；`latest` 会跟随上游 rc 漂移，且与包内版本不一致时不能用内置引擎 |
| 优先使用内置引擎 | 关闭 | 开启后，内置引擎排到 PATH 探测之前 |
| 自定义启动命令 | 留空 | 高级项，一般不用填；优先级最高 |

「优先使用内置引擎」适合没有 Node 的电脑、本机 Node 环境混乱，或希望演示环境固定的人。它不会改变默认版本锁，仍使用 `0.1.0-rc.6`；如果把后端版本改成 `latest` 或其他与包内 manifest 不一致的版本，鲸坞会拒绝误用这份内置 runtime。

### 帮助

本版帮助页提供版本/架构、操作手册、日志目录和常见问题入口。完整帮助中心留待后续版本。

## 五、更新机制与隐私

### 更新检查不是遥测

开启更新检查时，鲸坞只向固定的 GitHub API 地址发 GET：

```text
https://api.github.com/repos/sgd-shine/whaledock/releases/latest
```

请求只带 GitHub API 所需的 `Accept` 和固定应用 `User-Agent`，不带账号、设备号、安装 ID、设置内容或其他用户标识。GitHub 仍会看到普通网络连接必需的信息（例如来源 IP），但鲸坞不会额外收集或上传身份数据。

`checkUpdates` 是总开关。开启时会在启动约 15 秒后检查一次、常驻期间每 24 小时检查一次，也允许手动检查；关闭后这三种触发都不会请求 GitHub。

### macOS

发现新版后可选「去下载」「跳过此版本」「稍后」。当前未签名阶段只打开 Releases 页面，不自动替换应用。

### Windows 安装版

发现新版后：

1. 用户确认下载；
2. 鲸坞把 Setup 和 `SHA256SUMS-win.txt` 下载到临时目录；
3. SHA-256 校验通过后才显示「重启并更新」；
4. 用户再次确认后，鲸坞退出并用静默参数启动安装器。

校验失败会删除临时下载并提示改走手动下载页。由于当前没有代码签名，这套链路的安全锚是 HTTPS、GitHub 仓库账号安全和 Release 校验和；仓库所有者必须开启 GitHub 2FA。

### Windows 便携版

运行中的单文件 exe 不能安全地原地覆盖，因此便携版与 macOS 一样只提醒并打开下载页。想省心更新，优先用 Setup 安装版。

预发布版（例如 `v0.2.0-beta`）不会出现在 GitHub 的 `releases/latest`，所以不会打扰正式版用户。

## 六、Windows 专项排查

### 首启没有进入 Harness

Windows 上的 dsh、安装器与更新链目前没有真机结论。遇到问题先在启动页点「复制日志」并提交 issue，不要先猜路径或大改配置。重点记录：

- 用的是系统 dsh、npx 还是内置引擎；
- 报错前最后 30 行日志；
- Windows 版本，以及是否安装过 Node；
- 托盘是否出现彩色鲸鱼图标；
- 退出后任务管理器是否还有 node/dsh 子进程。

把这些信息交给 Claude/Codex 定位。Windows 的 PATH/PATHEXT、`.cmd/.bat` 启动与进程树清理已经做了兼容层，但尚未真机证明；失败时优先用日志确认是哪一层，不做猜测性重构。

### 开机自启失效

安装版先在设置中关闭再开启。便携版确认 exe 没被删除；如果移动过，先手动启动一次让鲸坞对账新路径。仍失败时检查 Windows「启动应用」中 WhaleDock 是否被系统禁用。

### 退出后仍有进程

务必从托盘「退出」，而不是只关窗口。若任务管理器仍有相关进程，保留日志与进程名/父子关系截图，这是验收缺陷，不要手工删除用户的 dsh 数据目录。

## 七、macOS 专项排查

日志与配置默认位于：

```text
~/Library/Application Support/WhaleDock/logs/
~/Library/Application Support/WhaleDock/config.json
```

旧版 Harness Desktop 的配置会在首次启动时迁移。未签名版若无法写入系统登录项，以设置页真实回报为准；不要把「保存成功」当作系统已接受，需去系统设置复核。

Intel Mac 请下载 x64 包。Apple Silicon 日常使用下载 arm64 包；x64 包只用于 Rosetta 抽查或兼容性排障。

## 八、源码运行与打包

源码开发需要 Node.js 22.12+：

```bash
git clone https://github.com/sgd-shine/whaledock.git
cd whaledock
npm install
npm run smoke
npm start
```

打包命令：

```bash
npm run dist:mac:arm64   # arm64 dmg + zip
npm run dist:mac:x64     # x64 dmg + zip
npm run dist:win         # x64 NSIS Setup + portable
```

每个构建命令都会先为目标平台/架构生成 `vendor/dsh-runtime/`，然后把它作为额外资源写入包。该目录不提交 Git；不要把在 macOS 生成的 runtime 直接放进 Windows 包，也不要在不同架构构建之间复用未核对的 runtime。

macOS 打包产生的 dmg/zip 会继续留在 `release/`；electron-builder 展开的 `WhaleDock.app` 只是构建中间物，会自动注销并移到隐藏的 `release/.app-archives.noindex/`，后缀改为 `.app-bundle`。每个架构只保留一个滚动裸包归档，历史版本由带版本号的 dmg/zip 留档；它们不会被系统 App/Spotlight 当成多个已安装版本。升级安装时始终用新版覆盖 `/Applications/WhaleDock.app`，不要并列创建 `WhaleDock 2.app` 或版本号命名副本。构建收尾可执行：

```bash
node scripts/macos-build-visibility.js --out-dir=release --check
mdfind 'kMDItemCFBundleIdentifier == "com.sgd.whaledock"'
```

第一条必须显示 `staging=0`；第二条在无挂载 dmg 的收尾状态只应返回 `/Applications/WhaleDock.app`。

`npm run smoke` 是纯 Node 跨平台冒烟测试，不需要图形界面。当前 v0.3 源码态本地回读为 **119 PASS / ALL PASS**：基础 34、config 13、events 24、backend adapter 20、main 24，另有 4 项 wrapper 确认子套件真实纳入统一 smoke。该本地结果与正式 tag 提交的 [main CI 31893926627](https://github.com/sgd-shine/whaledock/actions/runs/31893926627) 三平台全绿是分开证据。

## 九、正式发布与 GitHub Actions

发布工作流按 tag 构建：macOS job 产 arm64/x64 的 dmg/zip 和 `SHA256SUMS-mac.txt`；Windows job 产 Setup/portable 和 `SHA256SUMS-win.txt`。两个构建 job 会先把产物保留为 Actions artifacts，供精确哈希、inventory 与合规回读。

内置 dsh 属于第三方运行时闭包再分发。公开 Release 默认被审批门拦住：必须先完成 G1 所需的许可清单、完整许可文本、对应源码/替换重链说明、平台 inventory 与成品回读。2026-08-15 的预授权允许 Codex 在无 S1 且这些材料闭环后，把仓库变量 `WHALEDOCK_BUNDLED_COMPLIANCE_APPROVAL` 临时设为该次 workflow 的精确 `release:<tag>:sha256:<digest>`，只重跑失败的 publish job；Release 与资产确认后立即删除。未闭环时 workflow 失败是预期结果，不得绕过或复用旧值。

v0.3.0 正式注解 tag 对象 `8af8f86a527a105c9dbe5a204e75afcdd9dba409` 指向提交 `fe2d4def7bb7ef1d9339b71b1e28236fd9e1eabf`。首次 main CI [31893823255](https://github.com/sgd-shine/whaledock/actions/runs/31893823255) 仅 Windows 因 LF/CRLF 静态测试失败，第一轮修复后 [31893926627](https://github.com/sgd-shine/whaledock/actions/runs/31893926627) 三平台全绿。[Release run 31894036652](https://github.com/sgd-shine/whaledock/actions/runs/31894036652) 的 attempt 2 publish job [95035294975](https://github.com/sgd-shine/whaledock/actions/runs/31894036652/job/95035294975) 成功；精确批准值 `release:v0.3.0:sha256:8a7e9f14cfdaee35eb5baaa016547ec0a5d32d110876436185f186a3257407ad` 已在发布回读后删除，仓库变量回读不存在。
