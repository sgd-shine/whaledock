# 鲸坞 WhaleDock 开发方案（原名 Harness Desktop）

版本 v1.0 · 2026-08-14 · 作者：Claude（方案与首版实现）· 执行者：Codex（真机落地）· 项目所有者：SGD

---

## 1. 背景与目标

DeepSeek 于 2026 年 8 月 12/13 日开源了 **Harness**（仓库 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)，MIT 协议，基于 Cordis 插件架构的 AI Agent 运行框架，开发者预览版）。它的"网页版"并非在线服务，而是本地服务：用户在终端执行 `npx @deepseek-ai/dsh web`（npm 包 `@deepseek-ai/dsh`，bin 名 `dsh`，编写本方案时版本为 0.1.0-rc.6），然后在浏览器访问 `http://127.0.0.1:3080`。官方没有桌面客户端。

本项目 **鲸坞 WhaleDock**（原名 Harness Desktop）是一个非官方 macOS 桌面客户端，把"开终端敲命令 + 浏览器找标签页"两步合并为双击一个 App：自动拉起本地 `dsh` 服务，用原生窗口承载其 Web UI，并提供托盘、全局快捷键等桌面能力。

项目的三个交付目标，按优先级：一，项目所有者能在自己的 Apple Silicon Mac 上日常使用；二，效果适合录制演示视频（启动过程有可视化日志、有"哇点"）；三，以 MIT 协议发布到 GitHub，附带可下载的 .dmg 安装包和自动构建流水线。

## 2. 需求范围

**v0.1 范围内**：自动托管后端（含"检测到已运行服务则直接接入"）；启动页实时显示后端日志、失败时可重试/复制日志；原生主窗口（记忆位置尺寸、⌘R 刷新、缩放、全屏、外链跳系统浏览器）；菜单栏托盘常驻（关窗不退出）；全局快捷键呼出/隐藏（默认 ⌘⇧H）；中文菜单栏（编辑/视图/后端/窗口/帮助）；JSON 配置文件；文件日志；dmg 打包；GitHub Actions tag 触发自动发布。

**v0.1 明确不做**：Windows/Linux 支持、Apple 签名公证、自动更新、自研聊天 UI、多实例多端口管理、登录态或 API Key 管理（Key 在 Harness 自己的界面里配）。

## 3. 技术选型与理由

**Electron 43 + electron-builder 26，主进程纯 JavaScript（CommonJS），零运行时依赖。** 备选方案对比：Tauri 体积更小但要求 Rust + Xcode 工具链，项目所有者不写代码，环境成本不可接受；Pake 一键打包最快但无法托管后端进程，开源含金量低；用 Harness 的 headless/JSON-RPC 接口自研 UI 工作量以周计，列为远期方向。Electron 的决定性优势：目标用户（Harness 使用者）机器上必然有 Node.js，除此之外零环境要求；且 Harness 本身是 Node 生态，未来深度集成天然契合。

不引入前端框架和打包器：主进程 6 个 JS 文件、一个自包含的 splash.html，复杂度不需要。**`lib/` 三个模块（backend/config/log）刻意不依赖 Electron**，纯 Node 可测——这是本项目最重要的工程约束，见第 8 节。

## 4. 系统架构

进程模型三层：**Electron 主进程**（生命周期、窗口、托盘、快捷键、菜单）→ **dsh 子进程组**（`detached: true` 独立进程组启动，退出时对整组发 SIGTERM，4 秒宽限后 SIGKILL，确保 npx → dsh → 其内部子进程全部清干净）→ **渲染层**（启动页 splash.html 经 preload 桥接收状态与日志；主窗口直接 `loadURL` 本地服务，无 preload、无 nodeIntegration）。

启动时序：`app ready` → 读配置初始化日志 → 显示启动页 → TCP 探测 `127.0.0.1:{port}`。**端口已有服务 → 直接接入**；真正的外部服务按 attach 模式处理，退出时不杀，若端口由 WhaleDock 仍持有的存活子进程打开，则保留 spawned ownership 并在退出时清理。无服务且 `autoStartBackend=true` → 解析启动命令并 spawn → 轮询等端口就绪（超时 5 分钟，因首次 npx 需下载组件）→ 创建主窗口 loadURL → `ready-to-show` 后关启动页。加载失败自动重试 6 次（后端刚就绪时 HTTP 层可能还没稳）。

启动命令解析优先级：配置 `command` 字段（shell 方式执行）→ PATH 中的 `dsh`（执行 `dsh web`）→ PATH 中的 `npx`（执行 `npx -y @deepseek-ai/dsh@<dshVersion> web`，默认锁定 0.1.0-rc.6）→ 都没有则报"找不到 Node.js"并给出指引。

**PATH 发现机制（关键设计）**：macOS 从 Finder/Dock 启动的 GUI 应用只继承 `/usr/bin:/bin:/usr/sbin:/sbin`，拿不到终端里的 PATH，Homebrew/nvm 装的 node 全部不可见。`lib/backend.js` 的 `fullPath()` 会合并：登录 shell 输出的 PATH（`$SHELL -ilc` / `-lc`，带 4 秒超时防卡）＋ 进程自身 PATH ＋ 常见安装目录（`/opt/homebrew/bin`、`/usr/local/bin`、`~/.nvm/versions/node/*/bin` 按版本号降序、`~/.volta/bin`、`~/.local/bin`）。spawn 子进程时也注入这份完整 PATH。

生命周期约定：关窗口 = 隐藏（托盘常驻）；Cmd+Q / 托盘退出 = 真退出，`will-quit` 中先异步停后端再放行退出；attach 模式退出时不动用户自己启动的服务；后端意外退出且主窗口可见时弹对话框提供一键重启，窗口隐藏时按 1/2/4 秒退避自动重启三次，全部失败后发系统通知。

## 5. 工程结构

| 路径 | 职责 |
| --- | --- |
| `main.js` | 主进程全部逻辑：启动编排、窗口、托盘、菜单、快捷键、IPC、生命周期 |
| `lib/backend.js` | 后端进程管理：PATH 发现、which、端口探测、命令解析、spawn/stop（**不依赖 Electron**） |
| `lib/config.js` | 配置读写，文件在 `userData/config.json`（**不依赖 Electron**，注入目录初始化） |
| `lib/log.js` | 文件日志 + 内存环形缓冲（**不依赖 Electron**） |
| `preload.js` | 仅启动页用的 contextBridge（onStatus / onLog / action） |
| `splash.html` | 自包含启动页：状态、进度条、实时日志、错误态按钮（重试/复制日志/打开日志/退出） |
| `test/fake-backend.js` | 假后端：最小 HTTP 服务，供自测 |
| `test/smoke.js` | 纯 Node 冒烟测试，14 项断言，`npm run smoke` |
| `assets/` | 512 图标、托盘模板图（16/32，template image） |
| `build/icon.png` | 1024 应用图标，electron-builder 自动转 icns |
| `.github/workflows/release.yml` | tag `v*` 触发：macos runner → npm ci → smoke → 构建 → 发 Release |
| `.github/workflows/ci.yml` | push / PR 到 `main`：ubuntu runner → npm ci → smoke |
| `docs/` | 本方案、给人类的操作手册 |

配置字段（`config.json`）：`port`（默认 3080）、`autoStartBackend`（默认 true）、`command`（自定义启动命令，默认 null 自动探测）、`dshVersion`（npx 回退版本，默认 `0.1.0-rc.6`，可设 `latest`）、`workdir`（后端工作目录，默认用户主目录）、`hotkey`（默认 `CommandOrControl+Shift+H`）、`bounds`（窗口位置，自动记录）。

## 6. 关键实现规格

主窗口：1280×820 起步，最小 960×620，深色背景 `#0b0f19` 防白闪；`setWindowOpenHandler` 同源允许、外链 `shell.openExternal`；`will-navigate` 同规则。菜单：编辑菜单必须有完整 roles（否则 macOS 上 Web UI 里无法复制粘贴）；视图菜单含刷新/缩放/开发者工具/全屏；「后端」菜单：重启后端、在浏览器打开、打开日志文件夹、打开配置文件。托盘：template image（黑+透明，系统自动适配深浅色），菜单与「后端」菜单同源。单实例锁；Dock 点击 activate 唤起。

日志：`userData/logs/whaledock.log`，超 5MB 轮转一份 `.old`；dsh 的 stdout/stderr 按行进日志并实时推给启动页。

隐藏自测模式：环境变量 `HARNESS_SMOKE=1` 时，主窗口 `ready-to-show` 后 1.2 秒打印 `SMOKE_OK` 退出 0；任何 error 态打印 `SMOKE_FAIL` 退出 1；90 秒兜底 `SMOKE_TIMEOUT` 退出 2。供 CI 与容器环境做无头验证。

## 10. 风险与对策

**dsh 是 rc 版本，行为可能变**：npx 回退默认锁定已验证的 0.1.0-rc.6，只有用户显式设置 `dshVersion: "latest"` 才跟随上游；所有对 dsh 的假设（端口 3080、`web` 子命令、无交互初始化）都收敛在 `lib/backend.js` 和配置文件里。**首启极慢**：npx 下载组件可达数分钟，已用 5 分钟超时 + 启动页进度提示缓解；全局安装的 dsh 会绕过 npx 版本锁，需由用户自行维护。**端口冲突**：3080 被非 Harness 服务占用时 App 会误接入——v0.1 接受此风险（探测到端口就视为 Harness），v0.2 可加 HTTP 特征校验。**未签名分发**：Gatekeeper 拦截为预期行为，文档已交代；Electron 43 的 macOS Notification 也要求有效代码签名，当前监听发送失败并回退错误对话框，签名公证列入后续版本（需 Apple Developer 账号）。
