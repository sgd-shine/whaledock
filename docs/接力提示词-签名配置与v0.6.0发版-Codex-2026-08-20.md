【本轮最重要的安全铁律】
- Apple 开发者网页、App Store Connect、钥匙串的导出对话框：全部 SGD 本人操作，你只报「下一步点哪里」。
- .p12 / .p8 / 证书密码是身份凭证：永不进仓库、永不出现在你的命令输出或对话里。
  给 SGD 的 base64 命令一律带 `| pbcopy`（内容只进剪贴板）；你自己绝不 cat / base64 / 读取这两个文件。
- 你可以自己跑的只读验证命令仅限：`security find-identity -v -p codesigning`（只列证书名）、
  `gh secret list`（只列 secret 名字，看不到值）。

【阶段一：配签名资料（约 15 分钟，逐步带他走，每步确认完成再进下一步）】

第 1 步 · 生成证书请求（他的 Mac 上，必须这台机器）
  让他打开「钥匙串访问」→ 顶部菜单「钥匙串访问」→「证书助理」→「从证书颁发机构请求证书…」：
  用户电子邮件 = 他的 Apple ID 邮箱；常用名称 = 他的名字；CA 电子邮件留空；
  勾「存储到磁盘」→ 存到桌面（得到 .certSigningRequest）。

第 2 步 · 网页申请证书
  让他打开 developer.apple.com/account → Certificates → ＋ →
  类型选 Developer ID Application（⚠ 不是 Mac App Distribution、不是 Developer ID Installer；
  Profile Type 用默认的 G2 Sub-CA）→ 上传第 1 步的文件 → Continue → Download 得到 .cer →
  双击装入钥匙串。

第 3 步 · 验证证书落位（你来跑）
  `security find-identity -v -p codesigning`
  应出现一行 `Developer ID Application: 名字 (十位TEAMID)`。把引号内整串记下来（第 6 步要用）。
  没出现 → 多半是私钥不在这台机器（CSR 不是本机生成的），回第 1 步重来。

第 4 步 · 导出 .p12（他做）
  钥匙串访问 → 左侧「登录」→ 分类「我的证书」→ 右键那条 Developer ID Application 证书 →
  「导出…」→ 格式「个人信息交换 (.p12)」→ 存到桌面 → 设一个密码并记住。

第 5 步 · 公证密钥（他做）
  让他打开 appstoreconnect.apple.com →「用户和访问」→「集成」→ App Store Connect API →
  「团队密钥」（第一次可能要先点「申请访问」同意条款）→ ＋ 生成密钥：名称随意，
  访问权限选 Developer → 生成 → 下载 AuthKey_XXXXXXXX.p8（⚠ 只能下载这一次，提醒他存好）。
  让他把 Key ID 和页面上方的 Issuer ID 念给你（这两串不是机密，可以进对话）。

第 6 步 · 填六个 secrets（他在浏览器粘贴，你逐个报名字和取值方式）
  打开 github.com/sgd-shine/whaledock → Settings → Secrets and variables → Actions，
  逐个 New repository secret：
  1. MACOS_SIGN_CERTIFICATE —— 让他在自己的终端跑
     `base64 -i ~/Desktop/<p12文件名>.p12 | pbcopy`，然后到网页直接粘贴
  2. MACOS_SIGN_CERTIFICATE_PASSWORD —— 第 4 步设的密码（他自己填网页，不要发给你）
  3. MACOS_SIGN_IDENTITY —— 第 3 步记下的整串
  4. MACOS_NOTARY_KEY —— `base64 -i <AuthKey_XXXXXXXX.p8 的路径> | pbcopy` 后网页粘贴
  5. MACOS_NOTARY_KEY_ID —— 第 5 步的 Key ID
  6. MACOS_NOTARY_ISSUER_ID —— 第 5 步的 Issuer ID

第 7 步 · 验证（你来跑）
  `gh secret list` 必须列出以上六个名字，结果记入汇报。缺哪个补哪个。

第 8 步 · 收尾清理（提醒他做）
  桌面的 .p12 与 .p8 移进安全位置（密码管理器附件或加密盘），.certSigningRequest 可删。
  钥匙串里保留证书原件，将来换机器再导出即可。
