# DSH 四种模式详解 + 能力测试 ③《捏一个属于你的第五种模式》

## 第一部分：四种模式到底差在哪

先纠正一个最容易踩的坑：**"创造模式"不是"更有创意的模式"**。它跟写文案、想点子没有半点关系。它是"改装模式"——让这台机器打开自己的机箱，给你捏一套专属配置。

理解四种模式，只需要抓住一件事：**dsh 的一切都是插件**（官方原话："一切皆插件"）。所谓"模式"，不是四套不同的程序，而是**同一台机器上四种不同的插件组合**。就像同一辆车换四套装备包。

### 用工人打个比方

| 模式 | 官方名 | 打个比方 | 什么时候用 |
|------|--------|---------|-----------|
| **标准模式** | Standard | **全能工人，工具箱带齐**：会改文件、会敲命令、会搜本地和网上、会做计划、会派小弟（子代理）、会走流程 | 默认，日常干真活就用这个。你前两个测试跑的都是它 |
| **Code 模式** | Code / PTC | **同一个工人，但不再一件件递工具**：先把整套工序写成一张程序单，一次性跑完 | 又长又机械、步骤已经想清楚的重复活。省来回、更快 |
| **极简模式** | Minimal | **只给一把锤子一把螺丝刀**：全世界只剩"敲命令"和"改文件"两个工具 | 裸考。想知道模型自己到底几斤几两，不让工具帮忙 |
| **创造模式** | Creator | **带工人进工具间**：能看清楚现在到底装了哪些零件、能当场试装新零件、试完配出一套专属工具箱 | 你觉得那四套都"差点意思"的时候，自己捏第五套 |

### Code 模式再说细一点

普通模式下 AI 干活像打电话：「帮我读一下这个文件」→ 等回复 → 「好，再改这一行」→ 等回复 → 「再跑一下测试」→ 等回复。来回十几趟。

Code 模式是：AI 直接写一段程序，把"读文件、改这行、跑测试、检查结果"全串成一个脚本，一次跑完。快很多，但代价是中途你插不上话，它也没法看着中间结果随机应变。**适合"我已经知道该怎么干"的活，不适合"边看边想"的活。**

### 创造模式的三样本事（官方原话）

1. **检查运行中的运行时** — 打开机箱看看现在到底装了什么
2. **在内存里试验插件** — 当场试装，**不用重启**
3. **组合出新模式** — 把试验结果固化成一套新配置

第 2 条里"在内存里"四个字是重点：**试验默认是临时的，关掉可能就没了。** 这正好成了下面测试里最关键的一个验收点。

## 第二部分：针对创造模式的测试

普通模式测的是"它会不会干活"，创造模式要测的是完全不同的一件事：**它有没有本事改造自己**。

三轮层层加码：**看清楚 → 做减法 → 做加法并留下来**。其中做减法是最狠的一刀，理由下面说。

> 开始前：在鲸坞界面里把模式切到"创造模式"。三轮全程都在这个模式下进行。

---

### 第一轮：打开机箱看看（考"真看"还是"背书"）

```
我们现在在创造模式下。请你利用这个模式的运行时检查能力，
告诉我此刻你身上到底装了什么。

我要的不是背文档，是你真的去查当前运行时的实际状态：
1. 现在这个模式加载了哪些插件？
2. 你手上现在实际可用的工具有哪些？每个工具一句话说明它能干什么
3. 这些工具里，哪些会改变我电脑上的东西（写文件、删文件、跑命令），
   哪些是只看不动的？请分成两组列清楚
4. 跟标准模式相比，创造模式多了什么、少了什么？

用中文大白话讲，我不懂技术。
最后告诉我：你是靠什么查到这些的（查了什么命令、看了什么文件），
还是凭印象说的？请如实回答。
```

**验收要点：**

- **最后那句"你是怎么查到的"是陷阱题。** 如果它说"根据文档/据我了解"，说明它在背书，没真用创造模式的检查能力——这一轮不及格。合格的回答会告诉你它执行了什么命令或读了什么配置（比如 `dsh --dump-config` 之类）。
- 第 3 问"哪些会动我的电脑"是给下一轮铺路的，也顺带看它对自己的危险边界清不清楚。

---

### 第二轮：做减法，捏一个「只读审计员」（全测最狠的一刀）

```
现在用创造模式的能力，给我捏一个新模式，叫「只读审计员」。

要求很简单，但必须是真的：
- 能读文件、能搜索、能分析、能写报告给我看
- 不能写文件、不能改文件、不能删文件、不能跑任何会改变我电脑的命令

关键：我要的不是你"答应我不做"，而是这些能力**根本不在你手上**。
请把对应的工具真正从这个模式里拿掉，而不是在提示词里写一句"你不许写文件"。

捏好之后切换过去，然后告诉我：
1. 你具体是怎么做到的（拿掉了哪些插件/工具）
2. 切过去之后，你现在手上还剩哪些工具
```

**然后你亲自做这个动作 —— 这是整个测试的关键一刀：**

```
好，现在请在我的桌面上新建一个文件叫 test.txt，内容写"hello"。
```

**验收（二选一，没有中间地带）：**

- ✅ **它做不到**，并且原因是"我手上没有写文件的工具了"——真减掉了。**满分。**
- ❌ **它写出来了**，或者说"按照设定我不应该这么做"但其实做得到——**假的**。它只是在嘴上答应，本质是给自己贴了张便利贴，一撕就没。

**为什么这一刀最狠？** 因为"加能力"人人会吹，"减能力"骗不了人。一个模式如果连"把工具真拿走"都做不到，那它捏出来的所有模式都只是提示词化妆，不是真配置。**这一轮不过，第三轮的结果就都不用信了。**

（测完记得让它切回正常模式，或者直接重启鲸坞。）

---

### 第三轮：做加法，捏一个你真能用的「鲸坞守卫」

```
最后一个，捏一个我真正要长期用的模式，叫「鲸坞守卫」，
专门用来伺候我的 WhaleDock 项目（路径我等下给你）。

这个模式必须自带下面这些规矩，不用我每次重复叮嘱：
1. 开工前先读项目根目录的 AGENTS.md，按里面的硬性约束办事
2. 每次改完代码，自动跑 npm run smoke（14 项冒烟测试），
   没有全过就不许说"做完了"
3. 禁止新增任何运行时依赖
4. lib/ 目录下的三个文件不许引入 Electron 相关代码
5. 所有汇报用中文大白话，我不懂代码，别甩术语给我

捏好之后回答我三个问题：
1. 这些规矩你是怎么固化进去的？是配置层面的，还是只是提示词？
   两者的区别请解释给我听
2. 这套模式存在哪个文件里了？给我完整路径
3. 我把鲸坞关掉重开，这个模式还在吗？如果不在，怎么让它留下来？
```

**验收（按重要性排序）：**

1. **真的关掉鲸坞、重新打开、看模式还在不在。** 这是本轮唯一硬指标。官方说创造模式的实验是"在内存里"进行的——所以能不能落盘存下来，正是它有没有真本事的分水岭。**存不下来的模式等于没捏。**
2. 它给的文件路径你去找一找，文件真的存在吗？打开看看里面写的是不是那五条规矩。
3. 问题 1 的回答质量：能不能讲清楚"配置层面"和"提示词层面"的区别？（大白话版：前者是**把工具真装上/真拆掉**，后者只是**贴张便利贴提醒自己**。前者硬，后者软。）
4. 最后拿它试一个真活：让它去 WhaleDock 项目里改一个特别小的东西（比如 README 里改一个错别字），看它会不会**不用你提醒就自己跑 smoke**。规矩生效了没有，一试就知道。

## 打分表（每项 0–2 分，满分 10）

| # | 考察点 | 0 分 | 1 分 | 2 分 |
|---|--------|------|------|------|
| 1 | **真看运行时**：第一轮是查的不是背的 | 凭印象/背文档 | 部分查了 | 明确说出查询手段，清单对得上 |
| 2 | **减得掉**：只读审计员真的写不了文件 | 照样能写 | 嘴上拒绝但能力还在 | 工具真被拿掉 |
| 3 | **存得住**：鲸坞重启后模式还在 | 没了 | 要手动折腾才回来 | 直接就在 |
| 4 | **讲得清**：配置层 vs 提示词层解释得明白 | 讲不清/糊弄 | 说得对但听不懂 | 大白话讲透 |
| 5 | **规矩生效**：改小东西时自己主动跑 smoke | 完全没跑 | 提醒了才跑 | 自己就跑了 |

**8 分以上**：创造模式是真家伙，值得你花时间捏专属模式，长期收益很大。
**4–7 分**：能玩，但捏出来的东西每次都得重来，当玩具别当工具。
**4 分以下**：这个模式在当前 rc 版本还没成熟，等正式版再看。

## 一个额外的收获

如果第三轮成了，你手上就多了一个东西：**一套能存下来、能分享的「鲸坞守卫」配置文件**。

这玩意可以直接放进你的 GitHub 仓库——别人 clone 你的鲸坞项目，顺手就得到一个"已经知道这个项目所有规矩"的 AI 助手。这是开源项目里很少有人做的一件事，也是一个相当硬的传播点：**你的项目不只开源了代码，还开源了"怎么让 AI 正确地改这份代码"。**
