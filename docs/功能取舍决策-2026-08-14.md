## 一、结论（10 行）

1. **边界已定（SGD 拍板）**：鲸坞保持"Agent 桌面底座"，只吸收服务 Harness 工作流的交互；划词、WPS、持续屏幕共享等系统级全家桶不做，不另立实验项目。
2. 视频真正值得学的是四种交互思想（上下文就地获取、低打扰副窗、系统级反馈、帮助可问），按底座边界**分级吸收**，不照搬形态。
3. 直接进已定版本：设置中心 + **自启/启动最小化微扩（本轮批准）**→ v0.2；**完成通知（本轮批准，消除总纲冲突）**→ v0.3；截图入口 v1（含"屏幕快照求助"场景，即全屏框选）→ v0.4。
4. **侦察批次一已批准执行**：S0 dsh 能力查重 + S1 任务完成事件 + Token 数据源，合并为一次受限侦察，任务书见附录 A——它是 v0.3 看板/通知与 v0.4 图片入口的共同前置。
5. 完成通知、Token 看板、未来宠物状态**共用同一个任务事件层**（S1 的产出），只建一次。
6. RECON-PLAN（只设计、待批次一结论再定）：紧凑副窗、截图自动送入会话、说明书问 AI、通用文件附加（安全复制到工作区模型）、临时会话清理。
7. LATER（附重开条件）：截图标注、截图翻译/解释快捷动作、划词、动作模板系统、完整帮助中心、液态玻璃。
8. NO（附重开条件）：WPS 专项接入、持续屏幕共享、改造成 DeepSeek 官网包装器、多官网聚合。
9. dsh 已有的模型模式/搜索/思考/会话/Agent 能力一律 REUSE，鲸坞最多做入口显性化，绝不重做。
10. 技术边界遵循报告 A/B 路线：新能力放独立原生窗口 + 最小 IPC；涉及会话只走稳定接口；DOM 注入/自动点击不进正式产品；主窗口保持无 preload、无 nodeIntegration。

### 明细补充（仅列需要痛点/用法定义的批准项与 RECON 项）

**F11a 完成通知** — 痛点：切去干别的事，就不知道 AI 干完没有，只能回来盯窗口。用法：任务完成→系统通知（mac 签名后）/托盘徽标+应用内横幅（未签名期）→点击回到对应会话。验收按报告第 13 节：只在正式完成事件触发、同任务只报一次、重启不重报、点击回跳正确、未签名状态如实标注降级。
**F13a 自启/最小化** — 痛点：每天手动开 App；用法：设置页两个开关，`app.setLoginItemSettings`（mac/Win 通用），关闭语义与回退写入 v0.2 方案。
**F05a 自动送入会话** — 依附 v0.4；批准人=待批次一结论后 SGD 再定；无接口时的降级路径（预览→用户确认→复制/落地文件到工作区）本身已够用，自动化只是锦上添花。
**F12 副窗** — 依附版本待定（候选 v0.5+）；前提：S0 证实稳定的"会话选择+消息提交"接口；若只有工作区文件通道，则副窗形态改为"快速指令窗"（写指令文件+通知），另行提案。
**F16/F06b/F10** — 全部依 S0 结论；共同原则：复用 Harness 工作区与插件生态，不建私有数据层。

## 三、战略问题的正式回答

**鲸坞保持"Agent 桌面底座"定位（SGD 2026-08-14 拍板，选项：保持底座/扩成系统级助手/底座+实验分支，选了保持底座+选择性吸收）。** 理由：dsh 是引擎，鲸坞的独特价值是"让引擎在桌面上可用、可见、可控"（启动托管、入口、观测、管控），这条线生态无人做全；系统级助手线（划词/WPS/屏幕共享）与 87★ 视觉插件、官方 App、竞品官网壳三方正面相撞，且每一项都带权限/隐私/跨平台长尾。若未来要扩边界，成本=新的权限模型+双平台辅助功能适配+独立隐私评审，届时应另立项目而非改造鲸坞。

## 四、报告 15 节"12 个问题"的回答

1. **底座还是助手？** 底座（见上），已拍板。
2. **哪些视频能力 dsh 已有？** 模型模式/深度思考/搜索、会话管理、Agent 工具调用、（待 S0 证实的）工作区文件读取——鲸坞只做入口显性化与状态显示。
3. **dsh 有无稳定图片/文件/会话提交接口？** 未知，S0 的第一优先查重项；在拿到证据前，v0.4 方案对"会话交付"只写降级路径。
4. **有无可信任务完成事件？** 未知，S1 目标；"日志安静"明确不算事件。现有代码只有"后端进程退出"级事件。
5. **副窗如何同步同一会话？** 只接受 B 路线（JSON-RPC/插件事件/结构化本地记录）；没有就改形态或不做，不做 DOM 双开。
6. **图片入口怎样服务 Harness 用户？** 场景定义为"把报错截图/设计稿/屏幕现场交给正在干活的 Agent 当上下文"，入口默认进当前工作区的会话，不做通用闲聊识图。
7. **入口 v1 怎么拆层、排除什么？** 三入口（快捷键框选/拖图/粘贴）→统一预览确认清理→理解路由（官方视觉→插件→本地 OCR）→交付（稳定接口或人工确认降级）。明确排除：标注、翻译/解释快捷动作、持续共享、跨应用划词。
8. **通用文件附加？** 是，转换为"安全复制到工作区（默认只读、不改源、可清理）"模型，S0/S5 后提案；WPS 专项 NO。
9. **帮助中心与 v0.2 一起设计？** 设置窗信息架构本轮就预留"帮助"标签位（防返工），完整帮助中心 LATER 凭示意提案。
10. **通知/看板/宠物共用事件层？** 是——这是本轮最重要的架构决定：S1 产出一个统一任务事件层（纯 Node 模块，遵守 lib/ 边界），三个消费者（通知、看板、宠物）只建一次。
11. **哪些能力破坏现有约束？** 持续共享与跨应用划词（权限+隐私）、WPS 桥（脆弱依赖）、DOM 注入（隔离边界）、官网聚合（定位）——都已 NO/LATER；现阶段没有一项值得为之破界。
12. **进现有节奏还是实验分支？** 全部进现有版本节奏（依附关系见总表）；不建实验分支（SGD 已选"保持底座"而非"底座+实验项目"）。
