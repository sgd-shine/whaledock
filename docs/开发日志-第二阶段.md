## 2026-08-15 · 批次 11：v0.3 任务事件、用量看板、软预算与战报（已正式发布）

- 保持 dsh `0.1.0-rc.6` 锁定，在纯 Node backend adapter 内实现 loopback-only 的 host.describe/session.list/session.history/events.mux 只读边界。HTTP 只调用三个白名单 RPC，WS 只 downlink；请求/响应/帧/数组/字节/超时/消费者积压都 fail-closed 限界，不把 dsh 原始路径与帧名泄漏到中性层或 UI。
- 新增纯 Node 事件服务：用本地 salt HMAC 会话/任务/请求引用，按 seq 管理乱序缺口、终态矩阵、waiting ledger、chunk/final 用量去重、顶层/子代理归属、日/周时区聚合和费用估算。状态只落在 WhaleDock `userData/events-state.json`，schema 1 以 0600 临时文件+原子 rename 持久；损坏时有界备份并建新基线，未来 schema 保持 fail-closed。不保存 title、消息正文、工具内容、cwd 或原始 frame。
- 主进程按“先开 WS 订阅、后 list/history 补洞”接线。backfill 期间 live 队列按 10,000 条/4 MiB 双上限有界缓冲，普通 live 事件每 200ms 串行批写，断线按 generation 持久并指数退避重连。正常退出会 flush 最后批次、关闭 subscription/adapter/service，但换代/退出中的旧 effect 在每个 await 与迭代边界被抑制。
- 按方案 7.4 修正 live terminal 顺序：先 flush 前序事件，等约 350ms，以中性 `sessionRef+seq` 回读 history 尾部精确确认，再持久 notification ledger 并执行 Electron effect。未确认终态使用 suppressNotifications 静默记录。首次 baseline 只导入 `<= floor` 且不发旧通知；重连时已知会话的 history 不 suppress，可补发断线期间已持久终态。这仍是尽力语义，保留约 200–400ms hard-crash 窗口，不宣称 exactly-once。
- 通知 effect 只在本地持久成功后执行，首选 Electron Notification，不可用/失败时降级到 Dock badge/bounce、托盘待办与鲸坞自有 banner。通知只有匿名任务状态，不包含会话 ID、问题正文或 Harness DOM 定位。
