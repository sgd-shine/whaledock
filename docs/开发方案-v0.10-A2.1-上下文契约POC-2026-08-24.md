# WhaleDock v0.10 A2.1：上下文契约 POC

更新：2026-08-24 · 执行基线 `055e2aab730ebe8e314a34043fd1dfe40beda680`

## 1. 产品目标

用户在鲸坞工作台查看项目，在同一窗口内使用原生 dsh 对话修改项目，不需要复制粘贴，也不需要先把项目永久绑定到某个会话。

取消的是用户手动绑定动作，不是系统内部的精确关系。每次项目感知发送都必须冻结：当前 dsh 会话、主项目、参考项目、工作区身份与上下文版本。

## 2. 本批范围

本轮按 `P0A → P0B` 两个门执行。P0A 交付默认关闭的 contract POC：

1. 纯 Node 上下文状态机；
2. 每会话独立的单调 revision、单调 ACK、turn freeze 与消息级 delivery proof；
3. 不含路径、正文或凭据的最小上下文 envelope；
4. managed / external / 错版 / 未挂桥的诚实资格判定；
5. 假 transport 与故障矩阵测试；
6. 环境变量 `WHALEDOCK_CONTEXT_POC=1` 才允许初始化实验状态。

P0A 不安装插件。P0B 只在 `WHALEDOCK_CONTEXT_POC=1`、鲸坞自行拉起、精确证明为 bundled `0.1.1-rc.2` 时，把固定静态 Host/Client 插件复制到每次启动新建、资产哈希与随机 owner 双重标识的 app-owned 隔离 `DSH_HOME`，并在 `web` 子命令后追加固定 patch；其余路径完整回退原启动命令。

两个阶段都不写用户 `~/.dsh`，不改 dsh DOM / CSS，不给 dsh `WebContentsView` 增加 preload，不新增根运行时依赖，也不把纯 Node fixture 写成真实 dsh 已连通。

## 3. 已确认的上游边界

- 固定版本仍为 `@deepseek-ai/dsh@0.1.1-rc.2`。
- 当前公开 HTTP Host 只有既有会话、历史与 prompt 合约，没有 `context.stage`。
- 浏览器当前选择属于 client 私有状态；主进程读取 `session.list` 不能证明用户正在看的会话。
- `systemPrompt.context()` 会在每次组装时求值；若读取全局选择，同一 turn 中途切项目可能污染后续 step。
- dynamic Cordis browser half 需要人工允许、重启不恢复且调用不自带 session 身份，不能作为零动作生产桥。

因此 POC 只能对鲸坞已经冻结并验证过的 opaque `sessionRef` 建模；真实自由输入自动路由必须由后续正常 static host + client 插件证明。

## 4. 契约

协议名固定为：

```text
whaledock.context-bridge/v1
```

每个 session 独立保存：

```text
desiredRevision
pendingRevision
effectiveRevision
ackedRevision
ackedState
deliveredRevision
openTurn
lastTurn
frozenRevision
turnFenceLost
```

规则：

- 相同规范化 payload 为 noop，不增加 revision；
- idle 时新 revision 可成为 effective；
- 只有 `desiredRevision === effectiveRevision` 且没有 pending 时才允许开始 turn；否则阻止项目感知发送；
- turn 打开时新选择只能 pending，当前 turn 始终读取 frozenRevision；
- turn 结束后只提升最新 pending；
- turn 必须对同一 session 单调递增；每轮开始清除上一轮 delivery，旧轮次回读不得复用；
- stale ACK 忽略，未来 revision、错 bridge instance、错 session 一律 fail-closed；
- 同 revision 的 ACK 只能 `queued → effective` 或 `queued → rejected`，进入 effective/rejected 后不得回退；
- host reason 只接受固定 allowlist，未知错误统一映射为 `host-rejected`；
- 每个 controller 最多保留 64 个 session，重连回放总量同样有界；
- ACK 只证明桥已接收或已生效，不能单独证明模型已经看到；
- delivered 必须来自匹配 revision 的消息/请求回读，不能由定时器或“调用未报错”推断。

上下文只能包含受限元数据：协议、opaque session、workspace/project ID、项目标题、相对锚点、主项目/参考角色和 revision。不得包含绝对路径、文件正文、提示词、凭据或命令输出。

## 5. 项目身份边界

POC 的派生 ID 只保证同一 canonical workspace + 同一安全相对锚点在重启与内容编辑后稳定；标题、内容 hash、工作台 ID 不参与 ID。

移动或重命名后的稳定身份不能由路径派生保证。正式多项目功能放行前必须二选一：

1. 项目文件/manifest 持久 UUID；或
2. app-owned UUID registry，并完成改名、复制、恢复和冲突迁移验证。

在这项选择完成前，UI 不得把路径派生 ID 宣称为跨移动永久身份。

## 6. 降级合同

- `spawnedByUs=false`：`external-unproven`，零桥 RPC、零 profile 修改、不停止或重启外部 dsh；原生 dsh 完整可用。
- managed 但版本证明不是精确 rc.2：`unsupported-version`。
- 未挂插件或 handshake 失败：`bridge-unavailable`。
- turn 中断线会丢失远端冻结栅栏：重连后保持 `turn-fence-lost`，直到该 turn 结束再重放最新 desired。
- context 被关闭或未得到消息级回执：只能显示未连接/未送达，不能显示已同步。
- flag 默认关闭时不创建状态机，也不向既有 `shell:state` 增加 `contextPoc` 字段。

## 7. 分阶段放行门

### P0A｜契约内核

- 两 session 乱序 100 次不串线；
- running 中切项目只进入 pending；同一 turn 的 frozen revision 不变；
- pending 未生效禁止开 turn；turn 编号复用、迟到 delivery 与断线栅栏全部 fail-closed；
- stale/future/wrong-instance/ACK 回退全部按合同处理；
- external/错版/无插件零桥请求且不影响原生 dsh；
- 绝对路径、相对路径与 session 总量的真实边界均有回归测试；
- 所有公开 surface 不含路径、session、prompt、原始错误。

### P0B｜真实 dsh static plugin

- 在隔离的 app-owned profile 中挂 host plugin；
- client half 取得权威 current session，并给 host 带 session + controller + revision；
- handshake 必须声明 `delivery-proof`；真实 host events 必须有有序 cursor，按序回放 ACK/turn/delivery；
- 两页面、两 session、快速 A→B→A、刷新、重启均不串线；
- 同一 turn 多 step 冻结通过；
- 外部 dsh 缺桥时保持普通聊天可用。

P0B 的放行范围只包括 managed bundled rc.2、隔离 app-owned `DSH_HOME`、两个不同 session 与本机 `llm/stream` 请求边界回读。它不证明远端模型收到上下文；同一 raw session 被多个 controller 同时发送时，rc.2 没有 prompt-origin 身份，必须拒绝或降级。隔离 home 的设置、凭据与会话迁移也不在本阶段冒充已解决。

P0B 未通过，不进入完整视觉实现。

### P1｜单主项目双区域

默认一个系统窗口、两个独立 surface；顶部共享上下文栏；预览项目不改变主项目；只显示已被真实回执证明的状态。

### P2｜参考项目与跨项目提案

先只读比较，再做逐项目修改计划、CAS 校验与分项结果。未实现写入强制前，不把“默认不修改”标成硬只读。

### P3｜可分离窗口

大屏可选；默认单窗口。拍摄窗继续独立全屏，并恢复项目、tab、段落、滚动与版本信息。

## 8. 证据边界

- 纯 Node / fixture：只证明契约和故障收口；
- isolated dsh：只证明固定 rc.2 与指定 profile 的真实桥；
- 受控 GUI：只证明布局与操作链；
- SGD 真实会话、物理键盘、13 英寸屏幕、外部 dsh：保持独立人工验收；
- Windows、Intel、签名、公证、Release 均不由本 POC 代替。

### 9.3 P0B 实现结果

- 新增私有静态插件 `@whaledock/context-bridge-poc`，Host 只保存有界 opaque 关系，Client 通过正式 `sessions.list()` 上报当前会话；
- 隔离资产逐文件做常规文件、符号链接、大小与 SHA-256 回读；每次启动都在 WhaleDock `userData/context-poc/v1/runs/` 新建并封闭一个 `digest + owner` 运行目录，只有持有同一 owner 的进程状态才能清理，child 退出、spawn/apply 失败均收口；
- bridge secret 只通过受控子进程环境交给 Host。首次请求同时带 nonce 与 request MAC，Host 验证后才分配 RPC 会话并返回 PoP，双方再派生独立 session token；页面选择另用一枚不同的限域 capability，RPC 绑定精确 child、启动端口、绝对 deadline 与字节上限；
- 页面选择 capability 只放 URL fragment，不进入 HTTP request/Referer；Client 读取后立即用 `history.replaceState` 清除，同时保留 dsh 原有 path/query；
- 菜单刷新与后台恢复重载都不再 reload 已清 fragment 的历史 URL，而是保留同源 path/query、重新签发 fragment 后 `loadURL`；跨源当前页回退本地 Harness 根地址，两次连续刷新回归均重新调用 capability factory，恢复导航失败只写固定脱敏日志；
- event journal 采用有序 cursor，单页 64 条且自动分页追到 Host `throughEventSeq` 后才允许 stage/退役；覆盖 handshake、selection、stage、ACK、turn-start、delivery、turn-end、turn-miss、刷新、重连、A→B→A、双页面租约冲突与过期回收；
- `turn-miss` 按 session 有界保留；新 session 抢在 `selection/resolve(A) → events/read` 窗口发送时，已由本 controller 的 Host journal 验证的 B miss 会先私下保存而不污染 A，下一拍绑定 B 后持续显示未注入；后续首次 ACK 不会掩盖，只有同 session 更高 turn 的 delivery proof 才清除；
- 同一 Host 的 transport 暂停保留 effective/open/frozen/delivery fence，并只重试尚未生效的 idle stage；`turn-end` 可按同 session + turn 幂等重放未确认 effect，待退役集合与 current ref 跨 transport 保留；Host instance 换代时才重建本地契约状态并清除旧代 opaque ref，65 次连续换代回归不累积失效 session；
- staging 与 rename 后二次回读失败都会凭 state-held owner 回收本次 mount；正常 child exit、spawn/apply 失败也收口；
- 相对路径同时拒绝绝对路径、`..`、反斜杠、Windows drive-relative 与 URI-like 输入；
- 外部服务、非 bundled 命令、错版、flag 关闭、资产或握手失败均不挂桥；原生 dsh 保持可启动和可聊天。

### 9.4 真实 isolated dsh 证据

在临时根和随机 loopback 端口完成两组互补验证，均未读取用户凭据、未请求远端模型、未使用用户 `~/.dsh`，结束后子进程退出、端口关闭、临时根删除：

1. `darwin/arm64` 主机上以 Rosetta 拉起 `darwin/x64` runtime，子进程回读 `process.arch=x64`；主页、`__DSH_BOOT__`、最新静态 Client 资源（`200 / 4416 bytes`）与 Host 装载均通过。源码、mount 与真实 served client SHA-256 同为 `a145544342675a53c75ecb59d933bcccc67881e6f74adae66d82e1b758eee223`，聚合 asset digest 为 `4f1baed2d0619dcd9a3135584858cd4fcc5e75aec457b52e7f8ebf9069814a4e`。受控 VM 执行真实 served bundle，确认先 `replaceState('/?native=preserved')` 清 fragment、再 `selection/register`，query 与清理后的 history URL 均无 capability。缺 request proof 拒绝、nonce/request-MAC/Host-PoP handshake 与派生 token RPC 也通过；bridge secret 与页面 selection capability 不同，错误 selection capability 被拒绝。
2. 同一全新随机 profile 使用只存在于临时根的本地 `LlmAdapter`，无远端 provider、无用户凭据，通过官方 API 创建两个 session、选择可路由模型并完成 4 次 accepted prompt；两份 assistant history 均持久可读且用不同响应标记证明不串线。生产 Host 的 A→B→A 三段事件分别为 `1–4`、`5–8`、`9–12`，每段严格为 `ACK → turn-start → delivery → turn-end`；每次接管轮换 opaque ref，旧 ref 被拒，未 stage 的 B 第二轮产生绑定该 session + turn 的 `turn-miss(13)`，delivery boundary 为 `llm-stream-local`。

子进程只收到 11 个白名单环境键，凭据环境键为 0；两次 socket 快照均无非 loopback 出站连接；stdout/stderr 共 32 bytes 且 secret/token 扫描无命中。退出码为 0，端口关闭，当次 run mount、临时根和匹配进程均已清理。

这证明了固定 rc.2 的真实 `session/event → agent-loop llm/stream → delivery` 本机请求边界；不证明任何远端模型收到上下文，也不是 Intel 真机或真实账号验收。

### 9.6 P1 放行结论

P0B 的上下文与 delivery 门已通过，但精确 P1 视觉蓝图暂不放行。rc.2 的公开布局合同只有 `sidebar`、`conversation`、`details` 三个 single slot 和浮层；左栏没有 tab/nav additive slot，`details` 已被原生面板占用，`conversation.view` 也只能在同一时刻显示一个 active view。因此当前正式 API 不能同时实现“左栏顶部工作台 tab + 新中栏工作台 + 右侧原生对话”，注册这些 single slot 会遮蔽原生 UI，注册 root 更被上游明确禁止。

此外，rc.2 的原生 prompt 合同没有在发送前等待 WhaleDock context ACK 的原子门。Host 可以在 turn 开始后记录 `turn-miss`，但不能保证每一次用户从原生输入框发出的消息都先成为 project-aware；使用 pre-step 拒绝则会消耗该次 prompt/产生空 turn，不能冒充顺畅发送。

不破坏原生界面的最小合法降级，是把创作台注册为新的 `conversation.view`，与原生 chat 以页签切换；它不能满足“工作台与对话同屏”，也没有解决上述发送前原子门。若同屏和每轮项目感知都是硬要求，需要上游增加 additive layout/navigation seam 与 pre-send context seam，或另行批准并承担 root/layout fork 的长期兼容成本。未获得这项产品取舍前，不用 DOM/CSS 注入伪造 P1。
