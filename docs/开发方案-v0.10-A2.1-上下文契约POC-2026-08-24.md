# WhaleDock v0.10 A2.1：上下文契约 POC

更新：2026-08-24 · 执行基线 `055e2aab730ebe8e314a34043fd1dfe40beda680`

## 1. 产品目标

用户在鲸坞工作台查看项目，在同一窗口内使用原生 dsh 对话修改项目，不需要复制粘贴，也不需要先把项目永久绑定到某个会话。

取消的是用户手动绑定动作，不是系统内部的精确关系。每次项目感知发送都必须冻结：当前 dsh 会话、主项目、参考项目、工作区身份与上下文版本。

## 2. 本批范围

本批只交付默认关闭的 contract POC：

1. 纯 Node 上下文状态机；
2. 每会话独立的单调 revision、单调 ACK、turn freeze 与消息级 delivery proof；
3. 不含路径、正文或凭据的最小上下文 envelope；
4. managed / external / 错版 / 未挂桥的诚实资格判定；
5. 假 transport 与故障矩阵测试；
6. 环境变量 `WHALEDOCK_CONTEXT_POC=1` 才允许初始化实验状态。

本批不安装插件，不写 `~/.dsh`，不改 dsh DOM / CSS，不给 dsh `WebContentsView` 增加 preload，不新增运行时依赖，不把 fixture 写成真实 dsh 已连通。

## 3. 已确认的上游边界

- 固定版本仍为 `@deepseek-ai/dsh@0.1.1-rc.2`。
- 当前公开 HTTP Host 只有既有会话、历史与 prompt 合约，没有 `context.stage`。
- 浏览器当前选择属于 client 私有状态；主进程读取 `session.list` 不能证明用户正在看的会话。
- `systemPrompt.context()` 会在每次组装时求值；若读取全局选择，同一 turn 中途切项目可能污染后续 step。
- dynamic Cordis browser half 需要人工允许、重启不恢复且调用不自带 session 身份，不能作为零动作生产桥。

因此 POC 只能对鲸坞已经冻结并验证过的 opaque `sessionRef` 建模；真实自由输入自动路由必须由后续正常 static host + client 插件证明。

## 4. 契约

协议名固定为：

```text
whaledock.context-bridge/v1
```

每个 session 独立保存：

```text
desiredRevision
pendingRevision
effectiveRevision
ackedRevision
ackedState
deliveredRevision
openTurn
lastTurn
frozenRevision
turnFenceLost
```

规则：

- 相同规范化 payload 为 noop，不增加 revision；
- idle 时新 revision 可成为 effective；
- 只有 `desiredRevision === effectiveRevision` 且没有 pending 时才允许开始 turn；否则阻止项目感知发送；
- turn 打开时新选择只能 pending，当前 turn 始终读取 frozenRevision；
- turn 结束后只提升最新 pending；
- turn 必须对同一 session 单调递增；每轮开始清除上一轮 delivery，旧轮次回读不得复用；
- stale ACK 忽略，未来 revision、错 bridge instance、错 session 一律 fail-closed；
- 同 revision 的 ACK 只能 `queued → effective` 或 `queued → rejected`，进入 effective/rejected 后不得回退；
- host reason 只接受固定 allowlist，未知错误统一映射为 `host-rejected`；
- 每个 controller 最多保留 64 个 session，重连回放总量同样有界；
- ACK 只证明桥已接收或已生效，不能单独证明模型已经看到；
- delivered 必须来自匹配 revision 的消息/请求回读，不能由定时器或“调用未报错”推断。

上下文只能包含受限元数据：协议、opaque session、workspace/project ID、项目标题、相对锚点、主项目/参考角色和 revision。不得包含绝对路径、文件正文、提示词、凭据或命令输出。

## 5. 项目身份边界

POC 的派生 ID 只保证同一 canonical workspace + 同一安全相对锚点在重启与内容编辑后稳定；标题、内容 hash、工作台 ID 不参与 ID。

移动或重命名后的稳定身份不能由路径派生保证。正式多项目功能放行前必须二选一：

1. 项目文件/manifest 持久 UUID；或
2. app-owned UUID registry，并完成改名、复制、恢复和冲突迁移验证。

在这项选择完成前，UI 不得把路径派生 ID 宣称为跨移动永久身份。

## 6. 降级合同

- `spawnedByUs=false`：`external-unproven`，零桥 RPC、零 profile 修改、不停止或重启外部 dsh；原生 dsh 完整可用。
- managed 但版本证明不是精确 rc.2：`unsupported-version`。
- 未挂插件或 handshake 失败：`bridge-unavailable`。
- turn 中断线会丢失远端冻结栅栏：重连后保持 `turn-fence-lost`，直到该 turn 结束再重放最新 desired。
- context 被关闭或未得到消息级回执：只能显示未连接/未送达，不能显示已同步。
- flag 默认关闭时不创建状态机，也不向既有 `shell:state` 增加 `contextPoc` 字段。

## 7. 分阶段放行门

### P0A｜契约内核

- 两 session 乱序 100 次不串线；
- running 中切项目只进入 pending；同一 turn 的 frozen revision 不变；
- pending 未生效禁止开 turn；turn 编号复用、迟到 delivery 与断线栅栏全部 fail-closed；
- stale/future/wrong-instance/ACK 回退全部按合同处理；
- external/错版/无插件零桥请求且不影响原生 dsh；
- 绝对路径、相对路径与 session 总量的真实边界均有回归测试；
- 所有公开 surface 不含路径、session、prompt、原始错误。

### P0B｜真实 dsh static plugin

- 在隔离的 app-owned profile 中挂 host plugin；
- client half 取得权威 current session，并给 host 带 session + controller + revision；
- handshake 必须声明 `delivery-proof`；真实 host events 必须有有序 cursor，按序回放 ACK/turn/delivery；
- 两页面、两 session、快速 A→B→A、刷新、重启均不串线；
- 同一 turn 多 step 冻结通过；
- 外部 dsh 缺桥时保持普通聊天可用。

P0B 的放行范围只包括 managed bundled rc.2、隔离 app-owned `DSH_HOME`、两个不同 session 与本机 `llm/stream` 请求边界回读。它不证明远端模型收到上下文；同一 raw session 被多个 controller 同时发送时，rc.2 没有 prompt-origin 身份，必须拒绝或降级。隔离 home 的设置、凭据与会话迁移也不在本阶段冒充已解决。

P0B 未通过，不进入完整视觉实现。

### P1｜单主项目双区域

默认一个系统窗口、两个独立 surface；顶部共享上下文栏；预览项目不改变主项目；只显示已被真实回执证明的状态。

### P2｜参考项目与跨项目提案

先只读比较，再做逐项目修改计划、CAS 校验与分项结果。未实现写入强制前，不把“默认不修改”标成硬只读。

### P3｜可分离窗口

大屏可选；默认单窗口。拍摄窗继续独立全屏，并恢复项目、tab、段落、滚动与版本信息。

## 8. 证据边界

- 纯 Node / fixture：只证明契约和故障收口；
- isolated dsh：只证明固定 rc.2 与指定 profile 的真实桥；
- 受控 GUI：只证明布局与操作链；
- SGD 真实会话、物理键盘、13 英寸屏幕、外部 dsh：保持独立人工验收；
- Windows、Intel、签名、公证、Release 均不由本 POC 代替。
