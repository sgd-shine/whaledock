## 0. 开工功课与借鉴边界

参考对象只取**格式惯例与交互思路**，不复制任何代码、素材或商标：

- OpenAI Codex Pet Mode：默认像素宠物按 AI 状态反应、一张图生成一只宠物、社区分享。鲸坞对标的是「一张图就能当宠物」这个门槛，而不是它的实现。
- OpenPets（MIT）：pet manifest + 帧目录 + agent 状态联动的目录约定。我们采用「manifest.json + PNG 帧」这一类通行形状，字段自定义。
- Shimeji 系传统：用户往文件夹丢 PNG 就是一只宠物。这是本版零门槛设计的直接来源。

明确不做：不下载任何第三方宠物包或素材，不引入非 MIT 兼容资源，不执行包内任何代码。内置宠物图由本仓库脚本程序化生成（纯 Node + 内置 zlib 写 PNG），是原创像素画，与 DeepSeek 官方素材无关。

## 1. 问题陈述

### 1.1 桌面宠物

鲸坞已经有任务事件层、通知和看板，但用户感知 AI 状态仍需主动去看窗口。竞品把「状态可视化」做成了桌面宠物这种低成本高传播的形态。

同时，市面上宠物功能普遍有两个门槛：要么只能用官方内置的几只，要么自定义需要准备整套多帧动画。对内容创作和社区分享来说，这两个门槛都太高。

v0.5 要给出的答案是：**往 `userData/pets/<名字>/` 丢一张 PNG，就是一只会动的宠物**。漂浮、摇摆、呼吸缩放、事件弹跳全部由壳统一用 CSS 变换实现，任何一张图都自动「活」起来；愿意做多帧的进阶用户再用逐帧动画覆盖默认表现。

### 1.2 皮肤主题

鲸坞自有界面（启动页、设置、看板、通知条、截图窗、战报卡片）目前是硬编码的品牌深色。用户没有换肤入口，做内容时也没法把界面配色调成自己的视觉风格。

v0.5 提供「主题 = 一个 JSON 文件」的最小体系：放进 `userData/themes/` 即被识别，改 7 个颜色值就是一套皮肤。

作用域必须写死在鲸坞自有界面：**不注入 dsh 的 Web UI**——引擎的脸不动，这既是硬约束 4（主 Harness 窗口无 preload、无 DOM 注入）的直接推论，也避免把上游 UI 变更风险引进来。

## 2. 目标与成功定义

### 2.1 用户目标

- 用任意画图 AI 生成一张 PNG，丢进宠物文件夹，重新扫描后即可选用，无需写任何配置。
- 宠物能反映 AI 当前在干什么：空闲 / 干活中 / 等你拍板 / 完成庆祝 / 出错，五态一眼可辨。
- 宠物不碍事：可拖动、可置顶、可鼠标穿透、右键即可关闭或换宠物；默认关闭，用户主动在设置里开启。
- 换肤只需选一个下拉项，即时生效；想自制主题就复制一份内置 JSON 改颜色。

### 2.2 工程目标

- 宠物包与主题包都是**纯静态资源**：只解析数据字段，绝不 `require`、`eval`、`Function` 或以任何方式执行包内内容。
- 坏文件（JSON 语法错误、字段越界、缺帧、图不存在、路径越界）一律跳过并在日志说明跳过原因，不崩溃、不影响其他包。
- 五态推导是 `lib/events.js` 的纯函数，可 fixture 直测；渲染层只消费结论，不自己解释 dsh 事件。
- 不新增运行时依赖，`lib/` 继续零 Electron。

### 2.3 无遥测条件下的成功指标

不做任何上报。可核验的替代指标：

- `community-pets/` 与 `community-themes/` 收到的 PR 数量（公开可数）。
- issue 中「按指南自制宠物包/主题」的反馈条数。
- 本地统一 smoke 覆盖：宠物 manifest 解析/回落、主题 token 解析/回落、五态推导三组纯函数全部有 fixture。

## 3. 非目标

- 不做宠物包在线商店、云同步或任何联网下载。社区分享一律走 GitHub PR + 用户手动放文件夹。
- 不做宠物与用户的对话、喂养、成长数值等玩法；本版宠物只是状态可视化 + 一点趣味动效。
- 不做骨骼动画、Live2D、Spine 等需要运行时库的方案（会破坏零依赖）。
- 不注入、不改写 dsh Web UI 的任何样式或 DOM。
- 不做主题的字体、圆角、间距等排版级 token；本版只做配色 + 深浅基调 + 可选背景图。
- 不做 Windows/Intel 真机验收（延续既有边界）。

## 6. 不可放宽的硬约束

1. `lib/pets.js`、`lib/themes.js` 与 `lib/events.js` 保持纯 Node，严禁 `require('electron')`；窗口、透明度、鼠标穿透、右键菜单只在 `main.js` / preload。
2. 不新增 runtime dependency；devDependencies 仍只有 `electron` 与 `electron-builder`。动画一律 CSS 变换 + 原生 API。
3. **绝不执行宠物包或主题包内的任何代码**：只 `JSON.parse` 数据字段并逐字段白名单校验；不接受 `.js`、`.html`、`.svg`（可含脚本）作为资源；图片只接受 `.png`。这是 S5 级底线。
4. 不联网获取宠物包/主题包；无任何新增外网请求。唯一批准的外网请求仍是受 `checkUpdates` 控制的 GitHub `releases/latest`。
5. 主题只作用于鲸坞自有 `BrowserWindow`；主 Harness 窗口继续无 preload、无 CSS 注入、无 DOM 注入。
6. 宠物窗与设置窗共用现有安全样板：`contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`、精确 sender 校验、拒绝导航与 `window.open`、页面 CSP 禁止远程资源。
7. 资源路径限界：只从内置 `assets/pets`、`assets/themes` 与 `userData/pets`、`userData/themes` 读取；解析后 realpath 必须仍在对应根内（复用 v0.4 修好的原生 realpath 身份口径），symlink/junction 越界一律跳过。
8. 不写入、迁移或清理 `~/.dsh`；不读取用户其他目录。
9. 不新增遥测；不记录宠物包作者、文件名以外的用户内容，不把包内文本写进日志正文。
10. 每次代码改动后跑完整 `npm run smoke`，必须 ALL PASS 且不低于 201。

## 7. 总体架构与文件边界

```text
dsh 事件（已有）
      |
      v
 lib/events.js
  - snapshot().activity  ← 新增：未结束 turn 数
  - derivePetState()     ← 新增：五态纯函数（含瞬时态过期）
      |
      v
   main.js 薄执行层
   - 宠物窗生命周期 / 透明 / 置顶 / 穿透 / 右键菜单
   - 主题分发到全部自有窗口
   - 最小 IPC（pet:state / theme:apply）
      |            \
      v             v
 lib/pets.js    lib/themes.js
 - 包发现/校验   - 主题发现/校验
 - 单图默认值    - token 白名单与回落
 - 帧回落 idle   - 深浅基调
      |             |
      v             v
 assets/pets/*  assets/themes/*      userData/pets/*  userData/themes/*
 （内置示例）                          （用户自制，纯静态）

pet.html + preload-pet.js
 - 只接收：图片文件 URL 列表、帧率、状态、动效参数、底色
 - 不接触 fs、不解析 manifest、不发起网络请求
```

边界原则：

- `lib/pets.js` 不知道 Electron、窗口尺寸与 CSS；只产出「这只宠物在这个状态下该播哪些图、多快、锚点在哪」的中性描述。
- `lib/themes.js` 只产出 token 表；具体哪个窗口用哪个 token 由各页面 CSS 变量决定。
- `lib/events.js` 只多出一个纯函数与一个快照字段，不新增 dsh wire 假设。
- `main.js` 负责全部 Electron 行为与文件 URL 拼装，不复制校验逻辑。

## 8. 宠物包格式

### 8.1 目录

```text
userData/pets/<宠物名>/
  manifest.json     ← 可省
  idle.png          ← 单图宠物：任意一张 PNG 即可
  busy-1.png ...    ← 进阶：多帧
```

### 8.2 manifest.json（全部字段可省）

```json
{
  "name": "像素鲸鱼",
  "author": "SGD",
  "license": "MIT",
  "frameRate": 6,
  "size": { "width": 128, "height": 128 },
  "anchor": "bottom-right",
  "states": {
    "idle": ["idle-1.png", "idle-2.png"],
    "busy": ["busy-1.png", "busy-2.png", "busy-3.png"],
    "waiting": ["waiting.png"],
    "celebrate": ["celebrate.png"],
    "error": ["error.png"]
  }
}
```

校验规则（任一不满足即按「跳过该字段并回落」处理，不是报错崩溃）：

- `name`：字符串，控制字符剥离后取前 40 字；缺失时用文件夹名。
- `author` / `license`：可选字符串，各限 80 字，仅用于设置页展示。
- `frameRate`：1–24 的整数，默认 6。
- `size`：宽高各 16–512 的整数，默认 128×128。
- `anchor`：`bottom-right` / `bottom-left` / `top-right` / `top-left` 之一，默认 `bottom-right`。
- `states`：只认五个键；每个值是文件名数组，单个数组最多 24 帧；文件名只接受不含分隔符的 `.png`，必须实际存在于该包目录内且 realpath 不越界。
- 未知字段一律忽略（前向兼容），不报错。

### 8.3 单图宠物（零门槛路径）

包目录内没有 `manifest.json`，或 manifest 未声明任何有效状态时：

1. 按文件名排序取该目录下全部合法 `.png`（上限 24 张）。
2. 只有 1 张 → 五态全部指向它。
3. 多张且文件名带 `idle` / `busy` / `waiting` / `celebrate` / `error` 前缀 → 按前缀分组。
4. 多张但没有可辨识前缀 → 全部作为 `idle` 的逐帧动画，其余四态回落 idle。

无论哪条路径，缺帧的状态一律回落 `idle`；`idle` 也无帧的包判定为无效包，跳过并在日志写明包名与原因。

### 8.4 状态表现由壳统一实现

「活起来」不依赖用户提供多帧。`pet.html` 对当前帧图统一施加：

| 状态 | 壳动效 |
| --- | --- |
| idle | 慢速上下漂浮 + 呼吸缩放（约 3s 周期） |
| busy | 漂浮加快 + 左右小幅摇摆（约 0.8s 周期） |
| waiting | 定点晃动（注意力提示，幅度大频率低） |
| celebrate | 一次弹跳 + 轻微放大，2.5s 后回落 |
| error | 一次横向抖动，2.5s 后回落 |

多帧包在此基础上叠加逐帧播放，两者不冲突。

## 9. 五态推导

新增到 `lib/events.js`：

- `snapshot().activity = { openTurns, openSessions }`：由已提交状态里各 session 未删除的 `turns` 计数得出（现有实现已在 turn 开始时建条目、`turn-terminal` 时删除）。
- `derivePetState({ snapshot, transient, now })` 纯函数，优先级自上而下：

1. `transient` 里存在未过期的 `error` → `error`
2. `transient` 里存在未过期的 `celebrate` → `celebrate`
3. `snapshot.waiting.approvals + questions > 0` → `waiting`
4. `snapshot.activity.openTurns > 0` → `busy`
5. 其余 → `idle`

`transient` 由 `main.js` 在收到既有 `task-terminal` effect 时按 `result` 写入（`completed` → celebrate，`error`/`aborted` → error），带 `until` 时间戳，过期自动失效。事件层不可用（`availability` 为 `unavailable`）时固定 `idle`，并在设置页与右键菜单如实标注「事件层不可用，宠物只显示空闲」。

## 10. 主题格式

### 10.1 文件

`userData/themes/<name>.json` 或内置 `assets/themes/*.json`：

```json
{
  "name": "极光",
  "author": "SGD",
  "base": "dark",
  "colors": {
    "background": "#071021",
    "surface": "#0f1b30",
    "border": "#1e3350",
    "primary": "#4f46e5",
    "accent": "#22d3ee",
    "text": "#e6edf7",
    "textMuted": "#93a4bd"
  }
}
```

- `base`：`dark` / `light`，决定滚动条、阴影等基调，默认 `dark`。
- `colors`：七个键，值必须匹配 `#RGB` / `#RRGGBB`（大小写不限）；缺失的键回落到内置同 base 主题的对应值；多余键忽略。
- 解析失败或全部颜色都不合法 → 跳过该主题文件并在日志写明文件名与原因。
- 内置 4 套：`鲸坞深色`（现有品牌色 `#1e2a5e`/`#4f46e5`/`#22d3ee`）、`鲸坞浅色`、`极光`、`墨鲸`。

### 10.2 应用方式

主进程把当前主题 token 表通过各窗口既有 preload 通道下发，页面在 `:root` 上设置 CSS 变量。所有自有页面先把硬编码色值改为变量引用，变量默认值即当前品牌深色，保证主题缺失时外观不变。

`config.json` 新增 `theme` 字段（字符串 id，默认 `whaledock-dark`），进入 `SETTINGS_FIELDS`，不进 `RESTART_FIELDS`（即时生效）。

## 11. 设置窗新增区

**宠物**：启用开关（默认关）、宠物包下拉（内置 + 用户目录扫描，显示名字/作者）、置顶开关、鼠标穿透开关、「打开宠物文件夹」、「重新扫描」。扫描结果里被跳过的包以「N 个包被跳过（原因见日志）」形式如实提示，不静默吞掉。

**外观**：主题下拉（即时预览生效）、「打开主题文件夹」、「重载主题」。

两区的按钮都只做 `shell.openPath` 到受控目录与重新扫描，不接受渲染层传入的任意路径。

## 12. 安全模型小结

| 风险 | 处置 |
| --- | --- |
| 包内藏可执行代码 | 只 `JSON.parse` + 白名单字段；资源只接受 `.png`；不 require/eval/import 任何包内文件 |
| 路径穿越 / symlink 逃逸 | 文件名禁含分隔符；解析后 realpath 必须仍在包根内（复用原生 realpath 身份） |
| 超大/畸形图片 | 复用 v0.4 的 PNG header 校验与像素/字节上限；超限跳过该帧 |
| 包数量爆炸 | 单次扫描最多 200 个包，每包最多 24 帧，超出部分丢弃并在日志说明 |
| 坏文件导致崩溃 | 每个包独立 try/catch，失败只影响该包 |
| 联网下载 | 不实现任何下载入口 |

## 13. smoke 计划（纯 Node / 静态）

新增子套件 `test/pets-themes-smoke.js`，并入统一 smoke：

1. manifest 全字段合法 → 解析结果逐字段正确。
2. manifest 缺失 + 单张 PNG → 五态全部指向该图。
3. manifest 缺失 + 多张带前缀 → 按前缀分组，缺失态回落 idle。
4. manifest 缺失 + 多张无前缀 → 全部进 idle 逐帧。
5. `states` 引用不存在的文件 / 越界文件名 / 非 png → 该帧被丢弃，状态回落。
6. 坏 JSON / 空目录 / `idle` 无帧 → 该包被跳过且返回跳过原因，其余包不受影响。
7. 帧数、包数、尺寸、帧率越界 → 收敛到上限而不是抛错。
8. 主题：合法 JSON 解析、缺色回落、非法色值跳过、坏 JSON 跳过、未知键忽略。
