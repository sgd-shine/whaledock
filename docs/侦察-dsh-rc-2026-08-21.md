# dsh 最新 RC 侦察报告（2026-08-21）

## 结论

**本轮不升。鲸坞继续锁定 @deepseek-ai/dsh@0.1.0-rc.6。**

截至本次实时查询，上游 latest / next 已不是 rc.7 或 rc.8，而是当天发布的
@deepseek-ai/dsh@0.1.1-rc.1。最新版能在 macOS arm64 隔离环境启动，Web UI 也能被鲸坞源码态
壳加载；用户 agent preset 的真实发现路径也已实证。但它还不满足鲸坞的升级门：

1. rc.8 起本地 dsh web 默认会打开系统浏览器；鲸坞现有 system dsh、npx、内置 runtime 三条
   启动路径都只传 web --port，直接升锁会额外弹浏览器。升级前必须把 --no-open 收口到
   lib/backend.js 并补三条路径的 contract tests。
2. 鲸坞事件、只读状态、prompt 和工作区证明均以 rc.6 的根包 / host 精确版本证明 fail-closed。
   本次 custom-command 源码态 smoke 只能证明页面可嵌入；事件层因无法证明 rc.6 而按设计不可用，
   不能当作完整集成通过。
3. rc.8 官方明确写 SQLite 数据结构不兼容。真实用户状态迁移必须只在克隆的临时 DSH_HOME 上做
   兼容实验；本轮没有、也不允许拿真实 ~/.dsh 试。
4. 最新版刚发布数小时，rc.6 到最新跨 814 个上游 commit；正式三平台 lock、inventory、
   许可证全文、SOURCES、原生模块 runner 与 Windows 证据均未闭环。
5. preset 虽已证明能加载，但用户 preset 的实际根位于 $DSH_HOME/.agent-presets/。
   鲸坞硬约束禁止写 ~/.dsh，因此工作台包里的 agent.cordis.yml 仍只能写“已检测到，尚未接通”；
   不能因本次发现实证就宣称工作台包已经接通。

## 3. CLI、端口与启动行为

### 不变项

- 顶层语法仍有 --profile、--patch、--dump-config、--dump-default-config。
- 子命令仍为 web 与 plugin。
- apps/cli/src/args.ts、src/bin.ts，以及 npm tarball 中 lib/bin.js、
  dump-config、profile-boot、plugin 四份 CLI 产物在 rc.6 与最新版逐字节相同。
- 默认 bind 仍为 127.0.0.1，默认端口仍为 3080。

### 破坏鲸坞当前体验的变化

最新版 web help 新增 --no-open。rc.8 起直接运行本地 dsh web 会自动打开默认浏览器。
鲸坞现有三条非自定义启动计划分别是：

- system dsh：dsh web --port N
- npx：npx -y @deepseek-ai/dsh@版本 web --port N
- bundled：Electron as Node + dsh entry + web --port N

三条都没有 --no-open。直接升锁会在鲸坞自己的窗口之外再打开一个浏览器标签，因此本轮判为阻断项。

## 9. 下次从哪里继续

   --dump-config 与退出清理全部 contract probes。

6. 若要把工作台 agent.cordis.yml 从“已检测”升级为“已接通”，先侦察是否能通过只读外部路径
   或显式 --patch 安全挂载；任何方案都不得写、迁移或清理 ~/.dsh。

完成以上门后，再给“升 / 不升”第二次结论；本报告不授权修改版本锁。
