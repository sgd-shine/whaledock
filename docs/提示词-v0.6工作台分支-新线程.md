【第一件事：先读，不要动手】

【背景：我们为什么换赛道】

【v0.6 的核心命题】
SGD 的判断：Harness 是一个可以有很多形态的智能体底座，应该在原生常驻状态的基础上
"做分支"，开发不同形态的智能体工作台。

已经定下来的工程决策，不要推翻：
**分支不是代码分支，是内容分支——一个外壳，多个声明式「工作台包」。**
理由：每种形态开一个 App，签名/合规/更新全部乘以 N，很快维护不动；做成包之后，
加一个新形态 = 加一个目录，不改一行外壳代码。而且一期视频 = 一个工作台包。

【你要先做的：出方案，等 SGD 拍板，不要直接写代码】
SGD 不写代码，需要用普通人能听懂的话理解方案。按项目总则，每个提案必须包含三段：
1. 痛点一句话（一句大白话，不要术语）
2. 普通用户怎么用（点哪里、看到什么、结果落在哪，按步骤写）
3. 示意（ASCII 界面草图即可）

请就下面四件事各出一版方案，写进 docs/开发方案-v0.6-工作台包.md，然后停下来等 SGD 确认：

A. **工作台包的目录结构与 manifest 字段**
   起点是方案第 3.2 节给的结构（manifest/theme/pet/workspace/actions/agent.cordis.yml/
   skills/onboarding）。你要做的是把每个字段定死：叫什么、什么类型、缺了怎么回落、
   非法值怎么拒。同时明确"用户装一个包"的完整动线（放到哪个目录、怎么被发现、怎么切换）。

B. **第一个包：短视频创作工作台的内容**
   方案 3.3 节已经给了骨架（四个文件夹 + 五个按钮）。你要把五个按钮背后的提示词模板
   真正写出来，中文，可直接用。注意 SGD 自己就是这个包的第一个用户——他要用它做鲸坞的
   宣传视频，所以内容要真的好用，不是占位符。

C. **原生常驻状态怎么做到"不开浏览器也知道 agent 在干嘛"**
   托盘五态（空闲/思考中/等你确认/已完成/出错）+ 宠物动作联动。
   集成方式**只允许只读**：`dsh --profile <name> --dump-config` + HTTP/SSE 只读事件流 +
   轮询兜底。**绝对不碰 Cordis 内部 API**（第三方插件跟主线的兼容率只有约 14%，碰内部 API 的必死）。
   重点回答：agent 卡在"等你确认"时，怎么让用户在不看窗口的情况下被叫醒。

D. **风险清单**：这套设计里哪些地方最可能出问题，你打算怎么先验证。
