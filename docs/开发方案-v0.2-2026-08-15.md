## 0. 一句话与读法

**v0.2 的目标：让"任何一台 Windows 或 Mac 电脑，不装任何环境，下载即用"，并且装上之后能自己保持最新。** 四个交付物：Windows 全环境支持（安装器+便携版）、免装 Node 内置引擎兜底、Intel Mac 构建、设置窗（含开机自启/启动最小化，预留帮助位）+ 更新机制（Win 半自动更新 / mac 新版提醒）。

给 Codex：先读第 4、6、7 节和附录 A；硬约束仍以 `AGENTS.md` 为准。给 SGD：第 3 节看功能长什么样，第 8 节是你的两份 5 分钟验收清单，第 9 节是风险交底。

## 2. 侦察批次一对本版的影响（结论摘要）

侦察报告主要为 v0.3/v0.4 开门，对 v0.2 没有阻塞项，但有三条纪律写进本版：

1. **版本锁不动**：内置引擎与 npx 回退一律锁 `0.1.0-rc.6`（单一事实源 = `lib/config.js` 的 `DEFAULTS.dshVersion`）。报告证实 npm 包与官方仓库 HEAD 会漂移，升级 dsh 必须重跑侦察的 contract probes，不在 v0.2 做。
2. **更新检查 ≠ 遥测**：报告复核过"无遥测"承诺。v0.2 新增的更新检查只向 GitHub Releases 发一个不带任何标识的 GET，且设置窗里可一键关闭——方案 §4.D 有完整声明，写进 README。
3. **不碰 `~/.dsh`**：报告确认 dsh 数据目录无 delete/retention 语义，鲸坞任何版本都不得写入/清理它。v0.2 本来就不碰，此处立为红线备查。

顺带说明：报告给 v0.3 完成通知与 Token 看板的判定是 GO/PARTIAL（事件用 `turn/end` 状态机，看板走薄插件或 events.mux，数字标"观测值非账单"），**路线图不需要 v0.3/v0.4 对调**。v0.3 方案单独出，不挤进本文件。

## 3. 用户可见功能（按产品宪法：痛点 → 怎么用 → 示意）

### 3.1 Windows 版 + 免装 Node

**痛点一句话**：Windows 用户想用 Harness，先要过"装 Node、配环境、开终端敲命令"三关，大部分人第一关就放弃；Mac 这边没装过 Node 的新电脑同样跑不起来。

**普通用户怎么用**：去 Releases 下载 `WhaleDock-Setup-0.2.0.exe` 双击安装（或下载便携版，解压双击就跑）；电脑上有没有 Node 都无所谓——鲸坞先找你装过的，找不到就用自己肚子里带的那台引擎。全程不开终端。

**通俗类比**：以前的鲸坞是"借你家的发动机开车"（要求电脑装了 Node）；v0.2 在后备箱里常备一台**备用发动机**（Electron 本身就内含一台 Node，我们让它挂"纯 Node 挡"来带动预先打包好的 dsh），你家有发动机就优先用你的，没有就用备用的，保证车一定能开。

### 3.2 设置窗（含开机自启 / 启动最小化）

**痛点一句话**：现在改端口、改快捷键要打开 JSON 文件手改，普通用户不敢碰；每天手动点开 App 也烦。

**普通用户怎么用**：托盘/菜单点「设置…」（mac 也可 ⌘,）：改端口、改快捷键、勾"开机自动启动"和"启动时不弹窗口"，点保存即生效；需要重启后端的项会明确提示并给一键按钮。

**示意（文字稿）**：

```
┌─ 鲸坞设置 ──────────────────────────────┐
│ [通用] [后端] [帮助]                      │
│                                          │
│ 通用                                     │
│   ☑ 开机自动启动鲸坞                      │
│   ☐ 启动时最小化到托盘（不弹窗口）          │
│   全局快捷键  [⌘⇧H          ] [恢复默认]  │
│   ☑ 自动检查新版本    [立即检查更新]       │
│                                          │
│ 后端（改动需重启后端生效）                  │
│   端口       [3080 ]                     │
│   工作目录    [~/            ] [选择…]    │
│   后端版本    [0.1.0-rc.6    ]（锁定版）   │
│   ☐ 优先使用内置引擎（不探测本机 Node）     │
│   自定义启动命令 [               ]（高级）  │
│                                          │
│ 帮助（本版为静态占位）                     │
```

**关闭语义与回退（F13a 批准时要求写清）**：取消勾选"开机自启"= 当场从系统登录项/注册表移除，不留残余；Windows 便携版的自启指向解压后的 exe 本体（`PORTABLE_EXECUTABLE_FILE`），若用户移动了 exe，下次启动时鲸坞检测到登录项路径失效会自动修正为新路径并记日志；mac 未签名构建注册登录项若被系统拒绝，设置页如实显示"系统未接受，请在 系统设置→通用→登录项 手动添加"，不假装成功。"启动最小化"对每次启动生效（不只开机自启）：不显示启动页与主窗口，后端照常启动，托盘可随时唤出；仅当启动失败时才弹出启动页报错——静默启动不等于静默失败。

### 3.3 更新：Windows 半自动更新 / mac 新版提醒

**痛点一句话**：装完就成"绝版"——出了新版用户不知道，知道了也要重走一遍下载安装。

**普通用户怎么用**：Windows：右下角弹"发现新版 v0.2.1"，点「立即更新」→ 后台下载完校验 → 点「重启并更新」，鲸坞自动退出、静默安装、自动重开，前后不超过一分钟。mac：弹窗提醒 + 「去下载」打开 Releases 页（自动更新等 v1.0 签名后再做）。两端都可"跳过此版本"或在设置里整个关掉。

**通俗类比**：App 自己每天看一眼公告栏（GitHub Releases），看到新公告先把安装包搬回家、核对封条（SHA-256 校验和），一切没问题才请你按一下"换新"。它不上报任何东西——只看公告，不留名。

## 4. 技术方案（六个工作流）

### 4.A Windows 兼容层（`lib/backend.js` 跨平台化）

现状是 mac 专用的三处要平台化，全部收敛在 `lib/backend.js`（对 dsh 的假设仍只许住在 backend/config 两处）：

**A1 · PATH 探测**。Windows 的 GUI 应用能继承用户级 PATH（注册表环境变量），没有 mac 的"Finder 拿不到终端 PATH"问题，所以 `loginShellPath()` 在 win32 直接返回空串（不去 spawn shell）。拼接 PATH 一律用 `path.delimiter`（win 是 `;`）。追加的常见目录表：

| 平台 | 追加目录 |
|------|---------|
| win32 | `%NVM_SYMLINK%`（nvm-windows 当前版指针）、`%ProgramFiles%\nodejs`、`%APPDATA%\npm`（npm -g 的 bin，全局装的 dsh 在这）、`%LOCALAPPDATA%\Volta\bin`、`%USERPROFILE%\scoop\shims`、`%ProgramData%\chocolatey\bin` |
| darwin | 维持现状（登录 shell + Homebrew/nvm/volta 目录） |

**A2 · which 支持 PATHEXT**。Windows 可执行文件带扩展名：`which('dsh')` 生成候选 `dsh.exe / dsh.cmd / dsh.bat / dsh`（顺序按 PATHEXT，缺省 `.COM;.EXE;.BAT;.CMD`）。npm 全局命令的实体是 `.cmd` 垫片。实现为纯函数 `execCandidates(name, platform, pathext)`，smoke 在任何平台都能测它。

**A3 · spawn 与进程树清理**。① Node ≥20.12 出于安全修复（CVE-2024-27980）要求 spawn `.cmd/.bat` 必须 `shell: true`——命令解析结果里凡 file 以 `.cmd/.bat` 结尾则置 shell:true；② win32 一律 `windowsHide: true`（防止黑色控制台窗一闪）；③ `detached` 维持"仅非 win32 为 true"；④ 停止逻辑改为**纯函数规划器 + 薄执行器**：`killPlan(pid, platform)` 返回步骤序列——darwin/linux 为 `[进程组 SIGTERM, 等 4s, 进程组 SIGKILL]`，win32 为 `[taskkill /PID p /T（温和）, 等 4s, taskkill /PID p /T /F（强杀整树）]`；执行器逐步执行。smoke 断言两种平台的 plan 形状，Windows CI runner 真实跑一遍假后端的启动与树清理。

**A4 · 托盘/菜单/快捷键差异**。Windows 托盘用彩色图（mac 的黑白 template 规范不适用）：新增 `assets/trayColor.png`（16+32，由现有图标源导出）；托盘单击 = 切换窗口显隐（Windows 惯例，mac 维持仅菜单）。菜单栏：Windows 没有应用菜单位，新增「文件」菜单收纳「设置…」「退出」；mac 的「设置…」进 app 菜单（⌘,）。快捷键 `CommandOrControl+Shift+H` 在 Windows 自动落成 Ctrl+Shift+H，被占用时日志照旧提示、设置窗可改。

### 4.B 免装 Node 内置引擎（探测链末级）

**原理**：Electron 二进制本身内嵌完整 Node，运行时设 `ELECTRON_RUN_AS_NODE=1` 即以纯 Node 模式执行任意脚本——不需要再发一份 Node。配合打包时预装好的 dsh 离线目录，就得到"零环境要求"的兜底引擎。

**探测链定稿（`resolveCommand` 四级）**：

```
config.command（用户自定义，最高优先）
  → PATH 里的 dsh（用户自装，尊重其版本）
  → PATH 里的 npx（锁定版 npx -y @deepseek-ai/dsh@0.1.0-rc.6 web）
  → 内置引擎（ELECTRON_RUN_AS_NODE + 预打包 dsh，版本恒为锁定版）
```

配置新增 `preferBundled`（默认 false）：勾选后内置引擎提到第 2 级之前——给"机器上 Node 环境混乱"的用户和演示视频一个确定性开关。

**打包产物**：新增 `scripts/bundle-dsh.js`（纯 Node，构建期脚本）：读 `DEFAULTS.dshVersion` → 在 `vendor/dsh-runtime/` 执行 `npm install --omit=dev --no-audit --no-fund @deepseek-ai/dsh@<版本>` → 校验装到的确是锁定版本并写 `manifest.json`（版本、生成时间、包完整性值）→ electron-builder `extraResources` 把它带进安装包（运行期位于 `process.resourcesPath/dsh-runtime/`）。`vendor/` 入 `.gitignore`；`npm run dist` 前自动执行；**各平台在各自 runner 上现场生成**（防原生依赖跨平台错配——dsh 的 zstd 持久化若带平台二进制，混装会炸）。

**运行接线（保持 lib/ 纯净）**：`lib/backend.js` 不 require Electron，所以 Electron 专属的两个事实——Electron 可执行文件路径、resources 根目录——由 `main.js` 开机时注入：`backend.setRuntimeInfo({ execPath: process.execPath, resourcesPath: process.resourcesPath })`。backend 内部只负责：拼 `<resourcesPath>/dsh-runtime/node_modules/@deepseek-ai/dsh/lib/bin.js`（bin 位置是 dsh 假设，写在 backend.js 常量区）、存在性检查、spawn 时 env 加 `ELECTRON_RUN_AS_NODE: '1'`（子进程继承此变量，dsh 内部 fork 的孙进程同样落在 Node 模式，侦察已证 dsh 有多进程行为）。smoke 用假 runtimeInfo + 假目录测第四级命中与缺席降级。

**体积交底**：内置引擎会把安装包增大（估计 +80〜250MB，取决于 dsh 依赖树），这是"零环境要求"的定价。Codex 在批次 2 汇报实测数字；若单包超 500MB 再议瘦身（如 mac 版不带内置引擎只 Win 带——决策权在 SGD）。

### 4.C 设置窗

**窗口形态**：独立 `BrowserWindow`（约 520×600，单例，关即销毁），自包含 `settings.html`（无框架，风格延续 splash 深色系）+ 专属 `preload-settings.js`。主窗口继续**无 preload、nodeIntegration=false**，一行不改——这是给 v0.3 独立窗口们打的样板：新能力 = 独立窗口 + 最小 IPC。

**IPC 合约（settings: 前缀，全部经 contextBridge）**：`settings:get`（配置快照+运行态：平台、是否便携版、登录项真实状态、当前版本）、`settings:apply`（补丁，主进程逐字段校验）、`settings:choose-workdir`（系统选目录对话框）、`settings:restart-backend`、`settings:check-update`。

**字段与生效语义**：

| 字段 | 校验 | 生效 |
|------|------|------|
| openAtLogin | 布尔 | 立即（`app.setLoginItemSettings`，按 §3.2 语义含便携版路径与失败如实回报） |
| startMinimized | 布尔 | 下次启动 |
| hotkey | 试注册验证：先注销旧键→注册新键，失败则回滚旧键并报"该组合键被占用" | 立即 |
| checkUpdates | 布尔 | 立即 |
| port | 1024–65535 整数 | 提示"已保存，重启后端生效"+[立即重启] |
| workdir | 目录存在 | 同上 |
| dshVersion | `latest` 或 semver（含 -rc 等后缀） | 同上 |
| preferBundled | 布尔 | 同上 |
| command | 字符串/置空 | 同上（高级项，输入框带"一般不用填"提示） |

**帮助标签（占位实现）**：版本号与构建架构、打开操作手册（仓库 docs 链接）、打开日志文件夹、三条常见问题（mac 右键打开 / Win SmartScreen "仍要运行" / 首启慢与端口占用）。完整帮助中心仍是 LATER，此处只是把"位置"占住。

**附带小项 · attach 弱特征校验**（v0.1 风险清偿）：TCP 探通后、attach 之前，向 `http://127.0.0.1:port/` 发一个 1.5s 超时的 GET：响应像 Harness Web（HTML 且标题含 "DeepSeek Harness"）→ 静默接入；不像 → 启动页黄色提示"端口 3080 上有服务但不像 Harness，可能是其他程序占用"，给 [仍然接入] [打开设置改端口] 两个按钮。判定失败（超时/连接被拒于 HTTP 层）不阻塞，按原逻辑接入并记日志——弱校验只加提示，不加新的失败态。

### 4.D 更新器（`lib/update.js`，纯 Node，零依赖）

**为什么不用 electron-updater（本方案唯一改动既定预告的决策点）**：总纲第七节预告曾写"electron-updater"。落到实现上它与仓库宪法冲突：它是**运行时依赖**（还连带 fs-extra/js-yaml 等一串），直接违反 AGENTS.md 第 2 条"不新增运行时依赖"；且其增量更新、多通道等能力对未签名单文件安装器是冗余。自研轻量更新器约 200 行纯 Node，能被 smoke 离线测试，信任模型也更简单。**代价**：没有增量下载（每次全量 ~100MB+）、没有灰度通道——对当前体量可接受。若 SGD 想维持 electron-updater 路线，在批次 4 开工前说一声，此项可换（需在 AGENTS.md 记录破例理由）。

**检查流程**：`GET https://api.github.com/repos/sgd-shine/whaledock/releases/latest`（带 UA，不带任何用户标识；`releases/latest` 天然忽略 prerelease，所以 v0.2.0-beta 这类预发布 tag 不会打扰正式版用户）→ 比较版本（自带 semver 比较，正确处理 `0.2.0-beta < 0.2.0`）→ 高于当前且 ≠ `skipVersion` → 按平台/架构挑资产（命名规则见 §4.E，挑选逻辑是纯函数可测）。触发时机：启动后 15 秒一次、常驻期间每 24 小时一次、菜单/设置手动一次；`checkUpdates=false` 时前两者全停。

**Windows 半自动更新流**：提醒弹窗 →「立即更新」→ 下载 `WhaleDock-Setup-<v>.exe` 到临时目录（Node https，跟随 GitHub 资产重定向，带进度日志）→ 下载同 Release 的 `SHA256SUMS-win.txt` 并核对 → 弹"下载完成" →「重启并更新」→ `spawn(installer, ['/S','--force-run'], {detached:true}).unref()` + `app.quit()`——NSIS 静默安装后自动拉起新版。校验失败 = 删除下载物 + 提示改走手动下载页。**便携版**（检测 `PORTABLE_EXECUTABLE_DIR`）不能原地安装：降级为 mac 式提醒 + 打开下载页。

**mac 提醒流**：弹窗（新版本号 + 更新要点首行）→ [去下载]（开 Releases 页）/ [跳过此版本]（写入 `skipVersion`）/ [稍后]。

**信任模型（如实交代）**：未签名前提下，更新安全性锚定在"HTTPS + GitHub 账号安全"上——SHA-256 校验防的是下载损坏与中间人篡改资产，防不了 GitHub 账号被盗后发假 Release。对策写进 §9：SGD 的 GitHub 开启 2FA，这是 v1.0 签名之前整条分发链的真正钥匙。

## 9. 风险与对策（按大小排序）

1. **dsh 本身没在 Windows 验证过（本版最大未知）**。鲸坞壳的 Windows 化全在我们手里，但 dsh 的 Windows 行为（路径、zstd 持久化、子进程）只有 Windows 真机能证。对策：v0.2 已按“实验性支持（未真机验证）”发布口径处理，§8 Windows 清单在发布后补证；若 dsh 有 Windows 平台 bug，鲸坞如实提示、先收日志并向上游提 issue。
2. **未签名双平台的系统摩擦**。mac Gatekeeper 右键打开、Win SmartScreen 仍要运行、mac 登录项可能被拒——全部走"如实告知 + 文档截图"路线，不做任何绕过系统的小动作。签名统一 v1.0 解决。
3. **内置引擎体积**。+80〜250MB/包。当前决定为 macOS/Windows 都带；正式本地候选单包均低于 500 MB，探测链保证已有 Node/dsh 的用户仍优先使用自己的环境。
4. **更新链信任锚 = GitHub 账号**。对策：SGD 开 2FA；release.yml 只认 tag 触发；校验和随 Release 同源发布。
5. **ELECTRON_RUN_AS_NODE 的边角**：dsh 孙进程继承该 env 属预期，但若 dsh 未来改为按绝对路径找 node 则兜底失效——版本锁定 rc.6 使该行为冻结，升级 dsh 时按侦察纪律重验。
6. **便携版限制**：无法半自动更新（降级提醒）、自启依赖 exe 不挪窝（已做自愈+提示）。文档明说"要省心用安装版"。
