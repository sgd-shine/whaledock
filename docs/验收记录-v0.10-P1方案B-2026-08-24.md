## 2. 本批实现

### 2.1 受控局部 fork

- 只 fork `@deepseek-ai/dsh-client-ui-layout` 与 `@deepseek-ai/dsh-client-ui-conversation`；包名与版本保持精确 rc.2，manifest 记录上游原始 bundle SHA-256，保留 MIT LICENSE。
- fork 与 P0B Host/Client 插件一同只复制到每次启动新建的 app-owned 隔离 profile；源树、目标树、普通文件、symlink、单文件/总大小和 SHA-256 继续 fail-closed 回读。
- 真实 rc.2 证明 `web --patch` 和 `--patch ... web` 都不是合法入口；启动器已改为把 `web` alias 替换成 `--profile web`，再追加固定 `--patch`，同时保留 `--no-open` 与 `--port`。
- 非 bundled、外部启动、错版、flag 关闭和资产失败路径仍完整回退；不停止外部 dsh。

### 2.2 同屏工作台

- 默认进入“内容”，保留“会话”入口；选择写入当前页面 `sessionStorage`，不制造固定项目—会话绑定。
- 内容态为三栏：左侧项目库、中间项目阶段、右侧原生 dsh 对话；原生 `conversation`、`details` 与 `shell.overlay` 仍由 dsh 原组件渲染。
- 项目库直接读取原生 workspace + session 状态：显示有会话与零会话项目，可跨项目切换；零会话项目第一次操作时才用官方 `connectWorkspace()` 建立会话。
- 中栏提供 `概览 / 脚本 / 拍摄 / 发布 / 复盘`。操作只把阶段任务填入右侧原生草稿，不自动发送；右侧已有草稿时拒绝覆盖。
- 保留拍摄环节原有独立全屏拍摄窗口，本批不改变该链。

### 2.3 发送前上下文闸门

- Client 以正式 native session identity 请求 `context/preflight`；Host 同时核对 controller、页面、selection capability、revision、当前 session 与 queue/steer 模式。
- queue 只在目标 revision 已 pending/effective 时放行；steer 还要求当前 turn 已冻结同一上下文。
- Client 最多等待 2.5 秒让主进程完成 stage；仍未 ready 时原生发送入口返回错误、保留草稿并显示“工作台上下文尚未准备好，请稍后再发送”。
- Host 响应只有受限 `ready/code`，不向页面暴露 raw session、路径或上下文正文。

## 4. 设计审计结论

- 主要阅读顺序已经是“项目 → 阶段 → 原生对话”，跨项目切换不再要求绑定固定会话。
- 设计审计发现初版只按已有 session 聚合，导致零会话 workspace 不可见；现已改为以原生 workspace 为第一层，并真实点击验证即时建会话。
- 初版“填入右侧草稿”过于像普通信息卡；现使用 dsh 原生业务色 token 提升可操作性，仍弱于最终发送按钮，避免误导成自动发送。
- 960px 可用但右侧模型名称会按 dsh 原生规则截断；这不阻塞主操作。更窄宽度不在主窗合同内。
- 中栏当前是 P1 骨架，只投影项目/会话状态与阶段入口；真实稿件块、发布单和复盘数据仍属于后续批次，不能把骨架写成完整创作工作台已完成。
