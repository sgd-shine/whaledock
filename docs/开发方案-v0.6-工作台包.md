日期：2026-08-19 · 起点版本 v0.5.1 · **状态：提案，等 SGD 拍板，未写一行代码**

上游依据：[`开发方案-第三阶段-2026-08-18.md`](开发方案-第三阶段-2026-08-18.md) 第 2、3 节。
本文只覆盖 v0.6 的四件事（A 包机制 / B 第一个包 / C 常驻状态 / D 风险）。
扫码远程与引擎瞭望塔已顺延 v0.7，本文不涉及。

## 0. 一句话说清这一版在做什么

> **鲸坞从"一个能开 Harness 的壳"，变成"一个可以停不同船的坞"。**
> 换一个工作台，界面、宠物、常用按钮、文件夹全套一起换；而这些工作台**只是几个文本文件**，
> 不是代码，鲸坞永远不执行它们。

**为什么必须是"包"而不是"分支"**：每种形态开一个 App，签名、公证、许可证清单、更新通道全部要乘以 N，
两三个形态之后就维护不动了。做成包之后，加一个新形态 = 加一个目录，外壳一行不改。
顺带一个好处：**一期视频 = 一个工作台包**。

---

## 1. 先说清楚这一版**不做**什么

写在最前面，是因为这几条是安全叙事的地基，比功能重要。任何一条被放松，这版就不该发。

| 不做 | 为什么 |
| --- | --- |
| 不执行包里的任何东西 | 包里只有 JSON / Markdown / PNG。不 `require`、不 `eval`、不 `spawn`、不起子进程 |
| 不解析 `agent.cordis.yml` | 我们只检查"这个文件在不在、是不是普通文件、有没有超大"。内容原样交给 dsh。**不引入 YAML 解析器**（既是新依赖，也是新攻击面） |
| 不自动安装 skill | `skills.json` 只展示 + 给一个"复制安装命令"的按钮。装不装是用户的显式动作 |
| 不渲染 Markdown | `onboarding.md` 按纯文本显示（`textContent`），不解析 HTML、不自动生成可点链接。引入 Markdown 解析器 = 引入 XSS 面 + 新依赖，不值 |
| 不做提示词变量/模板引擎 | `{{变量}}` 就是一个小型解释器，属于执行面。v0.6 里提示词是**死文本**，包含 `{{` 也原样发出去 |
| 不联网下载包 | 跟 v0.5 宠物包/主题包一致，全靠用户手放文件 |
| 不开社区包目录 | `community-workbenches/` 顺延 v0.7。理由见第 D 节风险 9 |
| 不动 dsh 版本锁 | 仍锁 `0.1.0-rc.6`，升不升由另一个侦察任务决定 |
| 不新增运行时依赖 | devDependencies 仍只有 electron + electron-builder |

# A. 工作台包的目录结构与 manifest 字段

## A-1 痛点一句话

> 鲸坞现在只有一种样子。我想要"做电商的时候是一套环境，剪视频的时候是另一套环境"，
> 但我不会写代码，也不想为了换个样子重装一个软件。

## A-2 普通用户怎么用

> **2026-08-19 SGD 反馈后重写**：装和切都要"体感上不复杂"。原来那版是 5 步，现在是 **装 1 步、切 1 下**。

**装一个工作台包 —— 一步：把文件夹拖进鲸坞窗口**

拖进去就装好了，立刻出现在切换器里。不用先打开设置、不用找目录、不用点"重新扫描"。

鲸坞做的事只有一件：**把这个文件夹原样复制**到 `WhaleDock/workbenches/` 下，然后重新扫一遍目录。
不解压、不执行、不联网、不改你原来的文件夹。拖错了就在切换器里点「移除」，它只是删掉那份副本。

（「打开工作台文件夹」按钮仍然保留在设置里，给想手动管理的人用，但**不再是主路径**。）

**切一个工作台 —— 一下**

三个入口，随便哪个都是**点一下就换**：

- 窗口左上角的**工作台按钮**（常驻，不藏在设置里）→ 列表 → 点
- 托盘菜单 → 工作台 → 点
- 快捷键 `⌘⇧1` ~ `⌘⇧9` 直接切前九个；`⌘⇧0` 回到上一个用过的

**什么时候会拦你一下（只有这一种情况）**

只有**第一次启用一个"重工作台"**时，会弹一次卡片，因为它要在你硬盘上建文件夹、要重启后端。
看清楚了点「启用」。**之后再切回这个工作台，一下就过去，什么都不弹。**

轻工作台（不建文件夹的那种）**连第一次都不弹**——它只换外观和按钮，没有什么需要你同意的。

**切过去之后，到底变了什么**

| 变的东西 | 从哪来 | 包里没写就怎么办 |
| --- | --- | --- |
| 配色 | `theme.json` | 跟随你的全局主题，不变 |
| 桌面宠物 | `pet/` | 跟随你现在的宠物，不变 |
| 左边一列按钮 | `actions.json` | 不显示按钮栏 |
| 工作文件夹 | `workspace.json` | **不切工作区**，你现在在哪就还在哪 |
| 首次引导卡 | `onboarding.md` | 不弹卡，直接进 |
| 推荐 skill 清单 | `skills.json` | 不显示这一栏 |

**关键设计：轻工作台 vs 重工作台**

- **轻工作台**（没写 `workspace.json`）：切换 = 换皮肤 + 换按钮，**瞬间完成，后端不重启**。
- **重工作台**（写了 `workspace.json`）：切换 = 换一整套环境，要**停后端 → 改配置 → 重启后端**，
  真机上大约几秒到十几秒，界面全程显示进度条。这条路**完整复用 v0.4 已有的工作区串行事务 + journal**，
  中途失败会自动回滚到原来的工作区，不另起一套。

> 建议默认把大多数包做成轻工作台，只有确实需要独立文件夹的（比如短视频创作台）才做成重的。
> 这一条要 SGD 拍板，见第 E 节问题 1。

## A-4 目录结构（文件名全部写死，manifest 里没有任何路径字段）

```
WhaleDock/workbenches/短视频创作台/
├── manifest.json        必填。没有它 = 不是工作台包，整个目录跳过
├── icon.png             可选。切换器里的小图标
├── theme.json           可选。v0.5 主题格式，原样复用 lib/themes.js
├── pet/                 可选。v0.5 宠物包格式，原样复用 lib/pets.js
│   ├── manifest.json
│   └── *.png
├── workspace.json       可选。首次启用时要建的文件夹结构
├── actions.json         可选。左侧按钮 + 每个按钮发给 agent 的提示词
├── agent.cordis.yml     可选。dsh 的 agent preset，我们只查存在性，绝不解析
├── skills.json          可选。推荐 skill 清单，只展示不安装
└── onboarding.md        可选。首次启用时显示的引导文字
```

> **一个刻意的设计决定：manifest 里一个路径字段都没有。**
> 所有子文件的名字由鲸坞写死，包作者不能指定"我的主题在 `../../etc/passwd`"。
> 这让路径逃逸在**结构上就不可能发生**；后面那套逃逸校验是第二道墙，不是唯一一道墙。

**扫描根与优先级**（跟宠物包/主题包完全一致）

| 顺序 | 目录 | source | 说明 |
| --- | --- | --- | --- |
| 1 | `<安装目录>/assets/workbenches/` | `builtin` | 随安装包发的，用户不用管 |
| 2 | `<WhaleDock userData>/workbenches/` | `user` | 用户自己放的 |

包的 **id = 目录名**，对外统一带前缀：`builtin:默认工作台`、`user:短视频创作台`。
同名的内置包与自制包**并存**，各显示各的，不互相覆盖（跟宠物包一致，避免"我明明放进去了却没生效"）。

## A-5 `manifest.json` 字段定死

```json
{
  "schemaVersion": 1,
  "name": "短视频创作台",
  "summary": "选题、脚本、口播稿、封面标题、素材清单，一条龙",
  "version": "1.0.0",
  "author": "SGD",
  "license": "MIT",
  "homepage": "https://github.com/sgd-shine/whaledock",
  "dshRange": "0.1.0-rc.6",
  "accent": "#22d3ee"
}
```

| 字段 | 类型 | 必填 | 上限 / 格式 | 缺了怎么回落 | 非法怎么拒 |
| --- | --- | --- | --- | --- | --- |
| `schemaVersion` | 整数 | 否 | 必须 `=== 1` | 当作 `1` | **整包拒绝**，reason `schema-unsupported`。这是唯一一个"字段错就废掉整包"的字段——将来格式变了我们必须诚实拒绝，不能猜 |
| `name` | 字符串 | 否 | ≤ 40 字符 | **用目录名** | 清洗控制字符 → 压缩空白 → 截断；洗完是空的就退回目录名 |
| `summary` | 字符串 | 否 | ≤ 120 字符 | `null`，切换器不显示副标题 | 同上，洗完为空 → `null` |
| `version` | 字符串 | 否 | `^[0-9A-Za-z.+-]{1,32}$` | `null`，UI 不显示版本 | 丢弃该字段 → `null` |
| `author` | 字符串 | 否 | ≤ 80 字符 | `null` | 清洗后为空 → `null` |
| `license` | 字符串 | 否 | ≤ 80 字符 | `null` → UI 明写「**未声明许可证**」 | 同上 |
| `homepage` | 字符串 | 否 | 必须 `https://` 开头，≤ 300 字符 | `null` | 丢弃 → `null`。**只有 https，其他 scheme 一律拒**（挡 `file:`、`javascript:`） |
| `dshRange` | 字符串 | 否 | ≤ 64 字符 | `null` = 不限 | 丢弃 → `null`。**它只用于提示，永不阻断启用**（我们不写版本比较器，那是猜） |
| `accent` | 字符串 | 否 | `#RGB` 或 `#RRGGBB` | 跟随当前主题的 `primary` | 丢弃 → 回落 |

**整包被拒绝的情况只有四种**（其余一律"某字段回落，包还能用"）：

1. 没有 `manifest.json`，或它不是普通文件 / 是符号链接 / 超过 64 KiB → `manifest-unreadable`
2. `manifest.json` 不是合法 JSON，或顶层不是对象 → `invalid-json` / `not-an-object`
3. `schemaVersion` 存在但不等于 1 → `schema-unsupported`
4. 目录名不符合 `PACKAGE_ID_RE`（复用宠物包那条：不为 `.`/`..`，不含路径分隔符与控制字符，≤ 64 字符）→ `invalid-id`

被拒的包**不会让整个列表挂掉**：它进 `skipped[]`，设置页里显示成一条灰色的「未加载：<原因>」，
其他包照常工作。这一条继承 v0.5 的做法。

## A-6 `workspace.json` 字段定死

```json
{
  "root": "短视频创作台",
  "folders": [
    { "path": "01_选题库",   "readme": "把你随手想到的选题、看到的对标视频、听到的用户原话丢进来。一个想法一个文件，或者全塞在一个文件里都行——「今天做什么」会读这里。" },
    { "path": "02_脚本",     "readme": "分镜脚本落在这里，「写脚本」按钮生成。封面标题也存在这里。" },
    { "path": "03_口播稿",   "readme": "能直接对着念的稿子，「转口播稿」按钮生成。念着别扭就直接改，下次生成不会覆盖你改过的文件。" },
    { "path": "04_素材清单", "readme": "这条片子要拍什么、要录什么屏、要找什么图，「列素材清单」按钮生成。" }
  ]
}
```

| 字段 | 类型 | 必填 | 上限 / 格式 | 缺了怎么回落 | 非法怎么拒 |
| --- | --- | --- | --- | --- | --- |
| `root` | 字符串 | 否 | **单段目录名**，≤ 40 字符，不含 `/` `\` `:` 与控制字符，不为 `.`/`..` | 用 `manifest.name`；再不行用目录名 | 非法 → 回落，不拒包 |
| `folders` | 数组 | 是 | ≤ 32 项 | 不是数组或为空 → **当作没有 `workspace.json`**（退化成轻工作台） | — |
| `folders[].path` | 字符串 | 是 | 1–3 段，`/` 分隔；**每一段单独校验**：≤ 40 字符、不为 `.`/`..`、不含 `\` `:` 与控制字符、不以空格或 `.` 开头 | — | 该项丢弃并记 `issues`，其余项照建 |
| `folders[].readme` | 字符串 | 否 | ≤ 4000 字符 | 不写说明文件 | 清洗控制字符（保留换行）后截断 |

**建文件夹的三条铁律**

1. **只新建，不覆盖**：文件夹存在就跳过；`说明.md` 已存在就**一个字都不动**（用户改过的说明是他的财产）。
2. **不删任何东西**：v0.6 里鲸坞没有任何删除用户文件的代码路径。切走一个工作台只是不再显示它的按钮，文件夹原样留着。
3. **落点必须过工作区校验**：最终目录用 `lib/workspaces.js` 的 `canonicalWorkspace()` 走一遍，
   `forbiddenRoots` 传 `config.protectedWorkspaceRoots()`——**字面路径与 realpath 两层都查**，
   任何一层落进 `~/.dsh` 及其后代/链接目标一律拒绝，并且**拒绝时连文件夹都不建**。

**建在哪**：`<文档目录>/鲸坞工作台/<root>/`。跟 v0.4 的默认工作区同一个父目录，用户找得到。

## A-7 `actions.json` 字段定死

```json
{
  "actions": [
    {
      "id": "today",
      "label": "今天做什么",
      "hint": "读选题库，给三个能今天开拍的选题",
      "confirm": false,
      "prompt": "（提示词全文，见 B 节）"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 上限 / 格式 | 缺了怎么回落 | 非法怎么拒 |
| --- | --- | --- | --- | --- | --- |
| `actions` | 数组 | 是 | ≤ 12 项（超出的截断并记 `issues`） | 不是数组 → 不显示按钮栏 | — |
| `id` | 字符串 | 是 | `^[a-z0-9][a-z0-9_-]{0,31}$` | — | 非法或重复 → **丢这一条**，保留先出现的那条 |
| `label` | 字符串 | 是 | ≤ 16 字符（按钮放得下） | — | 洗完为空 → 丢这一条 |
| `hint` | 字符串 | 否 | ≤ 80 字符 | 不显示悬浮说明 | 洗完为空 → `null` |
| `confirm` | 布尔 | 否 | — | `false` | 非布尔 → `false` |
| `prompt` | 字符串 | 是 | ≤ 8 KiB（UTF-8 字节），非空，**不含 `\0`**，**trim 后不以 `/` 开头** | — | 违反任一条 → **丢这一条**并记原因。以 `/` 开头是斜杠命令，v0.4 的 prompt 适配器本来就拒；我们在解析期就拒掉，让用户看到的是"这个按钮没加载"而不是"点了没反应" |

**按钮点下去之后走什么路**（这条不能自由发挥，必须复用 v0.4 已有的通道）

```
按钮 → IPC → main → lib/backend.js 的 createDshPromptAdapter()
                     ├─ 只连 127.0.0.1（loopback），拒绝任何重定向到别处
                     ├─ packageVersionProof 必须精确等于 0.1.0-rc.6，否则直接返回 unknown 不发请求
                     ├─ 只发单条纯文本（content: [{type:'text'}]），没有附件、没有命令
                     └─ 返回 unknown 时**绝不自动重试**，UI 显示"已提交但没收到确认"，由用户自己决定要不要再点
```

按钮点击后 **5 秒内禁用自己**，防止用户以为没发出去而连点造成重复排队。
`confirm: true` 的动作先弹一次确认框再发。

**提示词是死文本**：不做变量替换、不做拼接、不做转义之外的任何加工。
包里写什么就发什么。用户在输入框里的内容与提示词**不合并**——按钮就是按钮。

## A-8 `agent.cordis.yml`：只查存在，绝不解析

我们对它做且只做四件事：

1. 存在吗
2. `lstat` 是普通文件吗（**是符号链接一律拒**）
3. ≤ 256 KiB 吗
4. realpath 之后还在包目录里吗

通过 → 记下**路径**，在 UI 里显示「本工作台带了一份 agent 预设」。
不通过 → 当它不存在，记一条 `issues`，工作台照常可用。

**我们不读它的内容，一个字节都不读进解析器。** 不引入 YAML 库。

> ⚠ **诚实交代一个未验证项**：dsh 到底怎么消费 preset（是复制进 profile？还是启动参数？），
> 我们**没有实证过**。所以 v0.6 P0 只做"检测 + 显示"，**不宣称已经接通**。
> 真正把它交给 dsh，要等 rc.7 侦察任务把 `dsh --dump-config` 的输出结构和 preset 加载方式回读清楚之后再做。
> 在那之前，任何文案里都不许写"支持 agent 预设"，只能写"已检测到，尚未接通"。

## A-9 `skills.json`：只展示，永不安装

```json
{
  "skills": [
    {
      "name": "示例 skill 名",
      "why": "这个工作台为什么需要它，一句话",
      "install": "dsh skills add <包名>",
      "url": "https://github.com/..."
    }
  ]
}
```

| 字段 | 类型 | 必填 | 上限 / 格式 | 非法怎么拒 |
| --- | --- | --- | --- | --- |
| `skills` | 数组 | 是 | ≤ 24 项 | 不是数组 → 不显示这一栏 |
| `name` | 字符串 | 是 | ≤ 60 字符 | 洗完为空 → 丢这一条 |
| `why` | 字符串 | 否 | ≤ 120 字符 | → `null` |
| `install` | 字符串 | 是 | ≤ 200 字符，**单行**（含换行/`\0` 即拒） | 丢这一条 |
| `url` | 字符串 | 否 | 必须 `https://`，≤ 300 字符 | 丢弃该字段 |

UI 规则，三条都是硬的：

- `install` **原样显示成可见文本**，旁边一个「复制」按钮。用户看得见自己要粘贴什么。
- **没有"一键安装"按钮，也没有任何 spawn 路径。** 鲸坞不会替用户执行这条命令。
- 这一栏顶部固定一句话，不可关闭：
  > **装第三方 skill 之后，它在 dsh 进程里是全权限运行的。鲸坞不做也做不到隔离，请只装你信任的来源。**

（这句话的口径来自第三阶段方案第 6 节：话不能说过头。我们能说"包里只有数据"，不能说"用鲸坞就安全了"。）

## A-13 底座必须通用且稳定（SGD 2026-08-19 的判断，写成工程约束）

> SGD 原话大意：**我们不可能把每个行业都做一遍，我们没有那个 know-how。
> 未来更可能是别人在这个底座上做不同的包。所以底座的设计一定要足够通用和稳定。**

这句话直接决定了三条工程规则。以下三条**优先级高于任何功能需求**——
将来任何一个新功能如果要以破坏它们为代价，宁可不做这个功能。

### 规则一：未知字段一律忽略，绝不报错

老鲸坞遇到新包写的新字段 → **当没看见，照常加载**，只在设置页记一条灰色的
「这个包用了 3 个本版本不认识的字段」。

**绝不能**因为多了个字段就说"包坏了"。否则包作者永远不敢用新字段，
生态一次都升不了级——这是所有插件体系最常见的死法。

### 规则二：`schemaVersion: 1` 是一句承诺，不是一个版本号

我们对包作者的承诺，写进文档并且不许后面的接力改：

- **v0.6 定下的字段，含义永不改变。** 已经写好的包，五年后的鲸坞还能装。
- **只增不减。** 新能力一律用**新的可选字段**表达，老包不写就走回落。
- **`schemaVersion` 只在我们不得不做破坏性变更时才 +1**，而我们的目标是永远不 +1。
  真到了那一天，老包必须继续按 v1 规则加载，不是让作者去改包。

### 规则三：字段描述的是「能力」，不是「行业」

manifest 里永远不会出现 `industry: "电商"` 或 `category: "法务"` 这种东西。
六个原语全部与行业无关：

| 原语 | 它表达的通用能力 |
| --- | --- |
| `theme.json` | 换一套视觉，让人知道"我换环境了" |
| `pet/` | 换一个陪伴形象 |
| `workspace.json` | 一套约定好的文件夹结构 |
| `actions.json` | 几个一键发出的提示词 |
| `agent.cordis.yml` | 一份 agent 预设，原样交给 dsh |
| `skills.json` + `onboarding.md` | 告诉用户还需要装什么、怎么上手 |

**"六个原语够不够通用"要靠验证，不能靠感觉。**
建议在写代码之前，先用**纸面**给五个完全不同的行业各写一个包（不实现，只写 JSON）：

| 试写的包 | 看它会不会撞墙 |
| --- | --- |
| 律师·合同初审台 | 文件夹结构 + 5 个审查提示词，够不够？ |
| HR·招聘筛选台 | 需不需要"批量对一堆简历跑同一个提示词"？（这是我预判的第一个缺口） |
| 客服·话术台 | 需不需要"先让我填一个订单号再发"？（第二个缺口：输入表单） |
| 教师·备课台 | 需不需要"第一步产出喂给第二步"？（第三个缺口：多步流程） |
| 自媒体·短视频台 | 已经写完了，见 B 节 |

**这五个纸面包，是底座通用性唯一靠得住的验收方式。** 花半天，能省掉后面半年的返工。

### 我已经预判到的三个缺口，以及为什么 v0.6 先不做

| 缺口 | 长什么样 | v0.6 的处理 |
| --- | --- | --- |
| **输入表单** | 点按钮前先填一个框（订单号 / 客户名 / 链接） | 先不做。做了就要做变量替换，那是模板引擎，是执行面。**但因为有规则一，将来加一个可选的 `inputs` 字段就行，老包不受影响。** |
| **批量执行** | 对文件夹里每个文件跑同一个提示词 | 先不做。它要循环、要限流、要中断，是完整的任务系统，不是一个字段能解决的 |
| **多步流程** | 第一步的产出自动喂给第二步 | 先不做。这本来就是 agent 自己该干的事，我们在提示词里让它自己串（B 节五个按钮就是这么串的：靠"读上一步存的文件"）|

**规则一让这三个缺口不必现在解决。** 这就是"未知字段忽略"这条规矩真正的价值——
它把"必须一次想全"变成了"可以慢慢加"。

### 包作者契约（将来写进《工作台包制作指南》）

**我们对包作者的承诺：**

1. 你今天写的包，将来的鲸坞还能装。
2. 我们**不改你的包**，不重写、不迁移、不自动升级你的文件。
3. 我们**不上传你的包内容**到任何地方，也不联网校验它。
4. 你的包解析失败时，我们**如实告诉用户是哪一项、什么原因**，不含糊其辞。

**我们对包作者的要求：**

1. 包里只能有数据（JSON / Markdown / PNG / 你自己的 yml）。放了可执行文件我们也不会执行它，但请别放。
2. 声明 `license`。不声明的，装的时候会明确标出「未声明许可证」。
3. 别在 `skills.json` 里写你自己没实测过的安装命令。

### 分发格式：v0.6 只认文件夹，不做一键装 zip（诚实说明）

SGD 设想的"下载一个安装包，双击就装上"——**v0.6 做不到，而且这是刻意的**：

- Node 没有内置的 zip 解压，写一个 = 新依赖（违反硬约束 2）或者自己写解压器（新的攻击面：zip-slip）。
- 折中方案已经够简单：包发在 GitHub 上是一个 zip，**macOS 和 Windows 双击 zip 就自动解压**，
  然后把解出来的文件夹拖进鲸坞窗口。**两步，其中一步是系统自带的。**
- 一键装 `.whaledock` 单文件包排到 v0.7，届时必须专门处理 zip-slip（压缩包里写 `../../` 的路径穿越）。

## B-4 五个按钮的提示词全文（可直接用，中文）

> 写法上的四条共同约定，是这些提示词好不好用的关键：
> ①**明确说清读哪个文件夹、写哪个文件**；②**找不到就问，不许编**；
> ③**同名不覆盖**；④**结果里最要紧的一段直接贴回对话**，这样不用打开文件就知道成没成。

### ① 「今天做什么」

```text
你是我的短视频选题助手。按下面的步骤做，做完直接给结论，不要复述我的要求。

第一步，读取当前工作区 `01_选题库/` 下的所有 .md 和 .txt 文件。这些是我平时随手记的
想法、对标视频、用户原话和数据。如果这个文件夹不存在或者是空的，就直接告诉我
「选题库还是空的」，然后给我 5 个提问，问完我就能填出第一批选题——问完就停下，
不要自己替我编选题。

第二步，扫一眼 `02_脚本/` 和 `03_口播稿/`，看看哪些选题我已经写过或拍过了。
做过的不要再推荐给我。

第三步，从选题库里挑 3 个「今天就能开拍」的选题。每个按这个格式给我：

【选题】一句话，不超过 20 个字。这是视频标题的雏形，不是主题分类。
【为什么是今天】为什么现在值得拍：时效性、我手上已经有的素材、或者它能接住我上一条视频。
【钩子】开头 3 秒说什么能让人不划走。直接写出那句话，不要描述"要有悬念"。
【难度】低 / 中 / 高，外加一句：最大的障碍具体是什么。
【素材现状】选题库里已有哪些相关材料，还缺什么。

最后给一段【我的建议】：三个里面你最推荐哪个，一句话说清理由。

硬性要求：
- 只用 `01_选题库/` 里真实存在的内容。不要发明我没写过的经历、数据、用户评价或案例。
- 如果素材不足以支撑 3 个选题，就诚实地只给 1 个或 2 个，并说清为什么。宁可少给也不要凑数。
- 把结果写成文件 `01_选题库/_今日推荐-<今天日期YYYYMMDD>.md`。
  如果同名文件已存在，就在文件名后加 `-2`、`-3`，绝对不要覆盖。
```

### ② 「写脚本」

```text
你是我的短视频分镜脚本作者。

第一步，确定选题。看 `01_选题库/`，特别是 `_今日推荐-*.md`。
如果我在对话里已经指定了选题，就用我指定的；如果我没指定，就把你找到的候选选题列出来
让我选，然后停下等我回答——不要自己替我决定拍哪个。

第二步，选题确定之后，把选题库里所有跟它相关的材料读一遍。

第三步，写分镜脚本，结构如下：

【一句话概括】这条片子到底在讲什么，20 字以内。
【时长】目标 60–90 秒，并说明为什么是这个长度。
【钩子】0–3 秒：画面写什么、台词说什么。台词要写成能直接念出口的话。
【分镜表】用表格，一行一个镜头：
| 序号 | 时间 | 画面（拍什么 / 录哪个屏） | 台词或字幕 | 备注（转场、音效、节奏） |
【结尾】最后 5 秒说什么，留一个什么问题给评论区。
【风险】这条片子最可能被人划走的位置在第几秒，为什么。

写作要求：
- 台词写口语，不写书面语。判断标准很简单：你自己念一遍，别扭就重写。
- 不要写「接下来我们将会看到」这类填充句。每一句要么给信息，要么给情绪，两样都不占的删掉。
- 涉及功能演示的镜头，写清楚屏幕上到底要出现什么，我要照着录屏。
- 不要发明产品功能、数据或用户评价。不确定的地方写成【待我确认：xxx】单独列出来。

写完存成 `02_脚本/<选题短名>-分镜.md`，同名不覆盖，加 `-2`。
存好之后，把【一句话概括】和【风险】两段直接贴在回答里给我看。
```

### ③ 「转口播稿」

```text
你是我的口播稿改写员。

第一步，找稿子。读 `02_脚本/` 下最近修改的那份分镜脚本。
如果有多份、或者我在对话里指定了某一份，以我指定的为准。不确定是哪份就先问我，不要猜。

第二步，把它的台词部分改写成一份**能直接对着念**的口播稿。

改写规则，请逐条执行：
- 长句拆短。一句话超过 25 个字就拆开。
- 去掉书面词：「进行」「通过……的方式」「具有」「从而」「基于」这类词，换成日常说法。
- 数字和版本号标注怎么念，比如「0.5.1」在稿子里标成「零点五点一」。
- 每句话结尾自然收口，不要半句话换行。
- 保留气口：该停顿的地方就断句，可以用「、」或「——」标出来。
- 不要加「大家好我是……」这种模板开场，除非分镜脚本里本来就有。

输出格式：
- 按分镜序号分段，每段开头标 `[镜头 3 · 约 8 秒]`。
- 每段正文就是要念的字，不要夹杂舞台指示。
- 要提醒我做动作的地方，单独一行写成 `> 提示：这里停一下，等录屏画面切过来`。
- 最后给【全文字数】和【按每分钟 280 字估算的时长】。

存成 `03_口播稿/<同名>-口播.md`，同名不覆盖。
存好后把第一段直接贴给我，我要先念一遍试试顺不顺。
```

### ④ 「出封面标题」

```text
你是我的封面标题写手。一次给我 5 个，不多不少。

第一步，读 `02_脚本/` 里对应的分镜脚本。我指定了就用我指定的，没指定就用最近改过的那份。
不确定是哪一条片子就先问我。

第二步，基于这条片子**真正讲的内容**出标题。不要为了抓眼球承诺片子里没有的东西。

5 个标题必须覆盖 5 种不同的钩子类型，不能重复。每个按这个格式：
```

# C. 原生常驻状态：不开浏览器也知道 agent 在干嘛

## C-1 痛点一句话

> 我让 AI 去干一件要十分钟的活，结果它干到第二分钟就卡住等我点「同意」，
> 而我把浏览器窗口切走了，二十分钟后才发现它一直在那儿等我。

## C-2 好消息：数据这一半 v0.5 已经做完了

先说清楚现状，避免把已有的写成新做的：

- `lib/events.js` 里**已经有五态推导** `derivePetState()`：`idle / busy / waiting / celebrate / error`，
  已经会把「有几个待审批 + 待提问」算进 `waiting`。
- 事件层挂在**后端进程生命周期**上，不挂在主窗口上。主窗口隐藏、Harness 页面没打开，事件照收。
- 系统通知、Dock 角标、`attentionCount` 都已经在 `refreshAttentionSurface()` 里跑着。

**所以 v0.6 P2 的工作量主要不在"感知"，在"表达"**：把已经算出来的状态，
用托盘图标和宠物动作**表达到用户眼角能看见的地方**，并且在「等你确认」时**主动叫醒**。
这一点要如实写进汇报，不能吹成从零做了一套感知。

## C-3 五态怎么表达

| 状态 | 什么时候 | 托盘图标 | 托盘提示文字 | 宠物 | 通知 |
| --- | --- | --- | --- | --- | --- |
| **空闲** | 没有进行中的回合 | 鲸鱼静止 | 鲸坞 · 空闲 | 轻轻呼吸 | 无 |
| **思考中** | `openTurns > 0` | 鲸鱼 2 帧慢速摆尾（**2 fps**，图片切换，不做动画渲染） | 鲸坞 · 正在干活 | 摆尾，动得更快 | 无 |
| **等你确认** | 有待审批或待提问 | 鲸鱼 + **醒目角标**（红点/感叹号） | 鲸坞 · **等你拍板（N 项）** | 晃动 | **有，见 C-4** |
| **已完成** | 终态 `completed` | 鲸鱼 + 对勾，**停 3 秒**后回空闲 | 鲸坞 · 刚完成一个任务 | 跳一下 | 有（已有逻辑） |
| **出错** | 终态 `error` / `aborted` | 鲸鱼 + 感叹号，**停 5 秒**后回空闲 | 鲸坞 · 有任务没完成 | 出错动作 | 有（已有逻辑） |

实现上：托盘状态**直接消费 `derivePetState()` 的输出**，跟宠物窗用同一个数据源，
从根上避免"宠物在跳、托盘还是空闲"这种不一致。

连不上事件流时是**第六种显示**（不是第六种状态）：图标变灰，提示写「鲸坞 · 连接不上，正在重试」。
**不猜、不装作空闲。**

## C-4 重点：卡在「等你确认」时怎么叫醒不看窗口的人

设计成一条**逐级升高的阶梯**，越往后越吵。用户一有动作（点通知 / 点托盘 / 窗口获得焦点 / 该项被处理）**立即全部停止**。

| 时刻 | 做什么 | 为什么是它 |
| --- | --- | --- |
| **0 秒** | 托盘换「等你确认」图标 + 提示写清是哪个会话；macOS Dock 角标显示数字 | 眼角余光能看见，零打扰。这是最重要的一层 |
| **0 秒** | 宠物窗切「等你确认」动作 | 宠物窗是独立原生窗口，浏览器关着它也在——**这是生态里 20 多只 Web 内嵌桌宠做不到的那件事** |
| **0 秒** | 系统通知：标题「鲸坞在等你拍板」，正文写清哪个会话在等什么。点通知 → 窗口到前台并跳到该会话 | 复用已有的 `deliverTaskNotification` |
| **8 秒** | 宠物窗**临时置顶并摆动一次**（幅度 5 像素左右，不抢焦点、不夺输入） | 用户在别的窗口里工作时，余光里的一次移动比一个静止红点有效得多 |
| **30 秒** | 第二次通知（**覆盖前一条，不刷屏**）；macOS `app.dock.bounce('critical')`（会一直跳到用户处理为止）；Windows `win.flashFrame(true)`（任务栏闪烁） | 这是两个系统各自的原生"叫醒"手段，零依赖、零费用 |
| **可选** | 一声提示音（`shell.beep()`，无依赖）。**默认关闭**，设置里一个开关 | 声音最容易招人烦，必须用户主动打开 |

**永远不做的三件事**（写进代码注释）：

1. **不抢焦点**。绝不 `win.focus()` 打断用户正在敲的字。
2. **不遮挡**。不弹全屏、不弹模态窗。
3. **不循环响铃**。每个待确认项**只走一遍阶梯**，按 approval / question 的 id 去重——
   轮询兜底重连时重新看到同一项，不许再叫一次。

**每一层都可以在设置里单独关掉**，并且提供一个「安静模式」总开关（只留托盘图标）。

## C-5 集成方式：三条腿，全部只读

```
主路（已有）：HTTP/SSE + WS 事件流  →  lib/backend.js 的事件适配器  →  lib/events.js
              只连 127.0.0.1，拒绝任何离开 loopback 的重定向

探测（新增）：dsh --profile <name> --dump-config
              · 只读子进程，超时 3 秒，只读 stdout，不写任何东西
              · 用途：启动前确认 profile 与端口，作为"我们理解的配置"与"dsh 实际配置"的对账
              · 失败就当"没有这个信息"，绝不因此阻断启动
              · 注：现在代码里对 --dump-config 是零引用，这是新增的第一处

兜底（新增）：事件流断开时，退化成每 5 秒一次的 session.list 只读轮询
              · 只为维持五态不卡死，不重放历史
              · 连续 3 次失败 → 托盘灰态「连接不上」，不猜状态
```

**绝对不碰 Cordis 内部 API。** 第三方插件跟主线的兼容率只有约 14%，碰内部 API 的必死。
这一条做成可执行的守卫：smoke 里静态断言 `lib/**` 与 `main.js` 里不存在对 `cordis` 的 require/import。
它不能防住所有事，但能防住"后面某次接力顺手引了一个内部包"。

> `--dump-config` 是执行 dsh 自己的二进制，跟现在启动后端是**同一个信任边界**，
> 不违反「绝不执行包内代码」——包里的东西我们一个字节都不执行，这一点没有松动。

# D. 风险清单：哪里最可能出问题，怎么先验证

按"出问题的代价"排序。每一条都写了**具体怎么先验证**，不是"注意一下"。

| # | 风险 | 为什么危险 | 怎么先验证 |
| --- | --- | --- | --- |
| **1** | **`agent.cordis.yml` 怎么交给 dsh，我们没实证过** | 这是包机制里唯一一个依赖上游未知行为的字段。猜错 = 用户以为预设生效了其实没有，比不支持更糟 | v0.6 **只做检测+显示，不宣称接通**。真正接通排到 rc.7 侦察之后。侦察时的验证方式：在一个测试 profile 里手放一份 preset，用 `--dump-config` 回读它有没有出现在配置里 |
| **2** | **重工作台切换要重启后端，用户可能以为卡死** | 真机上几秒到十几秒；如果当前是"接入外部 dsh"模式，按现有事务规则会**直接拒绝切换**——用户会觉得"点了没反应" | 先在真机量一次实际耗时。>5 秒就必须有明确进度条 + 文案。外部 attach 情况要有专门的解释弹窗（现有 `reportWorkspaceSwitchError` 已有文案，需要补工作台场景）。**同时把"轻工作台"这条路做出来**，让大多数包不需要重启 |
| **3** | **用户重命名文件夹，五个提示词集体失效** | 用户把 `01_选题库` 改成 `选题`，agent 找不到就会自己乱找、乱建，产出一堆错位文件 | 提示词里已经全部写了"找不到就告诉我，不要自己猜"。**验证方式：手动改名后把五个按钮全点一遍**，看 agent 是不是老老实实说找不到。另外工作台首屏做一个轻量检查：预期文件夹缺了就显示一行提示 |
| **4** | **提交返回 `unknown` 时用户连点 → 重复排队** | v0.4 的适配器约定 unknown 不重试，但 UI 不给反馈的话用户会自己重试三次 | 按钮点后 5 秒禁用 + 明确文案「已提交，但没收到确认，请到会话里看一眼再决定要不要重发」。**smoke 里造一个返回 unknown 的假适配器，断言不自动重试、不重复发** |
| **5** | **叫醒做过头 = 骚扰** | `dock.bounce('critical')` 会一直跳到用户处理。做过火用户会直接关掉整个功能，等于白做 | 分级阶梯 + 一动就停 + 每项只叫一遍 + 每层可单独关。**这一条必须 SGD 真机主观验收**，没有自动化测试能替代 |
| **6** | **托盘 20 个图标素材做不完就没法验收** | 纯素材工作量，容易在最后一天卡住 | 先用程序合成的占位角标跑通全部逻辑与真机验收，正式素材单独一个批次 |
| **7** | **macOS 上中文目录名的 NFC/NFD 归一化** | macOS 会把中文目录名存成分解形式，`readdir` 拿到的字符串跟用户在配置里存的可能不等，导致"选中的工作台下次启动找不到" | **早验**：在 macOS 上建一个名字含组合字符的包（比如带声调或日文浊音），重启鲸坞看还能不能选中。宠物包大概率有同样的隐患，顺便一起查 |
| **8** | **Windows 上大小写不敏感造成 id 撞车** | `工作台A` 与 `工作台a` 在 Windows 上是同一个目录，在 macOS 上是两个 | 复用工作区那套 `platform === 'win32' ? toLocaleLowerCase('en-US')` 的比较口径，smoke 里注入 `platform: 'win32'` 直测 |
| **9** | **社区包的许可证清单成本** | 我们承诺"逐包许可证清单"。每收一个社区包就要过一遍 G1 扫描与合规审查，收 10 个就顶不住了 | **v0.6 不开社区目录**，只开自制目录。社区目录连同审核流程一起排 v0.7 |
| **10** | **`onboarding.md` 纯文本显示可能很丑** | 我们为了安全放弃了 Markdown 渲染，可能产品观感不好看 | 先按短视频包的真实 onboarding 排一版看效果。接受不了再做"按行加样式"的极简格式化，**但依然不引入解析器** |
| **11** | **包多了切换器变长** | 上限没设的话，用户放 200 个包，菜单拉不完 | 硬上限 64 个包，超出不加载并在设置页明确告知 |
| **12** | **"半启用"中间态** | 主题生效了但按钮没加载，用户不知道自己在用一个坏包 | 规则定死：任何一项解析失败 → **整体退回默认工作台并报错**，不允许静默的中间态 |
