# 工作台包底座通用性验证：四个纸面包

日期：2026-08-19 · 对应 [`开发方案-v0.6-工作台包.md`](开发方案-v0.6-工作台包.md) A-13
状态：**只写 JSON，没写一行实现代码**。这是写代码之前的一次性验证。

---

## 0. 这份文档是干什么的

A-13 立了一条规矩：**底座必须通用且稳定，行业 know-how 交给别人做包**。
这句话听着对，但"六个原语够不够通用"靠感觉判断不了，只能真去写包。

所以在动 `lib/workbenches.js` 之前，先给四个跟短视频毫无关系的行业各写一版完整的纸面包
（律师 / HR / 客服 / 教师），看它们会不会撞墙。短视频台已经在 v0.6 方案 B 节写完了，不重写。

**判断标准只有一条**：
- 撞墙但能用「将来加一个可选字段」解决 → 记录，继续开工，**不改 schema**。
- 六原语结构性不够用、必须现在改 v1 schema → 停下来等 SGD。

---

## 1. 结论先行

**没有撞到必须现在改 v1 schema 的墙。四个包都能写出来，可以开工。**

四个包全部只用到了六个原语里的四个（`manifest` / `workspace` / `actions` / `onboarding`），
`theme` 与 `pet` 是纯素材、`skills` 与 `agent.cordis.yml` 本来就是可选，都不影响能不能写出包。

A-13 预判的三个缺口**全部真实出现了**，而且体感强弱不一样：

| 缺口 | 哪个包最痛 | 真实体感 | 现在怎么绕过去 | 将来怎么补 |
| --- | --- | --- | --- | --- |
| **输入表单** | 客服 · 起草回复 | **最痛**。客服一小时几十条，每条都要先粘一段客户原话，等于每次多一轮对话 | 提示词第一步写「没给我就先问我要，不要自己编」 | 可选字段 `inputs`，老包不写照常跑 |
| **批量执行** | HR · 筛这批简历 | **次痛**。20 份简历要 agent 自己循环，没有进度、断了不能续 | 提示词里自己设 20 份上限并如实告知「还剩 N 份」 | 可选字段 `batch`，需要配套任务系统，不是一个字段能解决 |
| **多步流程** | 教师 · 教案→课件→练习 | **最不痛，基本不算问题** | 每一步都落成真实文件，下一步读上一步的文件，链子自然接上 | 可以一直不做 |

**多步流程这个缺口比预判的轻很多**，原因很具体：因为 `workspace.json` 逼着每一步都把结果
落成工作区里的真实文件，"上一步喂给下一步"就退化成了"读文件"，而读文件是 agent 本来就会的事。
这反过来说明 `workspace.json` 这个原语的价值被低估了——它不只是"建几个文件夹"，
它是**把工作流状态外化成文件**，而这正好让多步流程不需要引擎。

另外发现四条不改 schema、但要写进《工作台包制作指南》的东西，见第 6 节。

### ① 出初审意见

```text
你是我的合同初审助手。你出的是给执业律师复核的草稿，不是最终法律意见。

第一步，确定审哪一份。读 `01_待审合同/` 下的文件。如果我在对话里指定了某一份，以我指定的为准；
我没指定又有多份，就把文件名列出来让我选，然后停下等我回答——不要自己挑一份开始审。
如果这个文件夹不存在或者是空的，就直接告诉我「待审合同文件夹是空的」，然后停下。

第二步，读 `03_我方立场/` 里的全部内容，搞清楚我们是甲方还是乙方、底线在哪。
这个文件夹是空的，就在意见书开头明写一句「本次没有我方立场材料，以下按通用商业惯例判断」。

第三步，按这个结构出意见：
【合同基本信息】当事人、标的、金额、期限、签署地。原文里找不到的写「原文未约定」，不要推测。
【我方身份与主要义务】我们要做什么、要付什么、什么时候付。
【重点关注条款】逐条列，每条写：条款号 + 原文摘录（不超过 50 字）+ 问题是什么 + 建议怎么改。
【原文未约定但应该约定的】违约责任、争议解决、通知方式、保密、终止条件，缺哪条列哪条。
【结论】能签 / 改了能签 / 不建议签，一句话说清最主要的理由。

硬性要求：
- 只依据合同原文和 `03_我方立场/` 里的材料。不要编造条款号、金额、日期或对方陈述。
- 原文看不清或有歧义的地方，单独列成【需要我确认】，不要替我作解释。
- 每条意见都要能指回原文的具体位置，指不回去的不要写。
- 末尾固定加一行：「本文件由 AI 生成，供执业律师复核，不构成法律意见。」

存成 `02_审查意见/<合同文件名>-初审意见.md`，同名不覆盖，加 `-2`。
存好后把【结论】和【重点关注条款】的前三条直接贴在回答里。
```

### ② 挑风险条款

```text
你是我的合同风险排查员。这一步只做一件事：把最可能让我方吃亏的条款挑出来排序。

第一步，确定审哪一份合同。我指定了就用我指定的；没指定又有多份就先把文件名列出来问我，然后停下。

第二步，按下面六类逐类过一遍。每一类都要给结论，没问题也要写「本类未发现问题」：
1. 钱：付款条件、付款节点、扣款与罚款、税费承担、价格调整
2. 时间：交付期、验收期、异议期、合同期限与自动续期
3. 责任：违约金比例、赔偿上限、免责范围、不可抗力
4. 退出：单方解除权是不是只有对方有、解除后怎么结算
5. 归属：知识产权、数据、成果物归谁
6. 争议：管辖法院或仲裁机构在哪、适用法律、通知地址

第三步，把找到的问题按「我方损失的严重程度」排序，每条写成：
【风险等级】高 / 中 / 低
【条款号与原文摘录】不超过 50 字
【最坏情况】一句话说清：如果这条被对方用足，我方会承担什么，尽量具体到钱或时间
【怎么改】给一句能直接拿去谈的话

硬性要求：
- 严重程度按我方实际损失判断，不要按条款长短或在合同里的位置判断。
- 不要把「行业惯例如此」当成没有风险——惯例不利也要写出来，另注一句「属常见条款」。
- 找不到某一类的对应条款就写「原文未约定」，这本身往往就是风险。
- 不要编造对方的意图，只写条款文本允许对方做什么。

存成 `02_审查意见/<合同文件名>-风险清单.md`，同名不覆盖。
存好后把【风险等级】为高的全部贴在回答里。
```

### ③ 出修改建议

```text
你是我的合同修改稿撰写员。产出的是可以直接发给对方的修改意见，不是内部吐槽。

第一步，确定合同，规则同上。同时读 `02_审查意见/` 下这份合同已有的意见与风险清单：
已经有了就以它们为基础，不要从头再审一遍；没有就先粗读合同再动手。

第二步，读 `03_我方立场/`，确认哪些是必须改的底线、哪些可以让。
`03_我方立场/` 是空的时候，把每条改动都标成【待确认是否为底线】，不要自己定底线。

第三步，逐条写修改建议，每条这个格式：
【条款号】
【现在写的】原文摘录
【建议改成】改后的完整条款文本，要能直接替换原文，不要写「建议增加相关约定」这种空话
【为什么】一句话，站在能说出口的立场上说，不要写内部判断
【让步空间】对方不同意时我们能退到哪一步；确实不能退的写「无退让空间」

第四步，最后给一段【谈判顺序建议】：哪几条必须先谈，哪几条可以最后打包一起让。

硬性要求：
- 改后的条款要自洽：改了定义就检查引用它的条款，改了金额就检查计算方式。
- 不要引用具体法条编号，除非合同原文里本来就引用了它。
- 不确定对方为什么这么写的地方，写成【需要我确认对方意图】，不要替对方编理由。

存成 `02_审查意见/<合同文件名>-修改建议.md`，同名不覆盖。
存好后把【谈判顺序建议】贴在回答里。
```

### ④ 比对标准条款

```text
你是我的条款比对员。

第一步，读 `03_我方立场/` 下的全部内容，把里面的标准条款、底线条款整理成一张清单。
如果这个文件夹是空的、或者里面没有可用的条款文本，就直接告诉我
「我方立场文件夹里还没有标准条款，没有基准就没法比对」，
然后给我 8 个问题，问完我就能写出第一版底线——问完停下，不要自己替我编一套标准条款。

第二步，确定要比对的合同，规则同上。

第三步，做一张比对表，一行一条：
| 我方标准条款 | 本合同怎么写的 | 一致 / 更严 / 更松 / 未约定 | 差在哪 | 要不要争 |

第四步，表后面给两段：
【必须改回来的】哪几条低于我方底线，逐条说清差距。
【可以接受的偏离】哪几条虽然不一样但可以接受，说明理由。

硬性要求：
- 「一致 / 更严 / 更松」一律站在我方角度判断，不要站在中立第三方角度。
- 本合同里完全没有对应条款的标成「未约定」，不要当成「一致」。
- 我方标准条款自己有矛盾的地方要单独指出来，那说明底线该更新了。

存成 `02_审查意见/<合同文件名>-条款比对.md`，同名不覆盖。
存好后把【必须改回来的】贴在回答里。
```

### ⑤ 出一页纸摘要

```text
你是我的合同摘要撰写员。读者是不看合同原文的老板，他只想知道签不签、有什么坑。

第一步，确定合同，规则同上。`02_审查意见/` 里已有的内容要先读，摘要不能和它们打架。

第二步，写一页纸，总长 600 字以内，就这五段：
【一句话】我们和谁做什么事，多少钱，多长时间。
【我们要做什么】三条以内，写义务不写权利。
【他们要做什么】三条以内。
【最需要注意的三件事】只写三条，每条一句话，写清楚「如果出事，出的是什么事」。
【建议】签 / 改了再签 / 不签，一句话理由。

硬性要求：
- 不要出现条款号，老板不看条款号。要引用就直接说人话。
- 不要用「本合同约定」这种转述句式，直接说结论。
- 超过 600 字就删，删到只剩最要紧的。宁可少说也不要把摘要写成第二份意见书。
- 数字必须来自原文，找不到就写「合同未写明」。

存成 `02_审查意见/<合同文件名>-一页纸.md`，同名不覆盖。
存好后把全文直接贴在回答里——这一份短，就是要让我不用打开文件。
```

### onboarding.md

```text
# 合同初审台

这个工作台把一份合同拆成四步：先看有什么问题，再排风险，再出改法，最后给老板一页纸。

# 先做一件事
往 03_我方立场 里写点东西。你们公司的底线条款、常用标准条款、上次谈判让过什么，一句话也算。
「比对标准条款」完全靠这个文件夹吃饭，空着的话它会直接问你要，不会自己编一套标准。

# 五个按钮的顺序
- 出初审意见 → 通读一遍，列出重点关注条款
- 挑风险条款 → 按我方损失排序，只挑最可能吃亏的
- 出修改建议 → 写成能直接发给对方的条款文本
- 比对标准条款 → 和 03_我方立场 里的底线逐条对
- 出一页纸摘要 → 给不看合同的人看

# 三件要知道的事
- 每一步的结果都会存成 02_审查意见 里的真实文件，同名不覆盖，会自动加 -2。
- AI 出的是草稿，不是法律意见。发出去之前必须执业律师过一遍。
- 合同原件会被交给 AI 处理。涉密合同能不能放进来，请你自己判断。
```

### 这个包撞墙了吗

| 原语 | 够不够用 | 说明 |
| --- | --- | --- |
| `workspace.json` | **够** | 四个文件夹一段路径，`readme` 正好用来写"这个文件夹空着会怎样" |
| `actions.json` | **够** | 5 个按钮，`label` 最长 6 个汉字，16 字符上限绰绰有余 |
| `onboarding.md` | **够**，而且比预想重要 | 免责声明与"合同会被交给 AI"这句合规提醒，只有这里放得下 |
| `manifest.json` | **够** | `license` 必须声明这条规矩，在法务场景下用户会主动看 |

**没撞墙。** 唯一别扭的地方：第一步"确定审哪一份"要靠对话问一轮（输入表单缺口的轻症版），
但律师一次只审一份合同，多问一句可以接受。

### ① 写岗位说明

```text
你是我的招聘岗位说明撰写员。

第一步，看 `01_岗位说明/` 里有没有这个岗位的旧版本。我在对话里指定了岗位就用我指定的；
没指定又有多个岗位，就把岗位名列出来问我，然后停下。
一个都没有、我也没说要招什么岗位，就问我 6 个问题（招什么岗、几个人、汇报给谁、
最要紧的三件事、必须会什么、预算范围），问完停下——不要自己替我编一个岗位。

第二步，写岗位说明，就四段：
【这个人来了要做什么】三到五条，每条是一件具体的事，不是一个能力词。
【硬性条件】列成清单，每条都要能一眼判断满不满足。判断不了的挪到加分项去。
【加分项】三条以内。
【我们能给什么】团队、成长、工作方式。写实话，不要写"扁平化、氛围好"。

硬性要求：
- 不要写"具备良好的沟通能力和团队协作精神"这类放在任何岗位都成立的话，一句都不要。
- 硬性条件超过 5 条就砍，砍到 5 条以内——条件越多，收到的简历越少而且越不准。
- 不写年龄、性别、婚育、籍贯、学校层次相关的任何要求或倾向。
- 我给的信息不足以写某一段，就把那一段留成【待我补充】，不要用套话填满。

存成 `01_岗位说明/<岗位名>.md`，同名不覆盖，加 `-2`。
存好后把【硬性条件】贴在回答里，我要先确认这几条对不对。
```

### ② 筛这批简历

```text
你是我的简历初筛员。

第一步，读 `01_岗位说明/` 下的岗位说明。我在对话里指定了岗位就用我指定的；
没指定又有多个，就把岗位名列出来问我，然后停下。
这个文件夹空着就直接告诉我「还没有岗位说明，没有标准就没法筛」，
然后给我 6 个问题，问完我能写出第一版 JD——问完停下。

第二步，列出 `02_待筛简历/` 下的所有文件，先把份数报给我，然后按文件名排序逐份处理。
一份都没有就说「待筛简历文件夹是空的」，然后停下。
如果超过 20 份，本次只处理前 20 份，并在结果开头写明
「本次只处理了前 20 份，还剩 N 份；把处理过的挪走之后再点一次这个按钮，我接着筛」——
不要一次吞完，也不要假装都看过了。

第三步，每一份按同一张表打分，不许因为看到后面累了就变松或变紧：
| 候选人 | 硬性条件是否满足 | 匹配度 A/B/C | 最强的一点 | 最大的疑问 | 建议 |
「建议」只能是三种之一：约面 / 待定 / 不约。
「最大的疑问」必须是一个能在面试里问出口的具体问题，不要写「经验不足」这种判断。

第四步，表后面给两段：
【我建议先约的三个人】按顺序，每人一句话理由。
【我看不准的】哪几份信息太少判断不了，缺的是什么信息。

硬性要求：
- 只依据简历里写的内容。不要根据学校、公司名、性别、年龄、籍贯、婚育状况做任何推断或加减分，
  这些也不要出现在你的结论里。
- 简历里没写的经历不要替候选人补上，「看起来应该会」不算。
- 同一个人有多份文件（比如附了作品集）合并成一条，不要重复计数。
- 硬性条件不满足的也要写进表里并说明差在哪，不要静默丢掉——我要知道你筛掉了谁。

存成 `03_筛选结论/<岗位名>-初筛-<今天日期YYYYMMDD>.md`，同名不覆盖，加 `-2`。
存好后把【我建议先约的三个人】贴在回答里。
```

### ④ 出面试问题

```text
你是我的面试提纲撰写员。

第二步，读这位候选人的简历，以及 `03_筛选结论/` 里对他的记录，特别是「最大的疑问」那一栏。

存成 `04_面试题/<候选人>-<岗位名>-面试提纲.md`，同名不覆盖。
```

### 这个包撞墙了吗

**撞了一次，是预判里的「批量执行」。**

真实需求是「对 `02_待筛简历/` 里每个文件跑同一个提示词」。v0.6 没有这个能力，
只能在提示词里让 agent 自己循环，代价是三条，全都真实存在：

1. **要自己设上限**。我在提示词里写死 20 份，因为再多 agent 会开始遗忘前面的人。
   这个数字是拍脑袋定的，包作者没法从鲸坞这边知道真实的上下文余量。
2. **断了不能续**。跑到第 14 份出错，只能整个重来；靠"把处理过的挪走"来做断点续传，
   这是让用户手动维护状态。
3. **没有进度**。用户点完按钮只能干等，不知道跑到第几份。

**但这三条都不需要改 v1 schema**：将来加一个可选的 `batch` 字段（比如
`"batch": { "folder": "02_待筛简历", "maxItems": 20 }`）就能表达，老包不写照常跑。
而且真要做好它需要的是循环、限流、中断、进度的一整套任务系统，不是一个字段的事——
**A-13 判断"先不做"是对的**。

顺带一个正面发现：`confirm: true` 在这个包里第一次有了真实用途（要发给真人的回复）。

### ① 起草回复

```text

（1）我在对话里直接粘给你的；（2）`03_今日待回/` 里最近修改的那个文件。
```

### ② 换个语气

```text
你是我的语气改写员。意思一个字不能变，只换说法。

第一步，找到要改的那一版回复。按这个顺序：（1）我在对话里贴给你的；
（2）`04_已回归档/` 里最近修改的那份。都没有就问我要，然后停下。

第二步，我在对话里说了要改成什么语气就照做。我没说的话，就把下面四种各出一版：
【更短】砍到一句话，只留结论。
【更软】不改事实，把可能顶撞的地方改成对方能接受的说法。
【更硬】立场更明确，适合对方在无理要求时用。不许威胁、不许羞辱、不许提法律后果。
【更正式】适合升级到书面沟通或工单存档。

硬性要求：
- 四版的事实必须完全一致。任何一版里出现原文没有的承诺，就是错的。
- 不要为了软化而含糊。「我们尽快处理」比「按 X 规则我们会在 3 天内处理」更容易惹事。
- 客户的原话不要复述进回复里，尤其是骂人的那部分。

不用存文件，四版直接贴在回答里——这一步是要我当场挑一版发出去。
```

### ③ 要不要升级

```text
你是我的工单分级助手。这一步不写回复，只判断该不该往上转。

第一步，拿到客户原话，规则同「起草回复」。没有就问我要，然后停下。

第二步，逐条检查这六个信号，每条给「是 / 否 / 看不出来」，并说明依据是原话里的哪一句：
1. 涉及人身安全、财产重大损失或健康风险
2. 客户明确提到投诉到平台、监管、媒体，或者要走法律途径
3. 涉及退款、赔偿金额超出一线客服的权限
4. 同一个问题已经来回三次以上还没解决
5. 客户要求的处理方式我们的规则里没有对应条款
6. 对方是媒体、大客户或有公开影响力的账号（原话里能看出来才算）

第三步，给结论，只能是三种之一：
【一线自己回】 / 【转主管】 / 【立刻升级并同步相关团队】
后面跟一句话理由，理由必须指向上面某一条具体信号。

第四步，如果结论不是「一线自己回」，再给一段【转交时要说清楚的三件事】，
让接手的人不用重看聊天记录就能上手。

硬性要求：
- 「看不出来」是允许的答案，不要为了给结论而脑补客户身份或动机。
- 不要因为客户语气冲就判定要升级。语气和严重程度是两回事。
- 不要因为问题难就升级。难但在权限内的，一线自己回。

不用存文件，结论直接贴在回答里。
```

### ④ 提炼常见问题

```text
【出现次数】
【标准答案】综合已归档回复里最好的那一版，改成能直接复制粘贴的话。

硬性要求：
- 标准答案里的每一个数字、期限、规则都要能追到 `02_产品事实/`，追不到就标【待确认】，
```

### ⑤ 写补偿方案

```text

  【需要我方决策：xxx】留空，不要自己定一个数。
- 不要写「我们将承担全部责任」这类不设边界的话。
- 补偿方案是给我看的内部草稿，不是发给客户的文本。要发的话再点「起草回复」。

存好后把三档摘要贴在回答里。
```

### 这个包撞墙了吗

**撞了，而且是四个包里最痛的一次：输入表单。**

客服的真实节奏是「一小时几十条」。现在每点一次「起草回复」，用户都要先做一步准备动作：
要么把客户原话粘进对话框，要么先在 `03_今日待回/` 里建个文件。而 A-7 明确规定
**提示词是死文本，不与输入框内容合并**，所以按钮本身拿不到"我刚才输入的那一段"。

我在提示词里的绕法是「按顺序找：对话里的 → 文件夹里最近改的 → 都没有就问我」。
这个绕法能用，但代价很实在：**高频短交互场景下，每条多一轮往返的成本会被放大几十倍**。

写完这个包我的判断是：**输入表单是三个缺口里最该先补的一个**，而且它比批量简单得多——
将来加一个可选的 `inputs` 字段（比如 `"inputs": [{ "id": "raw", "label": "客户原话", "type": "text" }]`），
点按钮先弹一个小框，填完把内容作为**一段独立的用户消息**发出去（而不是拼进提示词模板）。
这样既解决了体感，又不引入变量替换 / 模板引擎（那才是执行面）。

**但这不需要现在改 v1 schema**：`inputs` 是新增可选字段，规则一保证老鲸坞遇到它会忽略，
规则二保证今天写的包将来还能装。**所以照原计划开工，v0.6 不做这个字段。**

另一个发现：`tone` 和 `escalate` 两个按钮**不存文件、只贴回答**。
说明 `actions` 不必然要跟 `workspace` 绑定——有些按钮就是"当场问一句"。
这条要写进制作指南，免得包作者以为每个按钮都得产出文件。

### ① 写教案

```text
你是我的备课助手，帮我写一节课的教案。

第一步，确定讲什么。读 `01_教材与课标/` 里的内容。我在对话里指定了课题就用我指定的；
没指定又有多个课题，就把课题列出来问我，然后停下。
这个文件夹是空的，就直接告诉我「教材与课标文件夹是空的，我不知道要讲哪一课」，
然后问我四个问题（哪一科、哪一册哪一章、多少分钟一节、学生大概什么水平），问完停下。

第二步，读 `04_练习与讲评/` 里的历史复盘。上次记过「这里学生没听懂」的地方，这次要重点处理。
没有复盘就跳过这一步，不要编一个学情出来。

第三步，写教案，按这个结构：
【本节目标】三条以内，每条都要能在课后用一道题验证。写「能自己举出两个例子」，
不写「理解……的含义」——后者验证不了。
【学生已经会什么】写清楚这节课的起点。这一条错了整节课都会偏。
【最难的一个点】这节课学生最容易卡住的地方是哪个，为什么卡。
【流程表】一行一段，标时间：
| 分钟 | 环节 | 我做什么 | 学生做什么 | 这一段要达到什么 |
【板书设计】黑板最后留下的是什么样子，用文字描述布局。
【预设问题】学生最可能问的三个问题，以及怎么答。

硬性要求：
- 时间加起来必须等于一节课的长度，不要写出 55 分钟的内容塞进 40 分钟。
- 每个环节都要写「学生做什么」。整段只有老师在说的环节，超过 8 分钟就要拆开。
- 不要编教材里没有的例题、数据或史实。教材里找不到的写【需要我补充素材】。
- 不确定学生水平的地方，按 `01_教材与课标/` 里写的来；那里也没写就明确标出来。

存成 `02_教案/<课题>-教案.md`，同名不覆盖，加 `-2`。
存好后把【本节目标】和【最难的一个点】贴在回答里。
```

### ② 出课件大纲

```text
你是我的课件结构设计员。你不做 PPT，只给一页一页的提纲。

第一步，找教案。读 `02_教案/` 里最近修改的那份。我指定了某一份就用我指定的；
不确定是哪份就先问我，不要猜。`02_教案/` 是空的就告诉我「先点「写教案」」，然后停下。

第二步，把教案变成幻灯片提纲，一页一页写：
第 N 页
【这一页的标题】不超过 12 个字
【屏幕上出现什么】文字要点不超过 3 条，或者一张什么样的图/表（描述清楚我能做出来）
【我要说的话】这一页对应的口头讲解，两三句，写成能直接念的话
【停留时间】大概几分钟

第三步，最后给一段【这套课件的节奏】：哪几页是重点要慢，哪几页可以快速带过。

硬性要求：
- 页数按每分钟不超过一页控制，40 分钟的课不要出 40 页。
- 一页上文字不超过 3 条，超了就拆成两页。满屏文字的课件等于没有课件。
- 教案里没有的内容不要加到课件里。课件是教案的投影，不是第二次创作。
- 需要动画或分步展示的地方，明确写成「先出 A，再出 B」，不要笼统写「动态展示」。

存成 `03_课件大纲/<课题>-课件大纲.md`，同名不覆盖。
存好后把总页数和【这套课件的节奏】贴在回答里。
```

### ③ 出练习题

```text
你是我的出题助手。

第一步，找教案，规则同「出课件大纲」。练习题必须对着教案的【本节目标】出，
不是对着教材整章出。

第二步，出 12 道题，按这个配比：
- 基础题 6 道：直接对应本节目标，课上讲过就该会。
- 变式题 4 道：换个说法、换个情境，考的还是同一个点。
- 挑战题 2 道：需要把这节课和以前学的连起来。

每道题写：
【题目】
【考的是本节目标第几条】对不上任何一条目标的题就删掉，不要留
【答案】
【学生最可能错在哪】一句话，写具体的错法，不要写「粗心」

第三步，最后给一段【如果只留 5 道】：时间不够时留哪五道，为什么。

硬性要求：
- 每道题都要标清楚对应哪条目标。标不出来的题说明它不属于这节课。
- 答案必须自己算一遍/推一遍，不要给出你没验证过的答案。不确定的题直接换一道。
- 不出偏题怪题。挑战题也要是本节内容的自然延伸。
- 不编造教材里没有的公式、定义或事实。

存成 `04_练习与讲评/<课题>-练习.md`，同名不覆盖。
存好后把【如果只留 5 道】贴在回答里。
```

### ④ 分层任务

```text
你是我的分层任务设计员。同一节课，学得快的和跟不上的要有不同的活干。

第一步，找教案和这节课的练习题，规则同上。两个都没有就先让我点前面的按钮，然后停下。

第二步，出三套任务：
【跟不上的那几个】把本节目标拆成更小的步子，每步都要能独立完成并立刻知道对不对。
先写一句【他们卡在哪】：根据教案里的【最难的一个点】判断，不要泛泛说「基础差」。
【大部分人】就是常规练习，注明用哪几道题。
【学得快的那几个】给一个需要多想一步的任务，不是"多做十道同样的题"。
写清楚做完之后他们能说出什么以前说不出的话。

第三步，给一段【怎么在一节课里同时安排这三套】：什么时候分组、我在哪一组、
另外两组自己做的时候怎么保证不乱。这一段要具体到可执行。

硬性要求：
- 三套任务的目标是同一个，只是路径不同。不要给跟不上的学生降低目标。
- 「学得快的」那一套不许是惩罚性的加量。
- 每一套都要能在课内的同一段时间里完成。
- 不要给学生贴标签。任务分组按这节课的表现分，不写成固定的人群划分。

存成 `04_练习与讲评/<课题>-分层任务.md`，同名不覆盖。
存好后把【怎么在一节课里同时安排这三套】贴在回答里。
```

### ⑤ 课后复盘

```text
你是我的课后复盘助手。这一步靠我口述，你负责问和记。

第一步，找到这节课的教案。我指定了就用我指定的，没指定就用 `02_教案/` 里最近修改的那份，
并在开头说明你用的是哪一份。

第二步，读一遍教案，然后按教案的流程逐段问我，一次只问一段，等我回答完再问下一段：
「这一段实际用了多久？学生的反应是什么？」
全部问完之后，再问两个问题：「哪一个点你觉得没讲通？」「下次这节课你会改哪一件事？」
不要一口气把所有问题都抛出来，也不要替我回答任何一个。

第三步，把我的回答整理成复盘，就四段：
【实际时间 vs 计划时间】哪几段超了、哪几段快了，一行一段。
【没讲通的点】具体是哪个概念、学生的错误说法是什么样的。
【下次要改的一件事】只留一件，最要紧的那件。
【留给下次备课的提醒】一句话，写成"讲到 X 的时候要先 Y"这种能直接用的形式。

硬性要求：
- 全部内容来自我的口述。我没说的不要补，不要用"通常来说"来填空。
- 我说得含糊的地方追问一次，追问一次还含糊就照实记「未说清」。
- 不要写鼓励的话，也不要评价我这节课上得好不好。复盘是给下次用的，不是打分。

存成 `04_练习与讲评/<课题>-复盘-<今天日期YYYYMMDD>.md`，同名不覆盖。
存好后把【留给下次备课的提醒】贴在回答里——下次「写教案」会读到它。
```

### 这个包撞墙了吗

**没撞墙，而且它把预判里的「多步流程」缺口证伪了一半。**

备课天生是链式的：教案 → 课件 → 练习 → 分层 → 复盘 → 下次的教案。
A-13 原本担心"第一步的产出自动喂给第二步"做不到。实际写下来，它是这样解决的：

**因为 `workspace.json` 逼着每一步都把结果落成工作区里的真实文件，
"上一步喂给下一步"就退化成了"读 `02_教案/` 里最近改的那份"——而读文件 agent 本来就会。**

链子甚至能闭环：`课后复盘` 写下的提醒会被下一次 `写教案` 读到。
这一条不需要任何引擎，只需要两个提示词互相知道对方写在哪。

真正缺的只是"点一下自动连着跑五步"。但那个东西对备课来说反而是错的——
每一步之间老师都要看一眼、改一改。**所以多步流程这个缺口，可以一直不做。**

顺带记一条：`review` 这个按钮是唯一一个**反过来向用户提问**的按钮（一段一段问、等回答）。
它证明 `actions` 不只能做"一次性生成"，也能做"结构化访谈"，而这不需要任何新字段。

| --- | --- | --- |
| `name` ≤ 40 字符 | 5 个汉字 | 宽裕 |
| `summary` ≤ 120 字符 | 26 个汉字 | 宽裕 |
| `folders` ≤ 32 项 | 4 项 | 宽裕 |
| `folders[].path` 1–3 段 | 全部 1 段 | 宽裕 |
| `folders[].readme` ≤ 4000 字符 | 约 120 个汉字 | 宽裕 |
| `actions` ≤ 12 项 | 5 项 | 宽裕 |
| `actions[].label` ≤ 16 字符 | 6 个汉字 | 宽裕 |
| `actions[].hint` ≤ 80 字符 | 20 个汉字 | 宽裕 |
| `actions[].prompt` ≤ 8 KiB | 约 900 汉字 ≈ 2.7 KiB | **够用但不宽裕，见 6-2** |

**结论：一个上限都不用调。**

### 6-2 提示词的 8 KiB 上限：够用，但它在推着作者做一件对的事

UTF-8 下一个汉字 3 字节，8 KiB ≈ 2700 汉字。四个包里最长的提示词（律师 ①）约 900 字，
只用掉三分之一。

但写律师包的时候有一个真实的诱惑：**把"我方标准条款清单"整个塞进提示词**。
那样很容易顶到上限，而且更糟的是——用户改不了它，因为提示词在包里。

正确的做法是我最后采用的那种：**长清单放进工作区文件（`03_我方立场/`），提示词只写"去读那个文件夹"**。
这样清单是用户的财产，随时能改，而且改完立刻生效。

**这条要写进《工作台包制作指南》**：提示词里只放"怎么做"，不放"依据什么数据"；
数据一律放工作区。8 KiB 这个上限恰好起到了逼作者走对路的作用，不要放宽。

### 6-3 一个真实的一致性风险：文件夹名写在两个地方

`workspace.json` 的 `folders[].path` 定义了文件夹叫什么，而 `actions[].prompt` 里也写死了同样的名字。
**同一个事实写在两个地方，作者改了一处忘了另一处，按钮就会去找不存在的文件夹。**

v0.6 不做变量替换（那是模板引擎，是执行面），所以这个重复消不掉。能做的是两件事：

1. **制作指南里明写**：改 `workspace.json` 的文件夹名时，必须同时改所有提到它的提示词。
2. **D-3 的真机验收就是查这个**：把 `01_选题库` 改名后把五个按钮都点一遍，
   看 agent 是不是老老实实说找不到（四个包的提示词里都写了"找不到就告诉我，不要自己猜"）。

顺带说明：这个风险**不该用"工作台首屏检查预期文件夹在不在"来消除**，只该用它来提醒。
因为用户完全有权把文件夹改名——那是他的文件夹。我们能做的是让 agent 老实报错，不是拦着用户。

### 6-4 不是每个按钮都要产出文件

客服包的「换个语气」「要不要升级」，都是**不存文件、只贴回答**的按钮。
教师包的「课后复盘」甚至是**反过来一段一段问用户**的结构化访谈。

这说明 `actions` 这个原语比原设想的宽：它不是"生成文件的按钮"，是"一句想好的话"。
制作指南要说清楚，免得包作者以为每个按钮都必须落一个文件。

### 6-5 两条通用性输入的验收

来自 2026-08-19 一次内部讨论的两条设计约束（该讨论记录未入库），用四个纸面包检验：

| 约束 | 检验结果 |
| --- | --- |
| `actions` 的**数据与渲染分离**，将来能被复用成移动端/远程的"快捷指令面板" | ✅ 通过。四个包的 `actions` 数组里只有 `id / label / hint / confirm / prompt`，没有一个字段跟"左侧竖排按钮"这种呈现方式绑定。原样搬到手机上就是一个九宫格 |
| `workspace.json` 的 `folders` 语义保持**行业无关**，不为短视频特化 | ✅ 通过。四个行业的 `folders` 全都只是"一套约定好的文件夹"，没有一个需要"收件箱""待办箱"这类特殊语义。`01_待审合同`、`02_待筛简历`、`03_今日待回` 看起来像收件箱，但它们不需要鲸坞知道这件事——**它们只需要提示词知道**。这正是底座该有的分工 |

### 6-6 每个包都需要一句"你的数据会交给 AI"

四个包的 `onboarding.md` 最后都写了同一类话：合同/简历/客户原话/学生信息会被交给 AI 处理，
放不放进来请用户自己判断。

这不是巧合——**只要一个工作台把用户的真实文件交给 agent，这句话就该在**。
建议制作指南给一段**推荐模板**，但**不做成强制字段**：强制就等于我们替包作者做了合规承诺，
而 A-13 的包作者契约里我们只承诺"如实告诉用户解析失败的原因"，没承诺替他们兜合规。

## 7. 对 v0.6 实现的影响

### 7-1 不改的（照原计划开工）

- 六个原语一个不加、一个不减。
- A-5 ~ A-10 的字段表和上限**一个字不改**。
- 输入表单 / 批量执行 / 多步流程三个缺口**都不做**，理由见第 1 节。
- `schemaVersion` 保持 1，永不因为这四个包 +1。

### 7-2 加一个可选字段：`folders[].files`（SGD 2026-08-19 补充要求引入）

SGD 补充要求：**短视频包的 `01_选题库` 里要预置 3 份示例选题文件**，
让用户装完包点第一个按钮 60 秒内就有真实产出，不掉进"选题库是空的"的冷启动。

`workspace.json` 现在只能建空文件夹 + 写一个 `说明.md`（`readme` 字段），表达不了这件事。
两条路：

| 方案 | 做法 | 判断 |
| --- | --- | --- |
| A：包里放 `seed/` 目录，首次启用时递归复制进工作区 | 作者体验好（直接丢 .md 文件） | ❌ 引入"从包里递归复制任意文件到用户文档目录"这条新路径，要新加深度/数量/总大小/扩展名一整套限制，是**新的攻击面** |
| **B：给 `folders[]` 加一个可选的 `files` 数组** | 复用**已经存在的** `readme` 写文件代码路径 | ✅ **采用**。零新机制、零新攻击面 |

**这是一个纯增量的可选字段，完全符合 A-13 规则二（"新能力一律用新的可选字段表达，老包不写就走回落"），
不动 `schemaVersion`，老包一个字不用改。**

字段定义（补进 A-6 的表）：

```json
{
  "path": "01_选题库",
  "readme": "……",
  "files": [
    { "name": "示例-一条视频从选题到开拍.md", "content": "这是示例，可以直接删。\n\n……" }
  ]
}
```

| 字段 | 类型 | 必填 | 上限 / 格式 | 缺了怎么回落 | 非法怎么拒 |
| --- | --- | --- | --- | --- | --- |
| `files` | 数组 | 否 | ≤ 8 项 | 不写就只建空文件夹 | 不是数组 → 当作没写 |
| `files[].name` | 字符串 | 是 | **单段文件名**，≤ 60 字符，不为 `.`/`..`，不含 `/` `\` `:` 与控制字符，不以空格或 `.` 开头，**必须以 `.md` 或 `.txt` 结尾** | — | 违反任一条 → 丢这一条并记 `issues`，其余照建 |
| `files[].content` | 字符串 | 是 | ≤ 8000 字符 | — | 清洗控制字符（保留换行）后截断；洗完为空 → 丢这一条 |

**三条铁律原样适用**：只新建不覆盖（同名文件已存在就一个字不动）、不删任何东西、
落点过 `canonicalWorkspace()` + `assertWorkspaceNotForbidden()`。
另外加一条：**`files[].name` 不允许等于 `说明.md`**，避免和 `readme` 抢同一个文件名。

### 7-3 另外两条 SGD 补充要求（不涉及 schema）

| 要求 | 落在哪个批次 | 说明 |
| --- | --- | --- |
| `skills.json` 为空数组时，设置区**整栏隐藏**，不显示"没有推荐 skill" | 批次 3（设置窗） | 覆盖 v0.6 方案 E-1 问题 3 里"UI 显示「这个工作台没有推荐 skill」"的原措辞 |
| `agent.cordis.yml` 的「已检测到，尚未接通」**收进「关于这个工作台」详情**，不上切换器/主界面 | 批次 3 | A-8 的"在 UI 里显示"具体落到详情页；主路径上不出现，避免用户误以为已接通 |

### 7-4 要写进《工作台包制作指南》的四条（批次 5 交付）

1. 提示词里只放"怎么做"，数据一律放工作区文件（6-2）。
2. 改文件夹名时必须同步改提示词（6-3）。
3. 按钮不必然产出文件，也可以只回答、甚至反过来问用户（6-4）。
4. 涉及用户真实数据的包，`onboarding.md` 里建议写一句"数据会交给 AI 处理"（推荐模板，不强制）（6-6）。
